# Queue operations

- Import Harness from the control center; construct Context with the actual execution WorkspaceRoot.
- `harness.queue.status`: no mutation; returns revision, ordered items, current Change, dispositions, controller record, pause state and live TaskPlan progress. Unknown activity remains `unknown`; missing planning is `plan-needed`, with unknown task counts.
- Recovery: `recoveryPending` / `planState=recovery-needed` reports an unpublished transaction without replaying it. `claim` recovers queue writes and ownership while retaining a user pause; resume through the existing execution start/checkpoint operation with its actual new resolving source. `archive-pending` identifies an exact completed archive awaiting `advance`; `record-blocked` carries missing/invalid record issues. Neither goes through Ensure plan. Editing an exhausted queue returns it to idle when pending work exists, preserving any requested pause.
- `harness.queue.set`: `Changes = @('domain/change-a','domain/change-b')`, `ExpectedRevision = <status revision>`. Deduplicates in order and binds each active Change to this workspace.
- `harness.queue.remove`: `Change`, `ExpectedRevision`; removes a pending member. `reorder`: `Changes`, `ExpectedRevision`; supplies exactly the pending IDs in their new order. Pause/release before changing the controller's remaining authorized prefix, including its head. Appending after the authorized boundary does not authorize the new members for execution.
- `harness.queue.pause`: `Reason`; the owner acknowledges by releasing at a checkpoint. With no owner it becomes paused immediately.
- `status/set/remove/reorder/pause` accept `TargetWorkspaceRoot` only from the primary Context and only within that control center.
- `harness.queue.claim`: `SessionId`; optional `AuthorizedUids` and actual `SourceRef`; returns `controller.token`, its fixed ordered `authorizedUids`, and `sourceRef`. Omitted `AuthorizedUids` snapshots all current pending members; an explicit list must be an exact non-empty prefix. Repeating an owned claim cannot replace its scope or recorded source. Use the actual session ID where available; on other hosts generate one stable ID for the current chat invocation and retain it. Claiming the controller alone does not authorize implementation.
- `harness.execution.start` binds the actual execution request to that queue. `Scope=Queue` snapshots the current pending order; an exact `Change` limits it to the current head. `Scope=Change` is the same single-item adapter. An explicitly requested single item may initialize an empty queue; it never replaces an existing queue or skips another head. A non-head request reports `QueueOrderConflict` for an explicit user arrangement.
- `harness.queue.release`: `Token`; releases controller ownership without completing a Change or erasing the session's authorized request. Claim and takeover retain the pause independently of ownership. Resume keeps the original authorized UIDs and requires a new resolving source after a pause; an original request, pause source or already consumed resume source cannot resume a later pause. It cannot silently absorb later queue additions.
- `harness.execution.checkpoint` with `State=released`, the exact `ExpectedRevision`, actual `SourceRef` and concrete `Reason` explicitly ends that session request. It releases only a controller owned by that session and preserves the binding history. It never marks work complete. Use this before replacing an unfinished execution scope after the user changes the queue; a subsequent start retains the released record in local history.
- `harness.queue.takeover`: `SessionId`, `PreviousControllerStopped = $true`; only after an explicit takeover request and confirming the former controller stopped. Takeover retains the remaining authorized prefix and cannot widen it. Harness inspects Unreal activity; unresolved activity blocks takeover. Never steal by elapsed time. Transfer the unfinished execution request with `harness.execution.start`, `PreviousSessionId` and `PreviousSessionStopped=$true`; its input IDs, sources, pending/handled state, deduplication, history, pause/blocker and existing handoff authority follow the request. Ownership authority does not consume a new handoff or resolve feedback. An exact retry is idempotent and recovers an interrupted transfer; status alone never replays it. A new request follows explicit release/cancellation and retains the former request in history.
- `harness.queue.checkpoint`: `Token`; automatically captures actual host and plugin identities in indexed `attachments/data/harness-execution.json`. The first checkpoint retains `sourceBaseline`; later checkpoints refresh `source` and repository result HEADs. Primary host evidence includes HEAD, dirty paths and a content fingerprint including untracked files; replica host evidence includes copied/current file hashes. No fake root HEAD is created.
- Optional `Repositories = @(@{path='Plugins/Foo'; baseCommit='<sha>'; resultCommit='<sha>'})` narrows explicit commit evidence; every supplied result must match the actual selected plugin HEAD. Capture before implementation and before final evaluation; paths/runtime bindings remain local, while this attachment stores relative identities.
- The primary source fingerprint excludes canonical `openspec/` records to avoid hashing the checkpoint into itself; those records have their own Change input digest at closure.
- `harness.queue.advance`: `Token`; validates exact manifest UID, Change ID and completed closure in the archive before advancing within the controller's fixed scope. At the authorization boundary it releases ownership without marking the next pending member started or writing its execution evidence. It does not perform verification, archive, merge, push or run an agent.
- Queue mutations use short OS locks, revision checks and a recoverable file transaction. Local state does not duplicate Task DAGs or test evidence.
