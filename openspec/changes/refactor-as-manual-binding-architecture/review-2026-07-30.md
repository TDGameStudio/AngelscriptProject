# Re-review — 2026-07-30 (Superseded)

## Status

This review is retained only as decision history. Its Registry/package/lease design and the two later expanded-description variants were superseded by the 2026-08-07 direct-callback redesign recorded in `design.md`, `research.md`, and the current capability deltas.

Do not implement the previously selected A1/B1 architecture or either intermediate caching architecture. The current change does not call for:

- a Runtime/module-owned public `FAngelscriptBindingRegistry`;
- provider submission from `StartupModule()` or a central manifest;
- package registration handles, leases, unregister/unload blocking, or late replay for the direct callback collection; NativeModuleFunctionAddress is now an explicitly documented temporary transport exception;
- `Requires` / `Before` / `After` dependency strings or authored priorities;
- disabled-package configuration or cascading skip behavior;
- a parser/preflight expansion backed by an engine-independent AngelScript frontend;
- an expanded per-engine or process-wide description of every binding operation;
- a subsystem-owned bind array or pointer list;
- a long-lived `WITH_ANGELSCRIPT_LEGACY_BINDS` compatibility architecture.

The current architecture does require one explicit `EAngelscriptBindPhase` on every direct callback. This is a closed seven-value semantic classification, not the rejected dependency/priority model.

## Evidence Still Retained

Two findings from the original review remain valid:

1. production providers construct some declarations from reflection/enumerated types at runtime;
2. production providers perform auxiliary type, ToString, TypeFinder, BindDB, string-factory, default-array, and interface-signature work in addition to `asIScriptEngine::Register*` calls.

The direct-callback architecture handles both without caching expanded data:

- each full engine replays the sealed callback array through an explicit `FAngelscriptBinds` target;
- reflection and auxiliary callbacks execute in their declared phase and write directly to engine-owned stores;
- AngelScript remains the only declaration-semantic authority;
- the subsystem only loads generated modules and finalizes the one global callback array.
