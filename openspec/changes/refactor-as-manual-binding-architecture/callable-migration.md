# Hand-Written Callable Migration Matrix

This file began as the pre-migration checklist and now records the implemented ownership decisions. The 2026-08-08 audit covers all 130 checked-in production hand-written provider files plus one explicit row for the reflection helper/fallback implementation shared by `Bind_BlueprintType.cpp`. Generated UHT RuntimeLinked and Editor CodeGen providers are variable output rather than checked-in hand-written providers, so their owner/count/parity decisions are recorded in the generated-provider audit below.

## Rules

- A production hand-written callable directly supplied to an AngelScript method/constructor/behaviour/global registration gets a stable named owner function.
- Non-template implementations live in `Bind_<Name>_Functions.cpp`; declarations and required template definitions live in `Bind_<Name>_Functions.h`.
- Direct UE member/free pointers, exact UFunction-address payloads, generated thunks, and metadata-only providers do not receive empty companion files.
- Existing owners such as `FAngelscriptActorBinds`, `FAngelscriptMapBinds`, `FAngelscriptSetBinds`, `FAngelscriptOptionalBinds`, and `FAngelscriptBindHelpers` retain their established names.
- Native/trivial/template-native classification and generated C++ spelling must remain identical after symbol moves.
- The direct-lambda classification is a deliberately narrow multiline source scan of AS callable registration sites. Each row is rechecked manually when migrated so auxiliary finder/delegate/algorithm lambdas are not moved by mistake.
