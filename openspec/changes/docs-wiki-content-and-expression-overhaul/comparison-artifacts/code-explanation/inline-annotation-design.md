# 单列源码内注释实验设计

## 目标

在既有 `01`–`04` 双栏实验之外，再制作四个完全独立的单文件 HTML，验证“不把源码与解释分开”的代码讲解方式。

四个页面都以源码为唯一纵向阅读主轴。解释必须附着在具体代码行、表达式或连续代码段上，页面首次打开时全部展开；读者不需要点击、不需要播放，也不需要在两块面板之间建立对应关系，就能完整理解主要内容。

## 设计判断

现有双栏实验的主要问题不是解释不够，而是源码和解释形成了两个并行阅读任务：

1. 读者先定位左侧代码；
2. 再跨栏寻找右侧对应解释；
3. 阅读解释后还要回到左侧恢复代码上下文。

新实验取消这种空间配对。解释进入源码自己的阅读节奏，采用“解释在前、代码在后”或“代码在前、执行结果紧随其后”的局部结构。

## 非目标

- 不修改 `Wiki/` 子模块。
- 不把实验登记为正式 `built` 或 `tested` Wiki 组件。
- 不创建通用组件库、构建工具或共享运行时。
- 不使用外部字体、CDN、第三方脚本或网络资源。
- 不把解释写进源码字符串；复制操作必须能够得到干净的原始代码。
- 不恢复左右栏、永久侧栏、悬浮总览或完整流程图。
- 不用复杂路径动画代替内容组织。

## 共同阅读契约

### 单一主轴

- 页面内容区最大宽度控制在约 `980px`，居中显示。
- 所有源码、解释和执行值按一个纵向顺序排列。
- 桌面和窄屏使用同一信息顺序，不在移动端重新发明另一套结构。
- 代码块允许内部横向滚动，但页面本身不得产生横向溢出。

### 默认全部展开

- 页面加载后，每条主要解释都可见。
- 读者无需悬停、点击或播放才能获得核心含义。
- “隐藏解释”只是一项临时阅读辅助；再次显示时恢复完整静态内容。
- `prefers-reduced-motion: reduce` 下不影响任何解释的可见性。

### 干净源码

- 源码文本与注释 DOM 分离。
- “复制纯源码”从页面内保存的源码模型生成文本，不复制行号、解释、标记或执行值。
- 每页显示真实证据路径，并明确标识“完整源码”或“控制流摘录”。
- 控制流摘录只允许省略日志、长注释和重复实参换行；不得改变分支条件、调用顺序、所有权或返回语义。

### 轻交互

- 鼠标或键盘聚焦某条解释时，只高亮它对应的代码行或表达式。
- 点击行号或注释标记可固定局部高亮，`Escape` 清除。
- 只允许有限的 `120–180ms` 颜色、边框或背景过渡。
- 不自动播放、不循环动画、不使用移动光点或大范围滚动定位。

### 视觉语言

- 延续 `01`–`04` 的浅灰蓝画布、白色源码纸面、深墨色正文和单一页面强调色。
- 源码使用系统等宽字体；解释使用系统 UI 字体。
- 注释的结构标签必须表达真实语义，例如 `WHY`、`INVARIANT`、`OWNERSHIP`、`RESULT`，不使用纯装饰编号。
- 注释卡减少圆角和阴影，整体更接近“工程批注稿”，避免呈现为仪表盘。

## 原型 05：AS 行间讲解

### 问题

如何让普通函数的解释像教师批注一样，直接进入源码阅读顺序？

### 内容

使用 `Script/Examples/Extended/Example_InterfaceDispatch.as` 中的：

```angelscript
UFUNCTION(Category = "Example Dispatch")
void ApplyDamageToTarget(AExampleDamageableBase Target, float Damage)
{
	if (Target == nullptr)
		return;

	float Remaining = Target.ApplyDamage(Damage);
	if (!Target.IsAlive())
	{
		Print(f"{Target.GetName()} is dead!");
	}
}
```

### 注释语法

- 在相关代码行或连续代码段之前插入全宽解释条。
- 每条解释包含：
  - 语义标签；
  - 一句主要结论；
  - 一段原因或后果；
  - 对应的源码行范围。
- 解释条底部使用短括号或垂直引导线连接紧随其后的代码，不跨越其他解释。

### 主要解释

- `CONTRACT`：`UFUNCTION` 暴露的调用面及参数角色。
- `GUARD`：为什么空目标必须提前返回。
- `DISPATCH`：`ApplyDamage` 为什么可能进入派生类或 BlueprintOverride。
- `DECISION`：为什么用 `IsAlive()` 再次询问对象，而不直接比较 `Remaining`。
- `SIDE EFFECT`：死亡日志何时可见，以及它不改变目标状态。

## 原型 06：AS 表达式脚注

### 问题

如何在不把整行解释成一大段文字的情况下，精确说明表达式内部不同部分？

### 内容

继续使用 `ApplyDamageToTarget`，使 `05` 与 `06` 可以直接比较同一份源码的两种讲解粒度。

### 注释语法

- 在特定 token 或表达式下方绘制非遮挡下划线，并附稳定脚注标记。
- 脚注标记在同一代码行之后立即展开为脚注列表，不集中到页面底部。
- 一行可以有多个脚注，但最多三个；超过三个时合并为一条表达式解释。
- 脚注保持从左到右的 token 顺序。

### 主要脚注

- `Target`：基类静态类型与运行时对象的区别。
- `ApplyDamage`：动态分派与状态改变。
- `Remaining`：调用返回值的用途与本函数未直接用它决策的事实。
- `IsAlive()`：把“存活”的定义留在目标对象内部。
- 格式化字符串：调用方可见的观察性副作用。

## 原型 07：C++ 代码段批注

### 问题

如何解释较长 C++ 初始化函数，而不为每行重复添加微型注释？

### 内容

使用：

`Plugins/Angelscript/Source/AngelscriptRuntime/Core/AngelscriptRuntimeModule.cpp`

中的 `FAngelscriptRuntimeModule::InitializeAngelscript()` 控制流摘录。

### 注释语法

- 将函数划分为连续、互不重叠的语义段。
- 每段之前放置一张展开批注，随后紧跟该段源码。
- 每张批注固定包含三个字段：
  - `WHY`：这段代码为什么存在；
  - `OWNERSHIP`：该路径中的实例由谁持有；
  - `INVARIANT`：维护者不能破坏的控制流或生命周期事实。
- 不把每个语义段画成流程节点；代码段之间的先后顺序就是流程。

### 语义段

- 一次性初始化门。
- 自动化测试覆写接缝。
- Runtime 模块加载和 EngineSubsystem 委托。
- 当前上下文引擎的采用与补初始化。
- 模块自有引擎的创建、压栈和初始化。

## 原型 08：AS 执行值批注

### 问题

如何在源码自身的阅读顺序中展示一次具体执行，而不再生成单独的执行收据面板？

### 内容

继续使用 `ApplyDamageToTarget`，提供三个输入场景：

- `Target == nullptr`
- `CurrentHealth = 100, Damage = 25`
- `CurrentHealth = 20, Damage = 25`

### 注释语法

- 每个有运行时意义的代码行之后紧跟一条 `RESULT` 批注。
- 页面首次打开时所有 `RESULT` 批注都展开。
- 切换场景只更新批注中的值、真假结果和 `executed/skipped` 状态。
- 未执行行仍然保留并显示 `skipped because ...`，不通过隐藏内容制造错误的控制流印象。

### 动态字段

- `Target` 是否为空。
- `ApplyDamage` 前后的 `CurrentHealth`。
- `Remaining`。
- `IsAlive()` 的布尔结果。
- `Print` 是否执行及其输出文本。
- 函数结束后的最终可观察状态。

## 交互与状态模型

每个 HTML 都暴露：

```javascript
window.__CODE_EXPLANATION_PREVIEW__.audit()
```

审计结果至少包含：

- `errors`
- `annotationCount`
- `sourceCount`
- `state`

`08` 额外包含：

- `scenarioCount`
- `selectedScenario`

根元素使用：

- `data-preview-state="idle"`
- `data-preview-state="copied"`
- `data-preview-state="error"`

复制成功提示不得改变页面几何；一段有限状态提示后回到 `idle`。复制 API 不可用时显示可选择的纯源码对话框或文本区域，不向网络发送内容。

## 响应式与无障碍

- 在 `390px` 视口下页面级横向溢出必须为 `0`。
- 代码内部可以横向滚动，并显示非动画的滚动提示。
- 注释字段在窄屏改为纵向排列，不缩小到难以阅读的字号。
- 所有交互元素使用原生 `button`。
- 选中场景使用 `aria-pressed`。
- 局部固定状态必须有颜色以外的边框或标记变化。
- 键盘可以执行复制、隐藏/显示解释、固定局部高亮和 `Escape` 清除。
- 在 JavaScript 初始化前，主要源码和全部静态解释仍然可见。

## 验收

### 静态检查

- 四个目标文件存在且各自包含完整 `<style>` 与 `<script>`。
- 没有外部资源标签或网络依赖。
- 每页都包含真实源码证据路径。
- 每页的注释数和源码锚点数不为零。
- 源码模型能够生成不含注释文本的纯源码。

### 浏览器检查

- 四页通过内置 `audit()`，`errors.length === 0`。
- 默认可见注释数等于模型注释数。
- “隐藏解释”后注释不可见，再次显示后全部恢复。
- “复制纯源码”产生的文本包含函数签名，不包含 `WHY`、`RESULT` 等注释标签。
- 局部注释的键盘固定与 `Escape` 清除有效。
- `08` 的三个场景都能更新到正确执行值。
- 桌面和 `390px` 视口均无页面级横向溢出。
- `prefers-reduced-motion: reduce` 下无持续动画。
- 控制台错误和外部请求均为零。

### 感知检查

对四个页面分别检查桌面和 `390px` 全页截图：

- 源码是否仍是最强视觉层级；
- 注释是否明确附着到相邻代码，而不是形成新的第二栏；
- 长 C++ 行是否只在代码容器内部滚动；
- 默认全部展开后是否仍能看出函数整体形状；
- 标签、边框和强调色是否表达语义而不是装饰。

最多执行两轮定点视觉修正。
