入口是幂等的 只有“已经完成初始化”并且 PrimaryEngine 仍有效时才返回。 两个条件一起检查，避免布尔标记与指针状态意外分离后跳过恢复。 阅读结果：重复调用成本很小，同时不会把半初始化状态误认为完成。
先复用线程/上下文里已经存在的引擎 TryGetCurrentEngine() 是非创建式查询。查到实例后，Subsystem 采用它作为 PrimaryEngine，避免在同一宿主中平行创建第二套脚本运行时。 阅读结果：这是“采用现有资源”分支，不拥有被采用对象的生命周期。
所有权标志决定之后由谁 Shutdown 指针赋给 PrimaryEngine 后立刻把 bOwnsPrimaryEngine 设为 false。后续释放路径据此区分“借用”与“自有”，而不是仅凭指针非空判断。 阅读结果：选择实例与声明所有权在同一个分支完成，减少悬空责任。
采用现有包装器，不代表底层脚本引擎已经建好 GetScriptEngine() == nullptr 时才调用 Initialize()； 已经初始化的 ambient engine 只记录采用日志，不做重复初始化。 阅读结果：对象复用与底层资源就绪是两个独立判断。
兜底分支建立明确的自有生命周期 没有 ambient engine 时，PrimaryEngine 指向成员 OwnedEngine， 所有权标志设为 true，然后初始化。对应的释放路径只会 Shutdown 这一类实例。 阅读结果：函数最终保证 PrimaryEngine 可用，同时保留准确的销毁责任。
