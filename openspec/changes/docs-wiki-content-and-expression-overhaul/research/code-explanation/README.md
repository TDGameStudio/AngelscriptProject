# 源码解释表现研究

本目录是 `docs-wiki-content-and-expression-overhaul` 的长期研究入口，保存源码解释参考、模式归纳和编号实验的历次判断。它不是正式 Wiki 组件目录，也不是发布输入。

## 记录边界

- 编号 HTML 采用追加式历史；新实验不得覆盖、改写或删除旧实验。
- 每个外部参考必须记录直接来源、访问日期、实际展示方式、优点、局限和采纳判断。
- 参考必须实际打开核实，不依据搜索摘要或二手描述下结论。
- 截图只保留能说明设计关系的必要局部，避免完整文章、登录态、个人信息和无关页面内容。
- 外部参考页面的 HTML、CSS、JavaScript、字体和图片不成为实验运行时依赖；专门评估的开源库必须固定版本/许可证/来源并完整内联到对应单文件 HTML。
- 参考画廊只用于 OpenSpec 内部设计研究，不进入 `Wiki/`、插件或发布包。

## 评价维度

1. 源码是否保持连续。
2. note 位于行内、边缘、边注轨、下方索引还是独立正文。
3. 关系依靠编号、高亮、端口、直线、折线还是范围括线。
4. 默认露出完整解释、短注、标签，还是必须交互。
5. 展开详情是否推动或遮挡源码。
6. 键盘、触摸、窄屏和无脚本状态是否仍可理解。
7. 哪些形式值得进入当前实验，哪些只适合作为反例或未来候选。
8. 依赖是否只拥有一个清楚职责，体积、许可证、离线和 teardown 代价是否值得。

## 本轮固定方向

- `09` / `10` 使用小型右侧边注轨。
- `11` / `12` 不使用固定侧边栏。
- `09` / `11` 使用 CSS 连接线；`10` / `12` 使用 inline SVG。
- `13` 根据本轮审阅追加亮色代码块内嵌 note：note 与 connector 在代码块覆盖层中，源码根节点仍只有连续代码行。
- `14`–`17` 沿 `13` 继续比较原生 SVG、LinkerLine、Perfect Arrows 与 Floating UI；具体职责和结论见 `library-evaluation.md`。
- note 默认常显一句低对比短注；完整解释按 hover、focus 或 click 展开。
- 390px 保留完整实验画布，通过容器内部横向滚动查看边注，不把页面改写为另一套信息顺序。

参考提出的新形态如果超出上述边界，只记录为未来 `18+` 候选，不覆盖当前实验。
