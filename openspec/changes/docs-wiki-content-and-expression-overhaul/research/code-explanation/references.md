# 源码解释展示参考

更新时间：2026-07-30

这份记录只研究“如何在不打断源码阅读顺序的前提下，把解释附着到源码附近”。它不是产品依赖清单，也不要求后续实现复刻任何一个站点。截图仅用于本次设计研究，画廊中的每张截图都保留原始来源链接，并以有限尺寸、WebP 压缩、离线内嵌的方式保存。

## 结论先行

09–13 不照搬任何一个参考，而是组合四类已经被验证的表达语法：

1. **主次层级**：采用 Tufte CSS 的 margin note 思路，让源码保持最高对比度，短注解退到视觉第二层。
2. **定位语义**：采用 GitHub 的单行 / 多行范围语义，注解可以稳定指向一行或一个连续代码块。
3. **匹配反馈**：采用 Quarto 的“编号双端匹配 + 激活时突出源范围”，默认不把所有关系都画得很重。
4. **连接视觉**：采用 ExplainShell 的小端口和细正交线；Unreal Directive 只用于校准端口、线宽、状态色之间的层级，不照搬大型 Blueprint 节点。

窄屏处理是一个有意识的分歧。Tufte CSS 等参考通常会把边注折回正文或切换为展开控件；本轮实验按照用户已经确认的方向，保留完整桌面式画布，并把横向滚动限制在注解组件内部，页面本身不产生横向溢出。

## 逐项观察

### 01 · Unreal Directive

- 优点：视觉端口足够小，但仍能说明“信号从哪离开”；执行线、数据线和汇合关系具有明确层级。
- 优点：线条在不增加文字的情况下表达方向和合流。
- 局限：Blueprint 节点本身已经是一个强视觉对象，若直接移植到源码解释，会让注解成为第二个主体。
- 采纳：09–13 的端口尺寸和连接线对比度以它为上限，实际设计会更轻。

### 02 · ExplainShell

- 优点：命令始终是一条连续源字符串，解释系统没有改写源内容。
- 优点：短划线入口、微小端点和正交连接可以处理跨距离对应。
- 局限：解释项过多时，平行线路会快速增加认知负担。
- 采纳：09、11 使用 CSS 折线，10、12 使用 SVG；默认降低线条对比度，只在关联项激活时增强。

### 03 · Backbone Annotated Source

- 优点：解释始终可见，适合从头到尾阅读完整库。
- 优点：长段落可以与长代码块进行纵向对齐。
- 局限：它正是本轮要避免的“左右各占一半”结构；源码宽度和解释宽度互相牺牲。
- 采纳：只保留纵向接近关系，不保留固定双栏。

### 04 · GitHub Pull Request Comments

- 优点：单行和连续多行是同一套选择语义，用户无需学习两套模型。
- 优点：评论入口位于行号附近，默认几乎不可见。
- 局限：评论框插入 diff 后会把后续源码推开，破坏稳定的行几何。
- 采纳：注解锚点留在 gutter / 外缘，详情使用浮层，不插入源码行之间。

### 05 · Quarto

- 优点：源码编号和解释编号互相匹配，连接即使没有画线也能理解。
- 优点：点击解释时才突出代码范围，静止状态很安静。
- 局限：下方列表在长代码上会产生较大的视线往返距离。
- 采纳：所有注解都有稳定短编号；激活时同时增强源范围、端口、线和注解。

### 06 · Tufte CSS

- 优点：边注是“辅助阅读”而不是第二正文，字号、行宽和颜色都主动后退。
- 优点：边注靠近引用点，不要求读者跳到页底。
- 局限：原方案的窄屏折叠会改变文档纵向结构。
- 采纳：侧轨页以极窄 note rail 呈现；无侧栏页的标签也使用同样的轻量层级。

### 07 · Material for MkDocs

- 优点：默认只留下很小的标记，细节通过点击或聚焦出现。
- 优点：标记和浮层支持富文本，并考虑触摸和键盘路径。
- 局限：作者语法常把 `(1)` 放进源码注释，本轮不能让演示标记进入真实源码。
- 采纳：短摘要常驻，完整解释使用 `details`；标记完全位于源码容器外。

### 08 · Code Hike

- 优点：编号映射极稳定，复制代码时不必复制脚注。
- 优点：所有解释默认可扫读，适合教程。
- 局限：统一放在代码下方后，局部解释失去“就在附近”的感觉。
- 采纳：使用双端编号，但将短注解贴近源码外缘或窄侧轨。

### 09 · Expressive Code

- 优点：行、范围和词元标记都有清楚但不夸张的视觉语法。
- 优点：不同语义可用底色、边框和标签组合，而不改变代码字符。
- 局限：它不能单独承载较完整的原理解释。
- 采纳：只在 hover、focus 或 pinned 状态显示淡范围底色。

### 10 · Shiki Twoslash

- 优点：类型、错误和符号信息绑定到精确语义对象。
- 优点：静止时几乎不增加页面噪声，按需查看信息。
- 局限：强依赖 TypeScript 语义服务；纯 hover 交互不能覆盖所有输入方式。
- 采纳：使用同样的按需信息密度，同时增加 focus、Enter 固定和 Escape 关闭。

## 对 09–13 的具体映射

| 页面 | 语言 | 布局 | 连接 | 主要验证问题 |
|---|---|---|---|---|
| 09 | AngelScript | 窄侧轨 | CSS | 侧轨能否像代码旁的轻量批注，而不是第二栏 |
| 10 | C++ | 窄侧轨 | SVG | 长函数和多行范围能否保持连接精度 |
| 11 | AngelScript | 无侧栏、边缘标签 | CSS | 标签能否贴近代码但不进入源码结构 |
| 12 | C++ | 无侧栏、自由 callout | SVG | 在不设固定侧栏时，连接能否仍然克制、可追踪 |
| 13 | AngelScript | 亮色代码块内覆盖层 | CSS | note 视觉内嵌时，能否仍保持源码 DOM 与复制文本纯净 |

五页共同约束：源码 DOM 只含连续 `.code-row`；详情的开合不改变任何源码行位置；复制按钮复制真实源码而不是屏幕上的注解；窄屏横向滚动只发生在 `.annotation-viewport` 内。
