## Required semantic-validator acceptance rules

1. Parse every `proposal.declaration` into an immutable `parsedSignature` containing callable kind, return type, ordered parameter occurrences, exact type, base type, direction, and default.
2. Require unique parameter names for Runtime callables.
3. Allow duplicate parameter names only for explicit `CompileOnly` or `DiagnosticOnly` negative contracts with an exact duplicate-parameter diagnostic.
4. Require `proposal.returnType` to equal the parsed return type; constructors and lambdas use explicit kind-specific rules.
5. Reject property/scanner artifacts as callables; route them to source-only assertions or keep them blocked.
6. Make `proposal.parameters` a one-to-one ordered map of all declaration parameters, or rename it to `inputParameters` and add an authoritative `signatureParameters` list.
7. Require every pure out parameter to exist in the parser-derived signature list and in exactly one writeback channel.
8. Replace loose writeback objects with required `name`, `declaration`, `baseType`, `channelType`, `direction`, and `sourceParameter` fields.
9. Require each value/in/inout parameter in an invoke vector to occur exactly once in `arguments`, `omittedArguments`, or named `fixtureInputs`.
10. Permit `omittedArguments` only for parameters with an exact declaration default.
11. Require every default parameter to have at least one explicit override vector and one truly omitted vector.
12. Forbid `arguments.evidence` as a substitute for typed arguments in review-ready rows.
13. Validate argument values through a tagged union such as typed literal, fixture reference, or source expression with exact type and evaluation phase.
14. Forbid `nominal(Type)`, `default(Type)`, `from cited runner oracle`, `pending`, and equivalent placeholders in review-ready rows.
15. Require a concrete typed `rawReturn` for every non-void successful vector.
16. Require a structured expected writeback keyed by parameter name for every out/inout channel on successful vectors.
17. Require every inout channel to have both an input argument and a post-call expectation.
18. Require return and writeback objects to carry exact type plus comparable content; prose that says the runner compares it is insufficient.
19. Require non-empty `postFailureState` for every failed vector that owns an out/inout channel or other mutable side effect.
20. Reject empty `rawExpectations` as a successful oracle.
21. Require compile diagnostics to record mode, matcher kind, exact matcher text, and that unexpected compile success is failure.
22. Require runtime diagnostics to record exact message or matcher, count, phase, and registration timing.
23. Require runtime exceptions to record comparison, message policy, message, and post-failure state whenever mutable state exists.
24. Forbid null `expectedReturn`, `expectedCompileDiagnostic`, and `expectedException` placeholders in review-ready rows.
25. Make `status.design == review-ready` conditional on zero semantic diagnostics; inject a blocker with an exact JSON field path for every violation and include semantic-validator counts in `manifest.validation.passed`.
