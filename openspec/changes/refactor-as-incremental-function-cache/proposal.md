## Why

`PrecompiledScript.Cache` is a monolithic archive that mixes module declarations, reflected type data, globals, function bytecode, debug data, process-local FunctionIds, pointer-relocation tables, and a random `DataGuid`. It is generated by a dedicated pre-package process, is not maintained by ordinary Editor/PIE compilation, and cannot safely retain unchanged entities when one script changes. The plugin needs a Runtime-owned incremental script-artifact cache that is authoritative to loose `.as` source, works in Editor and packaged targets, and shares only stable function identity with the separate StaticJIT provider system.

## What Changes

- Introduce versioned 256-bit stable identities for modules, types, functions, globals, and properties. Persisted identity no longer depends on process addresses, numeric FunctionIds, source lines, registration order, absolute paths, or random GUIDs.
- Separate the pre-compile `FunctionInputDigest` used for cache lookup from the post-compile `FunctionContentHash` used for artifact validation and StaticJIT matching.
- Replace the single mixed archive with Cache V2 logical records for `SourceIndex`, `ModuleInterface`, `TypeSchema`, `ModuleState`, `FunctionBody`, and `DebugSidecar`, assembled through an atomic `ModuleSnapshot`.
- Store logical records in a bounded number of content-addressed immutable pack files and generation manifests under `Saved/Angelscript/CacheV2/<CompatibilityKey>/<ContextKey>/`. The design explicitly does not create one file per function.
- Restore an unchanged source snapshot without preprocessing, parsing, or compiling. When one module changes, parse that module and reuse unchanged function bodies while invalidating type/global/dependency records according to typed dependency edges.
- Keep current-engine activation module-atomic even when persistence and reuse are entity-granular.
- Add write-through generation publication after successful Editor, PIE, Development, and Shipping startup/reload compilation, plus bounded shutdown flush and explicit verification/compaction.
- Stage editable AngelScript source as loose NonUFS package content. Development and Shipping generate Cache V2 on first end-user launch and incrementally update it on later launches; packaging no longer generates a script-cache baseline.
- Add configurable packaged-runtime reload modes (`Disabled` by default, `Manual`, `Automatic`). Live packaged reload accepts code-only changes and reports `RequiresRestart` for class/global/signature structure changes.
- Add C++, Blueprint, console, and structured diagnostic surfaces for runtime reload, cache status, flush, verification, compaction, and CI reports.
- Add TDD coverage for identity, archive validation, invalidation, compiler reuse, atomic storage, lifecycle, and StaticJIT isolation; finish with real PIE and real Development/Shipping package multi-launch tests.
- **BREAKING**: remove `PrecompiledScript.Cache`, random `DataGuid` pairing, persisted old-pointer/FunctionId relocation, forced-exit cache generation, and the old package pre-step without a compatibility reader or migration tool.
- Keep `Binds.Cache` independent. Cache V2 observes the current binding environment through per-symbol ABI fingerprints rather than merging binding data or invalidating every script for an unrelated bind change.

## Capabilities

### New Capabilities

- `as-script-artifact-identity`: stable module/type/function/global/property identities, pre-compile function input digests, post-compile content hashes, artifact profiles, per-symbol environment fingerprints, collision behavior, and current-engine FunctionId routing.
- `as-incremental-script-cache`: Cache V2 records, module-atomic assembly, entity-granular reuse/invalidation, content-addressed packs, immutable generations, write-through lifecycle, runtime reload policy, diagnostics, validation, concurrency, and legacy rejection.

### Modified Capabilities

- `as-cooked-packaging-runtime`: replace staged `PrecompiledScript.Cache` and the pre-package generation step with loose editable `.as` source, first-launch Cache V2 generation, and Development/Shipping multi-launch verification.

## Impact

- Primary plugin impact: `AngelscriptRuntime` artifact identity, compiler/build seams, Cache service, engine startup/compile/shutdown orchestration, subsystem APIs, settings, diagnostics, and the maintained AngelScript C++ fork.
- Editor impact: reuse the existing directory watcher, hot-reload dependency analysis, class reinstancing, and PIE safe points while publishing Cache V2 only from successful transactions.
- Test impact: add a dedicated `Angelscript.TestModule.Cache.*` automation family and reuse the existing real-PIE harness.
- Packaging impact: `Script/` becomes loose NonUFS source, `RunPackage.ps1` stops pre-generating script cache data, and a separate heavy `CachePackage` suite launches actual Development and Shipping executables repeatedly.
- StaticJIT impact: `refactor-as-static-jit-multi-provider` consumes stable function key/content/profile contracts but owns its provider ABI, generated project module, Live Coding refresh, and Native fallback independently of Cache V2 storage.
- Unaffected: the AngelScript language syntax, existing project `.as` source conventions, `Binds.Cache` format, Standalone offline JSON bundles, and unrelated Unreal DDC/cooked-content caches.
