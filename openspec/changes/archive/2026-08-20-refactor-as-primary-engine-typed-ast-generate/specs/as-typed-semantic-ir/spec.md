## MODIFIED Requirements

### Requirement: HIR capture does not alter VM compilation or persistence

Enabling typed semantic HIR capture SHALL NOT change generated bytecode, bytecode debug/dependency metadata, or script execution behavior. AngelScript `SaveByteCode` SHALL remain HIR-free. Cache V2 FunctionBody bytecode payloads SHALL remain HIR-free. Optional typed-HIR persistence, when present, SHALL use a separate Cache V2 sidecar record and MUST NOT be written into FunctionBody bytes, `SaveByteCode`, public `angelscript.h`, or `.hir.txt`/`.hir.json` dump files.

#### Scenario: Capture-on and capture-off bytecode are identical

- **WHEN** the same source and engine configuration are compiled once with HIR capture disabled and once with capture enabled
- **THEN** the resulting function bytecode and maintained compiler metadata are byte-for-byte equivalent
- **AND** VM execution produces the same observable result

#### Scenario: SaveByteCode and FunctionBody bytes do not serialize HIR

- **WHEN** a module containing captured HIR is saved through AngelScript `SaveByteCode` or the Cache V2 FunctionBody bytecode writer
- **THEN** no HIR nodes, source body, or HIR-specific references are written into those bytecode archives
- **AND** capture-on and capture-off FunctionBody bytecode payloads for the same stable function identity are byte-for-byte equal
- **AND** the removed legacy `PrecompiledScript*.Cache` format remains without a production reader, writer, migration, or dual-write path

#### Scenario: Bytecode-only load without sidecar has no HIR

- **WHEN** a runtime loads a function from precompiled bytecode without a TypedHIR sidecar and without compiling its source
- **THEN** that function has no typed semantic HIR
- **AND** a low-level TypedASTJIT request reports missing HIR, while orchestration that mismatched the whole capture profile fails with `CaptureProfileMismatch`

## ADDED Requirements

### Requirement: Cache V2 may persist a pointer-free TypedHIR sidecar

A capture-on Engine MAY publish an optional Cache V2 `TypedHIRSidecar` record per FunctionBody. The sidecar payload SHALL be pointer-free and SHALL identify calls, types, and functions by stable keys. It MUST NOT store `asCTypedSemanticFunction*`, `asIScriptFunction*`, or engine-local numeric `resolvedFunctionId` values as durable identity.

#### Scenario: Capture-on Editor publishes sidecars

- **WHEN** a typed-ast primary Engine compiles or Hot Reloads a function with verified HIR and publishes Cache V2
- **THEN** that FunctionBody links a TypedHIR sidecar whose content hash covers only the sidecar payload
- **AND** the FunctionBody bytecode payload remains unchanged versus capture-off

#### Scenario: ExactStartup remaps sidecar onto restored functions

- **WHEN** ExactStartup restores a generation that includes TypedHIR sidecars into a capture-on Engine
- **THEN** each restored function receives a verified `asCTypedSemanticFunction` rebuilt from the sidecar
- **AND** engine-local IDs are assigned in the target Engine and are not the values from the publishing Engine

#### Scenario: Typed-ast ExactStartup misses bytecode-only caches

- **WHEN** a capture-on typed-ast Engine attempts ExactStartup of a generation that has valid bytecode FunctionBodies but no TypedHIR sidecars
- **THEN** ExactStartup reports a miss rather than restoring bytecode-without-HIR
- **AND** the caller falls back to source compilation that recaptures HIR

#### Scenario: Dump files remain non-inputs

- **WHEN** `.hir.txt` or `.hir.json` files exist beside a cache generation or Generate request
- **THEN** restore and TypedASTJIT ignore those files
- **AND** only the sidecar payload or live same-compilation HIR can supply typed IR
