# More 侧栏排版预览设计

## 状态与目标

- 日期：2026-07-26
- 用户选择：方向 A，“安静的索引面板”
- 交付物：独立、可交互的单文件 HTML 预览
- 计划路径：`Wiki/comparison-artifacts/more-sidebar-layout/more-sidebar-typography-preview.html`

本预览只优化主侧栏“更多”下方 11 个原生分类的字体、字重、行高、间距、分组和长文本排版。它保留当前已认可的 Notion 浅色 palette、84px 分类列、1px 分隔线、浅蓝选中面和蓝色选中竖线，不修改正式 Wiki 源码。

## 当前问题

正式 Wiki 当前存在以下排版不一致：

1. 11 个分类按钮全部为 `13px / 600`，未选中项持续抢占视觉注意力。
2. 普通内容链接使用 `14px / 500`，标签管理与探索分组标题使用 `11px / 600`，字号和字重频繁跳动，但没有形成稳定的信息层级。
3. 列表型分类没有一致的内容标题、数量和空状态，内容会直接从面板顶端开始。
4. 插件名称、冒号和英文描述混在同一阅读层级，窄列换行后卡片节奏破碎。
5. 探索树的目录、文件、数量和展开控件字重接近，多层结构容易退化为连续文本。
6. 系统 tiddler 路径与普通中文文档标题使用相同排版，技术标识和阅读标题没有区分。

## 预览结构

预览是一个独立页面，不复制完整 TiddlyWiki 导出文件。页面包含：

- 一个与正式 Wiki 尺寸和配色接近的 More 侧栏主体；
- “当前版 / 优化版”视图切换；
- 全部、最近、标签、缺失、草稿、孤立、类型、系统、默认、探索、插件 11 个真实分类；
- 每个分类的代表性真实风格数据；
- 一个简短的字体层级说明区，仅用于评审，不进入正式产品。

默认打开“插件”，因为它同时暴露分类栏、内层 tab、图标、标题、英文描述和多行换行问题。切换分类时只显示一个关联面板。

## 字体与排版 Token

### 字体角色

- UI 与中文内容：`"Segoe UI", "Microsoft YaHei", "PingFang SC", system-ui, sans-serif`
- 系统路径与技术标识：`"Fira Code", "Cascadia Mono", Consolas, monospace`

技术等宽字体只用于 `$:/...`、MIME 类型和明确的系统路径，不用于普通中文标题、分类标签或说明。

### 字体层级

| 角色 | 字号 | 字重 | 行高 |
|---|---:|---:|---:|
| 未选中分类 | 12px | 400 | 18px |
| 选中分类 | 12px | 600 | 18px |
| 内容区标题 | 12px | 600 | 18px |
| 内容计数/元数据 | 11px | 500 | 16px |
| 普通条目 | 13px | 400 | 18.5px |
| 当前项/重要名称 | 13px | 500 | 18.5px |
| 分组标题 | 11.5px | 500 | 17px |
| 描述与日期 | 12px | 400 | 17.5px |
| 系统路径 | 11.5px | 400 | 17px |

中文分组标题不添加额外字距；数量使用 tabular numerals。避免在 11–14px 范围内大面积使用 600 字重。

### 间距与几何

- 分类列保持 84px，分隔线保持 1px。
- 分类按钮最小高度由 30px 收紧到 28px，间距为 1px。
- 分类按钮横向 padding 为 `5px 8px 5px 10px`。
- 内容区 padding 为 `4px 8px 12px 12px`。
- 内容区统一增加 32px 高的上下文标题行；标题在左，数量在右。
- 普通单行条目最小高度 28px；多行条目自然增长，不裁切中文。
- 同组条目间距 1px，分组间距 8px。

## 11 个分类的内容模板

### 扁平列表

适用于全部、缺失、草稿、孤立和默认：

- 顶部显示分类名称与总数；
- 普通文档标题使用 `13px / 400`；
- 当前或重要标题使用 `13px / 500`；
- 默认分类中的 `$:/...` 使用技术等宽字体；
- 长标题允许两行以上自然换行，保持一致的左右 padding；
- 没有内容时显示一行克制空状态，例如“没有草稿”。

### 时间列表

适用于最近：

- 顶部显示“最近”和条目数；
- 日期作为 `11.5px / 500` 分组标题；
- 条目标题与时间拆成主次两列或两行；
- 时间为弱化元数据，不与标题使用相同字重。

### 标签与类型分组

适用于标签、类型和系统：

- 标签保留正式 Wiki 已认可的 4px 方形圆角和原生颜色变体；
- “标签管理”作为标题行右侧的次级操作，不再单独占据一个突兀的 11px 标题行；
- 类型和 MIME 名称作为小分组标题；
- 分组下的 tiddler 使用普通条目样式；
- “未设标签”保持平面列表语义，与彩色标签区通过 8px 分组间距和细分隔区分。

### 探索树

- 顶部显示“探索”和可见节点数；
- 图标固定 14px，层级缩进以 16px 为步长；
- 目录使用 `13px / 500`，文件使用 `13px / 400`；
- 节点数量使用右侧 `11px / 500` 元数据；
- 展开按钮与标题共享一条 28px 行，不让图标、按钮和文本形成三个不同基线；
- 系统路径可使用等宽字体，但目录标题仍使用 UI 字体。

### 插件卡片

- 顶部显示“插件”和已安装数量；
- 内层“语言 / 插件 / 布局主题”采用 12px 的安静横向 tab；
- 插件图标固定 20px；
- 插件名称独占第一行，使用 `13px / 500`；
- 描述位于下一行，使用 `12px / 400`，不再通过冒号与名称挤在同一文本流；
- 卡片保持透明背景，只有 hover/focus 时出现当前浅色 surface 与细边框；
- 描述允许自然换行，不做强制单行省略。

## 色彩边界

预览继续使用当前正式 More 色板：

- Surface：`#edf3f7`
- Divider：`#dbe4ec`
- Ink：`#45566a`
- Muted：`#667589`
- Accent：`#236c99`
- Accent soft：`#e6f1f7`

本实验不引入新的强调色、渐变、阴影或大面积卡片背景。字体和结构必须在不改变配色的情况下完成层级修复。

## 交互与可访问性

- 分类使用 `role="tablist"`、`role="tab"` 和 `role="tabpanel"`；
- 鼠标点击与 Enter/Space 可选择分类；
- 上下方向键在分类之间移动并选择，Home/End 跳到首尾；
- 焦点使用现有蓝色轮廓，不仅依赖背景颜色；
- “当前版 / 优化版”切换保留当前分类；
- 所有状态切换不改变面板整体宽度；
- 支持 `prefers-reduced-motion`，预览不依赖动画表达状态。

## 响应与边界

- 主要评审尺寸模拟正式桌面 More 内容宽度；
- 页面在 320px 以上保持无水平溢出；
- 预览不实现完整 Wiki resize、持久化、标签 popup portal、数据过滤或保存行为；
- 预览不导入远程字体、脚本、图片或 CDN；
- 预览不修改 `new_review2.html`、正式主题、正式 tiddler 或现有测试。

## 验收标准

1. 单个 HTML 文件离线打开即可工作。
2. 11 个分类均可通过鼠标和键盘切换，始终只有一个面板可见。
3. “当前版 / 优化版”切换能清楚展示字号、字重、分组和换行差异。
4. 列表、时间、标签/类型、探索树和插件卡片五种内容形态均有代表场景。
5. 优化版保留正式配色和 84px 分类列，不以新的颜色效果掩盖排版问题。
6. 中文标题、英文插件描述、长 `$:/...` 路径和空状态都没有水平溢出。
7. HTML 通过基础结构检查，并使用浏览器验证桌面与窄宽度的交互和布局。
