# V2.7 Read-only Python Cache V2 dump closure

Date: 2026-08-10 (Asia/Shanghai)

## Outcome

V2.7 now provides a plugin-owned standalone Python inspector at
`Plugins/Angelscript/Tools/CacheV2Dump/cache_v2_dump.py`. It accepts an explicit
Cache root, namespace root, Manifest, Pack or named pointer, launches no Unreal
process and contains no Store write/repair operation. Deterministic text and
sorted JSON are both supported.

The tool is intentionally a read-only physical-integrity and diagnostic reader.
It does not reproduce the Runtime's complete semantic validator or activate a
module. Known, versioned common record headers and ModuleSnapshot/FunctionBody/
DebugSidecar links are decoded for inspection. VM execution, initializer and
debug bytes remain opaque metadata. A record with an unsupported payload schema
is labelled `decoder_scope: unavailable`; it is not falsely presented as a
fully semantically validated Runtime record. Once the tool selects an exact
matching schema decoder, malformed fields are corruption and produce a
structured nonzero error rather than being downgraded to unavailable metadata.
Its product role is testing, debugging, verification and human observation of
cache data. It does not generate, repair, activate or recover a Runtime cache.

## Implemented layout

```text
explicit input
  |
  +-- cache/base root ---- discover compat/context namespaces deterministically
  |                           |
  |                           +-- Current / Previous / Pending pointers
  |                           +-- selected Generations/*.asmanifest
  |                           +-- referenced Packs/*.aspack
  |
  +-- namespace root ------ same pointer/generation path
  +-- *.asmanifest -------- infer sibling Packs directory
  +-- *.aspack ------------ validate/dump one physical Pack
  +-- *.ascurrent --------- inspect the named slot in its namespace

Pointer: 80-byte UEASCV2C + kind + GenerationId + BLAKE3 checksum
Manifest: UEASCV2M + roots + record locations + whole-file GenerationId
Pack: UEASCV2P + sorted 96-byte index + exact contiguous data ranges
  |
  +-- None/Zlib bounded decode
  +-- RawChecksum = BLAKE3(raw payload)
  +-- RecordId = kind-separated Cache record-domain BLAKE3
  +-- Manifest location == Pack index entry
  +-- common semantic summary and full stable-key collection
```

The format implementation is split from CLI/path/filter/rendering:

- `cache_v2_format.py` owns the exact bounded wire reader, optional accelerated
  and dependency-free fallback BLAKE3-256, RecordId hashing, pointer/Manifest/
  Pack validation, safe Zlib decode, Manifest-to-Pack link checks and common
  semantic summaries.
- `cache_v2_dump.py` owns explicit input discovery, generation/module/record-
  kind/stable-key filters, deterministic document shape, text rendering,
  structured errors and process exit codes.
- `README.md` records supported commands, validation scope and the explicit
  opaque-payload boundary.
- root `Tools/RunCacheV2DumpTests.ps1` is the repository wrapper and writes only
  test logs/summaries under its requested `Saved/Tests` output root.

## Filters and output

- `--generation` accepts a full/prefix GenerationId or Current, Previous and
  PendingColdStart slot names; it is repeatable.
- `--module` accepts an exact canonical module name or ModuleKey prefix. At a
  Generation root it follows the selected ModuleSnapshot links and retains the
  generation SourceIndex authority.
- `--record-kind` accepts the seven names or numeric values and is repeatable.
- `--stable-key` accepts a hexadecimal prefix, matches decoded stable keys and
  always emits the full matching key.
- text and JSON order is derived only from canonical namespace/generation/index
  order. Temporary absolute directory names are not serialized.

Success exposes exact magic/schema/header/index values, pointer roots, complete
stable identities, generation/module links, Pack offsets and stored/raw sizes,
codecs, raw checksums and RecordId integrity. Errors use one stable object with
`code`, `stage`, `message` and optional basename/byte offset, write it to stdout,
return exit code `2`, emit no traceback and do not return a partial corrupt record
as valid.

## Discovered implementation constraints

1. Windows PowerShell 5 wraps Python `unittest`'s normal stderr progress stream
   as `NativeCommandError`. The final wrapper uses a redirected foreground
   `System.Diagnostics.Process`, preserves the native exit code and emits one
   clean combined log; see IC-283.
2. Python's standard library has no BLAKE3. Requiring a package would violate the
   standalone/no-bootstrap expectation, while skipping the hashes would fail the
   integrity contract. The tool therefore contains a small unkeyed BLAKE3-256
   fallback, optionally uses an already-installed `blake3` accelerator and
   freezes both official and multi-chunk tree vectors; see IC-284. Cross-language
   compatibility is exercised by the Python suite reading the exact Pack,
   Manifest and Zlib golden bytes already frozen by the C++ Cache tests; Python
   behavior is not duplicated in a UE test target.
3. Generic offline inspection must not pretend to understand maintained-fork VM
   artifact bytes. The current decoder exposes only codec/version/hash/size for
   execution/debug payloads and marks initializer payload policy opaque. A future
   explicit decoder must be version matched before it can widen this boundary.
4. The tool validates physical wire integrity and the common summaries it owns;
   complete SourceIndex/ModuleInterface/TypeSchema/ModuleState semantic and graph
   validity remains the Runtime's authority. This distinction is visible in
   output and README rather than being hidden behind a generic `valid` flag.

## Completion boundary

V2.7 is complete. This does not prove that Editor startup currently consumes
Cache V2: V3 still owns DirectSourceInputs and exact warm restore, V4/V5 own
incremental invalidation/compiler reuse, V6 owns service/Editor/PIE lifecycle,
and V7 owns Development/Shipping multi-launch and final package acceptance.
