# V3.4 fresh-engine restore and activation packet

Date: 2026-08-10 (Asia/Shanghai)

## Outcome and non-goal

V3.4 is complete only when one isolated `FAngelscriptEngine` compiles and
publishes a Cache V2 generation, is destroyed, and a second independently
initialized `FAngelscriptEngine` restores that generation without compiling the
selected module. The restored module must be executable through the normal
plugin-owned engine surface, not merely readable by `asCReader` or discoverable
through a raw `asCModule*`.

V3.4 does not yet prove the production startup counters required by V3.5, nor
does its first representative vertical claim support for every class/global/
initializer shape. It establishes the real restore/activation ownership seam
using the currently admitted clean-capture fixture (one enum plus one
self-contained primitive global function), then subsequent verticals extend the
same seam. It must not add a hidden whole-module blob or call the source compiler
inside the consumer.

## A new Engine has two state layers

`FAngelscriptEngine` is the product-level owner. A valid restore cannot stop at
the maintained fork's `asCScriptEngine`/`asCModule` objects.

```text
new FAngelscriptEngine
        |
        +-- freshly initialized environment (never copied from cache)
        |     asCScriptEngine configuration
        |     native/manual/generated binds
        |     BindState / BindDatabase / TypeDatabase environment authority
        |     namespaces, native types/functions/properties and ABI catalog
        |
        +-- Cache V2 reconstructed script projection
              staging asCModule and script types/functions/globals
              current-engine numeric FunctionIds
              FAngelscriptModuleDesc and child descriptors
              imports/dependencies and ScriptModule back-pointers
              ActiveModules / ModulesByScriptModule / active type indexes
              ClassGenerator/reflection handoff where required
              StableFunctionKey -> current live function route table
```

The environment layer is recreated by normal
`InitializeWithoutInitialCompile()`/binding initialization and is validated
against the generation's profile/environment dependencies. Persisting any
native pointer, type id, function id, `FName` index, bind-registration order or
process-local database state is forbidden.

The script projection is rebuilt only from the complete validated
`ModuleSnapshot` graph. `ModuleInterface`, `TypeSchema`, `ModuleState`,
`FunctionBody` and `DebugSidecar` records are therefore reconstruction inputs,
not only hashes used to bless a separate legacy archive.

## Ownership and commit boundary

The restore coordinator operates under the owning `FAngelscriptEngine` and has
three distinct states:

1. **Immutable candidate** — one pinned generation plus locally and graph-
   validated decoded records. It contains no live AS/UE pointers.
2. **Staging projection** — temporary live AS module, reconstructed plugin
   descriptors, and a candidate stable-route array. It is not present in
   `ActiveModules`, `ModulesByScriptModule`, active class/enum/delegate indexes,
   ClassGenerator output, or the published route table.
3. **Active projection** — all module/plugin indexes, reflection handoff and
   stable routes are committed together after final validation.

```text
pinned generation
      |
      v
decode + complete graph/profile/environment validation
      |
      v
temporary asCModule under a non-public staging name
      |
      +-- materialize TypeSchema declarations/layouts
      +-- materialize ModuleInterface declarations/imports
      +-- restore FunctionBody through a maintained-fork VM adapter
      +-- apply DebugSidecar to the restored function
      +-- allocate current Engine FunctionIds
      +-- restore ModuleState/globals/initialization plan
      +-- build FAngelscriptModuleDesc projection and stable routes
      |
      v
final cross-layer validation
      |
      +-- failure: discard staging module/descriptors/routes; active state unchanged
      |
      `-- success: atomic plugin-level activation and normal JIT/global finalization
```

Using `asCReader::ValidateFunctionArtifact()` alone is insufficient: it creates
and destroys a detached half-built function to prove the opaque bytes are
well-formed. The maintained fork needs a restore operation that rebuilds the
complete private VM state, translates symbolic operands, installs debug data and
returns/attaches a live function to the staging module. Raw bytecode copying is
forbidden.

## Numeric and stable function identity

The cache never supplies a numeric `FunctionId`. The consumer allocates the
current ID while attaching the function to the new VM, then prepares an
engine-owned route entry:

```text
{ StableFunctionKey, FunctionContentHash, ArtifactProfileKey }
                         |
                         v
{ current asIScriptFunction*, current numeric FunctionId }
```

The candidate route array remains private until the complete ModuleSnapshot is
accepted. Duplicate stable keys, a route to a function outside the staging
module, a declaration/function ABI mismatch, or a function missing from either
the interface or snapshot fails the transaction. StaticJIT later consumes the
same stable identity but does not own Cache Pack/Manifest/Generation identity.

## `FAngelscriptModuleDesc` reconstruction

The module descriptor is not optional test decoration. Normal plugin lookup,
HotReload, ClassGenerator, source navigation, dependency processing and module
discard all assume it exists and agrees with the live `asCModule`.

For every supported record shape the reconstruction adapter must populate the
semantically relevant fields from records, including:

- canonical module name, imported-module names and post-init ordering;
- class/struct, enum and delegate descriptors plus metadata/reflection traits;
- property and reflected-function descriptors and their live ScriptType/
  ScriptFunction links;
- the `ScriptModule` back-pointer and successful restored state;
- source/debug logical coordinates needed by diagnostics/navigation without
  requiring preprocessing.

Fields that exist only as transient preprocessor implementation scratch are not
blindly serialized. If an existing consumer still requires one after exact
restore, either derive it deterministically from the semantic records or move
that consumer to a stable reconstructed DTO. Do not re-run preprocessing just to
recreate an obsolete scratch representation.

The current clean-capture vertical owns an enum plus a global function. Its
first activation packet therefore has a minimal but real module descriptor:
module name, enum descriptor/type link, live ScriptModule link and stable global
function route. This is a supported-shape boundary, not permission for later
class/reflection restores to omit their descriptors.

## First RED/GREEN tests

Create a separate `AngelscriptCacheFreshEngineRestoreTests.cpp` test class and
keep it behind `WITH_ANGELSCRIPT_UNITTESTS`.

1. `ColdGenerationRestoresExecutableFunctionIntoFreshEngine`
   - Engine A normally compiles the admitted enum/function fixture.
   - Capture, prepare, publish and reopen one physical Cache V2 generation.
   - Destroy Engine A before Engine B exists.
   - Engine B runs normal bind/environment initialization only.
   - Restore the selected snapshot without calling `BuildModule`, preprocessor,
     parser or compiler for that module.
   - Resolve `Answer()` through both normal module lookup and its stable route,
     execute it, and observe `42`.
   - Confirm the live enum and `FAngelscriptModuleDesc` are visible through the
     owning `FAngelscriptEngine`.
   - Confirm the route records Engine B's current numeric FunctionId; never
     assert that two independent engines happen to allocate different numbers.

2. `LateArtifactFailureLeavesFreshEngineUnchanged`
   - Feed a candidate whose record hashes/graph links are internally updated but
     whose opaque execution artifact fails at the private VM restore boundary.
   - Observe typed rejection, no active module, no plugin module/type index and
     no stable route.
   - A later authoritative compile remains possible in the same Engine.

3. Add focused route tests before broad lifecycle integration:
   - duplicate stable route key is rejected atomically;
   - a numeric ID cannot resolve without its owning Engine route;
   - discarding/replacing a module removes or replaces all of its routes;
   - two Engines may reuse one numeric ID without cross-routing.

## V3.4 verification gate

- focused fresh-engine restore class GREEN with diagnostic logs for generation,
  module, stable key, current FunctionId, execution result and rollback state;
- existing clean-capture/cold-generation/opaque-validation prefixes GREEN;
- complete `Angelscript.TestModule.Cache` prefix GREEN;
- official wrapper build GREEN;
- strict OpenSpec validation and parent/plugin `git diff --check` clean apart
  from documented line-ending warnings.

V3.4 closes only after the executable Engine A -> disk Cache V2 -> destroyed
Engine A -> Engine B path passes. V3.5 then instruments the production startup
entry so an unchanged second launch proves zero preprocess, parse and function-
compiler calls and no redundant generation write.
