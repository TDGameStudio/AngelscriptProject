# V3.1 DirectSourceInputs and first-stage candidate identity

Date: 2026-08-10 (Asia/Shanghai)

## Purpose

V3.1 answers one startup question before invoking any AngelScript preprocessor,
parser or compiler:

> Are the inputs that can be observed directly from source discovery exactly the
> same as the inputs used to create this historical candidate?

It does not decide whether recorded includes, generated sources or conditional
values remain valid. Those are persisted second-stage dependency candidates in
V3.2. Keeping the stages separate prevents an implementation from running the
preprocessor merely to discover whether it could have skipped preprocessing.

## Implemented contract

`FAngelscriptCacheDirectSourceInputs` contains only startup-observable values:

- artifact Profile;
- discovery-policy version and Editor/Development filters;
- explicitly kinded Compiler or Preprocessor option key/value pairs;
- stable SourceProvider, Mount and PreprocessHook authorities and fingerprints;
- each source's mount coordinate, logical relative path, exact raw bytes,
  optional generated-source identity/configuration and owning ModuleKey.

The Planner never accepts an absolute disk path and never stores one in the
projection. A file references a typed logical mount, and the existing
`FAngelscriptCacheSemanticArchive` remains the sole authority for path
normalization, derived provider/mount/hook/file keys, Unicode simple-fold path
collision checks, graph references and capability/ineligible consistency.

The current producer flow is:

```text
DirectSourceInputs
  |
  +-- preflight counts / per-file bytes / aggregate raw-byte budget
  +-- exact BLAKE3(raw source bytes)
  +-- Compiler and Preprocessor option domains stay distinct
  +-- derive SourceFileKey from logical coordinates
  +-- derive provider/hook missing-capability ineligible rows
  |
  v
Canonical direct-only SourceIndex projection
  |   PreprocessorInputs = []
  |   Edges              = []
  |   SourceSnapshot     = hash of this valid direct-only projection
  |
  v
DirectInputDigest = BLAKE3(domain, profile + canonical direct authorities)
```

The digest deliberately includes raw source hashes. Therefore adding only a
space or changing line endings is a safe first-stage miss. A later optional
token/semantic reuse layer may recover more work only after authoritative
preprocessing; it cannot weaken this first-stage exactness rule.

## Two-digest boundary

`SourceSnapshot` and `DirectInputDigest` serve different purposes:

```text
DirectInputDigest
  = profile + discovery + options + mounts/providers/hooks + files/raw hashes

SourceSnapshot
  = complete SourceIndex above
    + persisted preprocess/include/generated candidates
    + source edges
    + derived ineligible rows
```

`ComputePersistedDirectInputDigest` canonicalizes and validates a persisted
SourceIndex, then hashes only its direct projection. Changing a persisted
conditional/include dependency must not change this first digest; V3.2 validates
that dependency after candidate lookup. Changing raw bytes, profile, logical
coordinates, owning module, explicit options or provider/hook authority must
change it.

The `DirectProjection` returned by V3.1 is not a final persisted SourceIndex. It
is an explicitly named intermediate onto which V3.2 appends bounded dependency
candidates and recomputes the complete `SourceSnapshot`.

## Test authority and current state

Ten methods in the separate
`AngelscriptCacheDirectSourcePlannerTests.cpp` cover:

1. input-order independence and equivalent logical-path normalization;
2. independent raw-byte, Profile, option, provider-version, hook-version and
   ModuleKey invalidation, including whitespace as an exact raw-byte change;
3. separation of persisted preprocess dependency values from the direct digest;
4. provider/hook missing-fingerprint rows restricted to their typed scopes;
5. Unicode simple-fold path collision, invalid mount reference and raw-byte
   budget failure;
6. empty raw option keys rejected before compiler/preprocessor namespacing;
7. a true embedded NUL rejected without mistaking FString's terminator for data;
8. one shared canonical-string input budget across every direct authority;
9. one aggregate option budget across direct and Mount options; and
10. the frozen V1 identity
    `a0344dacb06ef4c92ec9a8a413d1bbcca7a4814d80ad2d1f1b2bac4157202197`.
