# V4.2 semantic RecordId diff packet

Date: 2026-08-10 (Asia/Shanghai)

## Outcome

V4.2 is complete when two already graph-validated Cache V2 generations can be
compared without reading or comparing physical Pack bytes. The comparison
matches semantic owners first and then compares their complete RecordIds. It
classifies module-interface, type-schema, module-state, function-body and
debug-sidecar changes and publishes the exact reused/new/retired semantic record
sets needed by V4.3.

The comparison is a pure immutable-data operation. It does not consult an
`FAngelscriptEngine`, current numeric FunctionIds, native addresses, live module
pointers, source files or the preprocessor.

## Input authority

The production entry point accepts two `FAngelscriptValidatedGeneration` values.
Those values have already passed Manifest/Pack integrity, all-record decoding,
exact reachability and `ValidateModuleSnapshotGraph`. V4.2 still fails closed if
the public value has subsequently been forged into an impossible shape (missing
root/record, wrong kind, duplicate semantic owner or mismatched embedded owner),
but it does not rerun opaque codecs or current-symbol/layout resolution.

Incremental comparison is legal only inside the same Compatibility, Context and
ArtifactProfile coordinates. A mismatch is not a source edit and returns an
incompatible-input error; startup selection must choose another namespace/profile
instead.

## Semantic ownership and comparison

```text
Manifest SourceIndexRecordId                    -> source-input change

ModuleSnapshot.ModuleKey                       -> module owner
  ModuleInterface.RecordId                     -> module interface
  TypeSchemas[TypeKey].RecordId                -> individual type schema
  ModuleState.RecordId                         -> module globals/init state
  FunctionBodies[StableFunctionKey].RecordId   -> individual function body
    FunctionBody.DebugSidecar[FunctionKey]     -> individual debug sidecar
```

Matching uses the full-width stable owner key. Once an owner is matched, equality
uses the complete `{RecordKind, BLAKE3-256}` RecordId. Physical PackId, Pack
offset, codec, compressed bytes, Manifest location and GenerationId never select
a semantic result.

For keyed type/function/debug collections, additions and removals remain distinct
from modifications. A function rename therefore appears as old-key removal plus
new-key addition, while an implementation edit under the same StableFunctionKey
appears as a modification. DebugSidecar is compared independently even though the
owning FunctionBody also links it and therefore normally receives a new RecordId
when debug identity changes.

ModuleSnapshot and SourceIndex are transaction/root records rather than one of
the five compile-artifact classifications. They are nevertheless included in the
global reused/new/retired RecordId sets so V4.3 can construct a complete exact
reachable generation.

## Result contract

The result contains:

- SourceIndex change and one sorted entry per added/removed/modified/unchanged
  module;
- per module, explicit interface and module-state dispositions plus sorted changed
  TypeKey, StableFunctionKey body and StableFunctionKey debug entries;
- sorted `ReusedRecordIds`, `NewRecordIds` and `RetiredRecordIds` over every
  reachable semantic record, including SourceIndex and ModuleSnapshot;
- a typed error and diagnostic for incompatible or impossible input.

`Unchanged` is retained explicitly for module/interface/state so diagnostics can
distinguish a proven hit from an unexamined category. Per-type/function arrays
contain only changed owners to keep the common body-only result compact.

## First TDD evidence

Add a separate `AngelscriptCacheSemanticDiffTests.cpp` test class.

1. Build and graph-validate the same real clean-compiled module into one aggregate
   Pack and one-record physical Pack shards. Their Pack/Generation identities
   differ but the semantic diff must be empty and all seven RecordIds must be
   reused.
2. Compile the same stable module with only `return 41` changed to `return 42`.
   SourceIndex, FunctionBody and ModuleSnapshot change; ModuleInterface,
   TypeSchema, ModuleState and DebugSidecar remain semantic hits.
3. Change only the enum authority value. The TypeSchema changes under the same
   TypeKey while the function body and module state remain hits.
4. Shift source line positions without changing declarations or executable
   tokens. DebugSidecar is classified independently; the owning FunctionBody may
   also change because it embeds the debug identity.
5. Rename the global function without changing its shape. ModuleInterface changes
   and the old/new StableFunctionKeys are reported as removal/addition rather than
   a false in-place modification.
6. Reject a different ArtifactProfile as incompatible rather than calling it a
   source edit, and fail a subsequently forged/missing reachable record with an
   atomic empty diff.

The expected RED is the missing semantic-diff API/header. GREEN requires the
official Development Editor build, the focused class, complete Cache regression,
strict OpenSpec validation and both parent/plugin diff checks.

## Non-claims

- V4.2 does not publish a generation or reuse a Pack; V4.3 consumes its result.
- V4.2 does not decide dependent-module propagation; V4.4 consumes interface and
  typed dependency changes.
- V4.2 does not implement per-function compiler hits; V5 owns that hook.
- The current real clean-capture fixture still admits only one simple enum plus
  one self-contained primitive global function. Modified non-empty ModuleState,
  classes/properties/layout and initializer breadth remain V4.5/later capture
  widening, although the generic RecordId classifier already handles those
  validated records.
- No old Engine pointer, numeric FunctionId, native address or compilation scratch
  is accepted as comparison input.
