## Context

The current script precompile path is owned by `StaticJIT/PrecompiledData.*` and writes one `Script/PrecompiledScript.Cache`. The archive combines module declarations, classes and reflected type metadata, globals and initializer functions, function bytecode/debug data, global type/function/property/string relocation tables, process-local numeric FunctionIds, old pointer tokens, and a random `DataGuid`. The cache is normally generated by a special process that exits after saving; ordinary Editor, PIE, Development, and packaged runtime compilation does not maintain it.

That design makes the complete archive and generated StaticJIT source a matched pair. It cannot retain one unchanged function independently, cannot distinguish class-layout invalidation from a body edit, and cannot safely use numeric FunctionIds after hot reload or in multiple engines.

The existing compiler and hot-reload architecture nevertheless provides the required seams:

- `FAngelscriptModuleDesc` retains logical/virtual source paths, processed sections, declarations, imports, code hashes, and compiled module state.
- `asCModule::FModuleDependencyInfo` and `DiffForReferenceUpdate` already distinguish normal, hard-value, and structural dependencies.
- `asCBuilder::BuildCompileCode()` reaches several distinct compile families: the normal/generated `CompileFunctions()` loop, a separate factory loop, and the public single-function `CompileFunction()` path. Cache coverage must enumerate these entry points explicitly rather than assuming one loop owns every callable.
- Global initializers are compiled through a dependency-solving module pass and therefore require a different cache unit.
- `FAngelscriptEngine::CompileModules()` already separates parallel parsing from serialized type/layout/code/global/swap/ClassGenerator stages.
- Editor has a directory watcher, class reload helper, and real PIE lifecycle harness.
- Runtime compiler code remains available in configured Development and Shipping targets.

This change owns stable script-artifact identity and Cache V2. The sibling `refactor-as-static-jit-external-module` consumes the function identity contract but remains independent of Cache V2 storage and lifecycle.

IC-475 corrected the last production connection after the first real Development
warm launch. The authoritative V5.6 timing, selected-session lifetime, shared
current-authority boundary, diagnostics and TDD slices are recorded in
`v5.6-production-compiler-reuse.md`. That correction preserves function-granular
reuse and exact-start atomicity; direct builder-callback tests alone are no longer
sufficient evidence of production compiler reuse.

## Goals / Non-Goals

**Goals:**

- Preserve unchanged AngelScript work across Editor, PIE, Development, and Shipping launches.
- Make exact unchanged startup bypass preprocessing, parsing, and compilation after source-content verification.
- Allow a changed module to reuse unchanged function bodies while correctly invalidating declarations, types, globals, and dependent modules.
- Keep active-engine publication module-atomic even though persistent records are entity-granular.
- Make loose source authoritative and generate/update Cache V2 on first and later packaged launches.
- Support existing Editor structural hot reload and a conservative code-only packaged live-reload policy.
- Separate StaticJIT Native routing from AS cache validity.
- Use bounded parallel pure-data work and serialized active-engine mutation.
- Make corruption, partial writes, concurrent writers, profile mismatch, and shutdown interruption recoverable.
- Provide deterministic diagnostics, exact compile/hit counters, and final real PIE/package evidence.

**Non-Goals:**

- Reading, migrating, or dual-writing `PrecompiledScript.Cache`.
- Changing `Binds.Cache` format or ownership.
- Requiring stable IDs, GUID annotations, or syntax changes in business `.as` source.
- Compiling functions concurrently inside one `asCScriptEngine`.
- Supporting live class/global/signature structure replacement in packaged games.
- Generating or compiling a StaticJIT C++ module at end-user startup.
- Replacing `FAngelscriptTypeDatabase`, Standalone offline bundles, Unreal DDC, or cooked asset storage.
- Guaranteeing one-function invalidation for changes whose real semantic dependency closure is wider.

## Decisions

### Cache and identity ownership move out of StaticJIT

Create two Runtime-owned boundaries:

```text
AngelscriptRuntime/Core/Artifacts/
    stable entity identity
    function input/content identity
    artifact compatibility/context
    environment symbol catalog

AngelscriptRuntime/Cache/
    logical records and serializers
    source snapshot and invalidation planner
    pack/generation store
    engine lifecycle service
    settings, diagnostics, verification, compaction
```

`StaticJIT` may include the public artifact identity types. It may not own Cache manifests, pack I/O, source-authority decisions, or Cache generation publication.

Alternative rejected: keep the new cache under `StaticJIT/`. Editor/PIE/VM-only and first-launch compilation all need the cache when no Native provider exists.

### Every persisted entity uses a domain-separated BLAKE3-256 stable key

The shared public value types are:

```cpp
struct FAngelscriptHash256;
struct FAngelscriptStableModuleKey;
struct FAngelscriptStableTypeKey;
struct FAngelscriptStableFunctionKey;
struct FAngelscriptStableGlobalKey;
struct FAngelscriptStablePropertyKey;
struct FAngelscriptFunctionSourceDigest;
struct FAngelscriptFunctionInputDigest;
struct FAngelscriptFunctionContentHash;
struct FAngelscriptCacheCompatibilityKey;
struct FAngelscriptCacheContextKey;
struct FAngelscriptArtifactProfileKey;
struct FAngelscriptFunctionArtifactIdentity;
```

`FAngelscriptHash256` wraps the complete 32-byte `FBlake3Hash`. Each canonical stream begins with the ASCII bytes `UEAS-ARTIFACT` followed by one NUL byte, a fixed-width little-endian identity-schema version, and a distinct domain string. Integers/enums use explicit fixed widths; byte/string fields use `uint32 length + canonical UTF-8 bytes`; arrays are sorted by full key when semantic order is not meaningful.

Stable identity inputs are:

- module: logical source mount, normalized virtual path, explicit/derived module name;
- type: module key, namespace, type kind, canonical declaration/traits;
- function: module or owner type key, namespace, function kind, canonical declaration/traits;
- global: module key, namespace, name, canonical type/traits;
- property: owner type key, name, canonical type/traits.

Path normalization removes redundant separators and dot segments, uses `/`, and never writes absolute paths. Identifier and logical-path case is preserved because AngelScript identifiers are case-sensitive; source discovery rejects logical paths that collide under a case-insensitive comparison so a Windows cache cannot become ambiguous on another filesystem.

Line/column, registration order, map order, process pointers, FName comparison indexes, temporary FunctionIds, random values, and whole-module dependency hashes are forbidden identity inputs. A display `FGuid` is derived from the first 128 bits for UI/logging only. Persistence, equality, provider matching, and collision checks always compare all 256 bits plus canonical metadata when diagnosing a duplicate.

Alternative rejected: stabilize the old 32-bit FunctionId formula. Collision increments and synthetic random IDs cannot become a safe cross-process contract.

### Function lookup identity, compile input, compiled content, and debug mapping are separate

A function artifact has four coordinates:

```text
StableFunctionKey       logical declaration/owner
FunctionInputDigest     pre-compile body/options digest + persisted dependency fingerprints
ExecutionContentHash    canonical compiled bytecode/runtime state
DebugContentHash        source maps/line cues/debug-only state
ArtifactProfileKey      compatible compiler/target/context
```

The first cold compile cannot know exact semantic dependencies merely from `sFunctionDescription`: name/type/property/global resolution happens inside `asCCompiler`. The executable algorithm is therefore two-phase. Cold/miss compilation instruments compiler/bytecode capture to collect the actual stable dependency set and persists it in canonical order. A later lookup first compares a `FunctionSourceDigest` over the canonical token/AST slice, invocation kind and compile/preprocessor options. If it differs, the function is a miss without semantic pre-analysis. If it matches, the loader resolves the persisted dependency keys against the current declarations/environment and computes `FunctionInputDigest = H(FunctionSourceDigest, ordered current dependency fingerprints)`. This digest is available before choosing whether to invoke the compiler. A successful compile captures its new actual dependency set and recomputes the stored digest; no separate duplicate semantic compiler pass is introduced.

`FunctionContentHash` is computed after compile or validated restore. Its execution component covers canonical bytecode, operands/literals, stack/locals, exception cleanup, and stable symbolic references. Its debug component covers source mapping and line cues. A debug-enabled Editor profile matches both; a Shipping execution path may omit the debug sidecar while still validating execution content. An omitted sidecar is represented by an unset optional and the shared `FAngelscriptArtifactCanonicalWriter("function-debug-absent")` digest over exactly the full ProfileKey, never a zero RecordId/hash or empty-debug payload sentinel.

`FAngelscriptFunctionArtifactIdentity` is the shared StaticJIT-facing tuple of StableFunctionKey, FunctionContentHash, and ArtifactProfileKey. FunctionInputDigest remains Cache-private lookup state and is not required by a Native provider.

Body changes preserve `StableFunctionKey` but change input/content. Signature, owner, qualifiers, or function kind create a new stable key. Unrelated functions do not enter either digest.

### Compatibility, context, and bound-symbol dependencies are intentionally split

`CompatibilityKey` contains inputs that make the binary format or bytecode fundamentally unreadable/incompatible:

- Cache schema and canonical encoder versions;
- Unreal AngelScript product/compiler/fork bytecode ABI identifiers;
- UE major/minor ABI input required by serialized runtime data;
- platform, architecture, endianness, pointer width;
- bytecode/archive layout version.

`ContextKey` contains inputs that select a distinct valid compilation context:

- Editor/Game target and Development/Shipping configuration;
- effective AngelScript engine properties;
- preprocessor/compile settings;
- logical source mounts and source-provider configuration;
- debug-metadata policy.

`ArtifactProfileKey` is the domain-separated hash of Compatibility and Context keys and is shared with StaticJIT.

The complete binding surface is not included in those root keys. After binding initialization, a read-only `FAngelscriptEnvironmentSymbolCatalog` observes each visible bound type/function/global/property and records a stable environment-symbol key plus ABI fingerprint. Its layout side stores pre-materialization environment recipes and engine-owned CodeRoot/StructHeader coordinates actually consumed by the maintained compiler. Selected imported-module snapshots provide cross-module script layout authorities; the module currently being restored is deliberately absent from the required current lookup set. A graph validator exposes its already validated local TypeSchemas through a non-owning prospective layout view when an environment template recipe contains a local value subtype. Primitive and ObjectHandle slots come from versioned Compatibility/Profile constants. Thus the separate current-symbol/current-layout services can evaluate the eligible external/environment set before selected-module live script types exist. Capture occurs from engine-owned surfaces after `Binds.Cache`/normal binds and `BindScriptTypes` have sealed the environment catalog in both normal `Initialize` and `InitializeWithoutInitialCompile`; it never consults the process-global fallback type database. Cache records persist only the symbol and layout dependencies they actually use. An unrelated binding addition/change therefore does not invalidate every script artifact; a referenced symbol ABI/layout change invalidates its actual dependency closure.

Stable references distinguish declaration ABI from embedded content/value dependencies. `ScriptModule`, `ScriptType`, `ScriptFunction`, `ScriptGlobal`, `ScriptProperty`, `ScriptImport`, and `EnvironmentSymbol` references carry nonzero expected ABI fingerprints; `CanonicalName` and `StringLiteral` carry zero ABI and their canonical UTF-8 bytes in the owning payload. A normal `ScriptFunction` reference expects declaration/signature/traits/call ABI, not callee implementation content, so caller bytecode remains reusable after a body-only callee change. Constant folding, inlining, or another true content dependency is represented by a separate typed semantic dependency with an explicit content/hard-value fingerprint.

`Binds.Cache` remains independently loaded and is not copied into Cache V2. `FAngelscriptTypeDatabase` remains the live runtime adapter registry; the symbol catalog observes it and other public engine surfaces without serializing or replacing it.

Alternative rejected: put one full binding-surface digest in the profile. It turns any unrelated binding change into a full-cache miss.

The essential ownership split is:

1. `SourceIndex` owns stable mount/provider/hook/source-file/include keys,
   typed relative logical paths, raw content/preprocessor fingerprints,
   complete snapshot identity, and per-scope exact fast-path ineligibility.
   `SourceFile.ModuleKey` is the sole mapping wire authority; no global
   eligibility boolean or second source-to-module table is persisted. Host
   absolute roots are never persisted. All typed source references resolve
   locally with no dangling target. Graph references are validated in exact
   wire order Mount -> Hook -> File -> Input -> Edge -> Ineligible; reference-
   kind/target errors precede resolved-authority conflicts, and authority
   conflicts run only after all references resolve. Capabilities and same-scope
   missing reasons agree bidirectionally. The decoder builds mutable state only
   in a local factory scope, validates it, and builds its indexes. The
   Task 2B-1 `FAngelscriptValidatedSourceIndex` was a transitional public slice;
   Task 2B-2 removes that owning boundary and publishes SourceIndex only through
   the sole common `FAngelscriptDecodedCacheRecordHandle`, with no compatibility
   wrapper or duplicate charge. A common-record-only
   `QueryExactFastPathEligibility` first requires SourceIndex kind, takes explicit
   `Limits + Budget`, neither copies nor re-prepares the record, and returns
   exact canonical reasons from the module/file/mount/provider and transitive
   fixed-point Hook closure, leaving detached Hooks and unrelated modules
   eligible. This is set closure over a validated authority chain, not a hash
   fixed point: HookKey includes AffectedScopeStableKey, so a valid self/multi-
   Hook cycle would require an infeasible BLAKE3 fixed point. Producers build
   keys outward from non-Hook scopes; forged cycles fail existing
   `DerivedHashMismatch` before eligibility, without a new cycle error or
   graph-hashing algorithm. Six public identity-only typed source-key builders
   are the only hash implementations; they fail closed and leave zero output
   so Task 4 cannot fork encoder-private domains.
2. `ModuleInterface` owns reconstructible canonical namespaces, declarations,
   signatures, imports, slots, reflection surface and typed semantic dependency
   targets. Hash-only declaration summaries are insufficient for a zero-parse
   restore. Imports have one authority outside declarations; declaration sets
   and per-kind slot ordinals are independent. Each declaration also stores
   explicit Required/Forbidden TypeSchema and FunctionBody coverage. V1 has no
   inferred or Optional coverage: required keyed child sets must match exactly,
   and a producer unable to capture a required body marks the complete snapshot
   NotCacheable. Its local owner graph follows an explicit callable matrix,
   resolves Type/Global owners inside the same interface, restricts ordinary
   Method to Class/Struct/Interface and Property to Class/Struct, admits only
   the explicitly Generated-trait-gated Delegate member exception, and
   restricts DelegateSignature to Delegate/Funcdef. Pure decode validates Global/Property
   type-spelling and DeclaredType shape/hash participation; producer and later
   resolved type authority, not a text parser in 2B-1, guarantee equality.
3. `TypeSchema` owns explicit class/struct/interface/enum/delegate/typedef/
   funcdef declaration, inheritance, properties, distinct public-method and VFT
   sequences, behavior slots, metadata, reflection and layout values. Every
   local property carries hash-bound storage kind/size/alignment, while canonical
   BaseType, UClass CodeRoot, and UStruct StructHeader LayoutInputs persist the
   numeric boundary/alignment contributions needed to replay `LayoutClass`
   without a live engine. A UStruct header contributes boundary only; every
   ordinary UClass retains code-root shadow alignment even when a Script Base
   supplies the cursor boundary. A standalone Typedef descriptor keeps primitive
   alias size/alignment `4`, property use expands to the primitive datatype, and
   Funcdef keeps descriptor `{size=0, alignment=4}` but is NotCacheable as V1
   property storage.
   ModuleInterface remains the sole type-identity authority. Direct implemented
   interface order is stored; its transitive closure is derived base-first with
   first-visit diamond deduplication. TypeSchema is the authority for ordered
   signed-int32 enum name/value/metadata; ModuleState stores only a validated
   derived hard-value fingerprint. Constructors/factories use behavior-slot
   sequences. Reflection explicitly stores ordered UFunction membership for
   ordinary classes and StaticsClass globals, including a target whose
   ReflectionFlags mask is zero, but does not duplicate relations, metadata or
   executable default bodies. Ordinary UClass uses optional ConfigName plus
   required StaticClassGlobalName; synthetic StaticsClass and non-UClass forms
   forbid both, with the StaticsClass flag enforced as a two-way discriminator.
4. `ModuleState` owns explicit global/storage/constant descriptors, canonical
   stable-keyed VM-private initializer units, one dependency-solved
   OrderedInitializationActions sequence that interleaves type-driven default
   construction with VM initializer execution, ordered post-init functions,
   hard-value dependencies, ProfileKey and per-global cleanup policy. Units are
   embedded in ModuleState, not independently linked FunctionBody records.
   There is no opaque ModuleLifetime field or persisted initialized bit: load
   allocates/zeros storage, installs pure constants, executes the exact action
   order, then post-init, publishes atomically, and rolls back/releases by a
   transient stack in reverse action-attempt order.
5. `FunctionBody` owns stable identity/input, invocation kind, expected
   declaration ABI, actual dependencies, a versioned VM-private execution
   payload and its sole optional DebugSidecar link. Invocation-to-declaration
   mapping is explicit; generated default destructor reuses Task 1
   `EntityKind::Destructor=35` plus the Generated declaration trait rather than
   adding or renumbering shared identity values.
6. `DebugSidecar` owns a ProfileKey, versioned VM-private debug payload, typed
   SourceFileKey/logical-section coordinates and the matching debug content
   coordinate. Debug absence is the shared identity-layer
   `function-debug-absent` hash over the full profile, never a sentinel.

Only VM execution, initializer and debug payload bytes are opaque to the common
archive, and each has its own codec version. An injected opaque-payload
validator returns only a validated payload hash, full-coordinate relocation
summary, exact debug sources and owned name/string bytes; common graph code
never parses the bytes. The five record deserializers perform wire/local/hash
validation only. One immutable token factory recomputes RecordId from canonical
payload, dispatches all seven decoders and captures trusted nested field
offsets; SourceIndex and graph records are these const tokens, not mutable DTO+
bytes aggregates. Graph step 1 calls the codec exactly once only for reachable
ModuleState initializers in Execute-action order, then bodies and body-owned
sidecars in the frozen link order, fails fast, and retains summaries in the
validated graph; Debug opaque V1 has no relocations. Canonical data types,
declarations, type/property/global/reflection descriptors, dependencies, and
links remain explicit so malformed order, ownership, duplicates, ABI and
budgets can be checked without a live engine.

Remaining-record tokens are factory-created thread-safe shared const handles.
Each token/control/DTO allocation is charged exactly once at decode; retaining a
handle never deep-copies or recharges it. A validated module graph retains only
the reachable handles and publishes compact ordinal-based RecordId, type,
global, function, initializer, and opaque-owner tables plus graph-owned opaque
summaries. Validation maps are temporary. Candidate output allocations consume
monotonic total-decoded budget and live scratch before allocation; step 11
atomically promotes the same resident bytes rather than double charging them.
Late failure releases candidate scratch and leaves no partial output, caller
input destruction cannot invalidate a success, and unrelated tokens are not
retained.

`ModuleSnapshot` uses keyed links: exactly one `{ModuleKey,
ModuleInterfaceRecordId}`, ordered `{TypeKey, TypeSchemaRecordId}` entries, one
`{ModuleKey, ModuleStateRecordId}` even for empty state, and ordered
`{FunctionKey, FunctionBodyRecordId}` entries. The generation manifest names
exactly one SourceIndex and keyed `{ModuleKey, ModuleSnapshotRecordId}` roots.
Its record index is the exact transitive reachable set, including sidecars;
historical records may remain in packs but are not injected into a new
manifest.

Types and functions may be persistently reused independently, but no partial
combination mutates the active engine. Restore validates entity ownership,
declaration coverage, link kinds, source/profile/ABI, imports, globals and
ClassGenerator constraints before atomically activating the module.
Task 2B-2 exposes only per-module `ValidateModuleSnapshotGraph`; exact manifest
reachability and unrelated-record rejection remain Task 2B-3. Local integrity
and immutable graph contradictions—including linked same-module Base/inline-
value numeric layout disagreements—precede current source/profile/symbol/layout
eligibility, so corrupt graph state cannot be reclassified as a normal miss.
Legal cross-module/environment single witnesses are compared only after graph
success through a required per-engine current-layout resolver; that resolver
never contributes to a stored hash or consults a process-global type database.
Selected-module Script* dependencies, same-module Base/inline-value layouts,
primitive slots, and ObjectHandle slots are graph/profile closed and make zero
current calls; a missing required local child is graph corruption rather than an
external lookup fallback. Eligible cross-module/environment coordinates are
memoized by stable identity. The resolver returns raw role coordinates; each
TypeSchema's locally validated stored presence mask selects only the boundary/
alignment values that the maintained producer consumed, so a derived UClass
ignores the raw CodeRoot boundary while still comparing shadow alignment. An
environment recipe may read the allocation-free prospective local layout view,
but it cannot query the selected module's live AS types. TypeSchema decoding
first exhausts physical bytes, then validates field-local semantics in exact
top-level wire order, then cross-field pairing/coverage/layout replay; the final
TypeLayoutHash is checked only after LayoutInput, property, and enum hashes.
The validator and opaque seam both receive `const FAngelscriptCacheReadLimits&`
with the same monotonic caller budget. The envelope adds a budget overload while
retaining its existing convenience overload. Full-key indexes and canonical
adjacent checks prohibit nested whole-pool scans; null context, wrong SourceIndex
token, and zero selected/root coordinates fail before codec/resolver work.

### Logical segmentation does not create one file per entity

The physical store is:

```text
Saved/Angelscript/CacheV2/<CompatibilityKey>/<ContextKey>/
    Current.ascurrent
    Previous.ascurrent
    PendingColdStart.ascurrent
    Generations/<GenerationId>.asmanifest
    Packs/<PackId>.aspack
```

Manifests map full content hashes to `PackId + offset + stored size + raw size + codec + checksum`. Packs contain many logical records in canonical order. The default writer targets 64 MiB of uncompressed payload per pack; an oversized record receives its own pack. Pack size is writer policy, not a semantic compatibility input.

The manifest magic/schema are `UEASCV2M`/1. Its fixed root fields are followed
by 65-byte `{ModuleKey, ModuleSnapshotRecordId}` entries and 122-byte record
locations; RecordId itself is exactly 33 bytes. The pack magic/schema are
`UEASCV2P`/1 with a 32-byte header and 96-byte canonical index entries. A pack
stores semantic payload bytes, never nested record envelopes (a 56-byte header
plus payload).

`RecordId` remains the domain-separated hash of record kind plus canonical
uncompressed semantic payload. `RawChecksum` is direct BLAKE3 over exactly that
payload. `PackId` hashes every byte of the complete final pack and is not stored
inside it; `GenerationId` similarly hashes every byte of the complete final
manifest and is not self-serialized. V1 codecs are per-record `None` and
canonical `Zlib`; `None` is always valid, while production `Auto` uses
`NAME_Zlib`, `COMPRESS_BiasMemory`, window 15 and accepts Zlib only when smaller.
Readers recompress and require byte equality so alternate/trailing Zlib streams
do not become a second valid physical representation in one compatibility
namespace.

The manifest index is exactly the records reachable from its one SourceIndex
and keyed ModuleSnapshot roots. A pack may retain historical extra entries,
but a manifest may not name an unreachable extra. The writer and decoder both
enforce at most 4,096 distinct PackIds per generation; the decoder rejects an
excess with `BudgetExceeded` before pack lookup/open. Archive stages `7..9` and
errors `65..71` describe only pack/manifest format and integrity.

New generations write only missing content-addressed records. Unchanged records continue to reference existing packs. This avoids filesystem explosion while retaining entity-granular reuse. Startup never rewrites packs merely to remove unreachable data.

### Source snapshot, module parsing, and function compilation form a two-level fast path

Startup and reload follow this fixed flow:

1. Discover `DirectSourceInputs` for every configured source kind (`Game`, `Plugin`, `Memory`): typed mount/provider/hook/file coordinates, provider identity/version/configuration/capability, development/editor filters, typed relative logical path, raw loose/memory/generated bytes, full raw-byte hash, explicit compile/preprocessor options, preprocess-hook fingerprint and owning ModuleKey. Generated/External are provider kinds, not source kinds. Reject absolute/escaping/NUL paths, strict-UTF-8 errors and simple-fold case collisions before lookup. A hook/provider without a stable fingerprint marks only its affected scope ineligible.
2. Canonically hash those directly discoverable inputs, read the `Current` SourceIndex and compare its direct-input digest before validating its single-current historical candidate. The candidate owns the include/generated edges, effective conditional inputs and other preprocess-derived fingerprints captured by the last successful preprocess; startup does not rerun the preprocessor merely to reconstruct that graph. V1 introduces no separate action-index database or candidate-history file.
3. Validate every candidate dependency against current raw/provider/option state. A missing, unhashable, corrupt or mismatching candidate is a normal miss and enters the authoritative changed-module path. Candidate history is disposable optimization state, never an unbounded dependency database or source authority.
4. On an exact source/profile/environment/candidate match, validate every selected
   ModuleSnapshot, prepare every admitted VM module/descriptor/stable route outside
   the active Engine maps, then run one complete-batch ClassGenerator setup and one
   `SwapInModules`/reload/route publication. A preparation/finalization failure
   discards every staging module, reports zero restored modules and permits the
   authoritative normal-compile fallback; it never leaves an early module active.
   Only the complete successful batch adopts restored Current provenance. The
   unchanged path skips preprocess, parse and compile.
5. Otherwise preprocess and parse only the affected source/module closure through the existing authoritative frontend and HotReload dependency ownership.
6. Build/validate ModuleInterface, TypeSchema, environment authority and the declarations required before any function reuse decision. Source scanning does not guess whether text represents a body, class, layout, global or signature change.
7. For a candidate whose `FunctionSourceDigest` matches, resolve its persisted actual dependency set in the current engine and calculate `FunctionInputDigest` immediately before that builder invocation's compiler decision:
   - hit: resolve stable references and attach the validated FunctionBody;
   - miss: compile normally and capture a new FunctionBody afterward.
8. Complete ModuleState, imports, dependency diff, module swap, ClassGenerator/reflection, and target-specific reload policy.
9. Only a successful transaction may prepare/publish a generation, reusing equal semantic RecordIds regardless of their physical Pack placement.

Formatting/comment-only changes can require module reparse and DebugSidecar update while execution FunctionBodies remain hits. A complete unchanged snapshot is the only path that promises zero preprocess/parse work.

The implementation also exposes a forced-clean compile mode that bypasses function
lookup while producing the same canonical artifacts. It is the fallback for any
unsupported/unstable invocation and the clean-vs-cached equivalence oracle. It does
not weaken the completed V1 requirement that supported changed modules obtain real
per-invocation compiler hits.

### Typed invalidation decides the minimum correct closure

The planner applies these rules:

| Change | Required invalidation |
|---|---|
| comments/whitespace/source-line movement | SourceIndex and DebugSidecar; execution body may hit |
| one function body | that FunctionBody only, unless actual dependency digest changes |
| function signature/owner/trait/add/delete | ModuleInterface, old/new function key, referring callers/importers |
| class/property/inheritance/metadata/interface/delegate/enum layout | TypeSchema, owning ModuleSnapshot, structural dependency closure |
| global/constant/enum value/global initializer | complete owning ModuleState and hard-value dependency closure |
| include/preprocessor input | affected SourceIndex/module closure, then entity comparison |
| referenced environment symbol ABI | records that name that symbol and their semantic closure |
| unrelated binding change | no invalidation |
| compiler/bytecode/platform incompatibility | different Compatibility namespace |
| Editor/Game/config/source-mount context change | different Context namespace |
| rename/delete | new/unreachable stable key; reclaim only by explicit compaction |

Caller bytecode does not miss merely because a callee implementation body changed if the call is expressed through the same stable declaration route: its `ScriptFunction.ExpectedAbi` is declaration/call ABI. A compiler transformation that embeds ordinary callee content records the append-only `FunctionContent` dependency kind with the exact execution hash; a constant remains `HardValue`. The names are not interchangeable. The StaticJIT sibling change separately guarantees that Native callers do not embed stale content-specific routes.

Default-expression presence and canonical bytes are caller-visible V1
declaration semantics and therefore enter SignatureHash and InterfaceAbi. If
the compiler resolves and embeds their value, Task 4 additionally captures a
HardValue dependency. InterfaceAbi excludes ExpectedContentOrValue and includes
only ABI-bearing dependency kinds; the full ModuleInterface RecordId still
covers every dependency field.

### The maintained AngelScript fork is an explicit Cache V2 implementation surface

All code under `Plugins/Angelscript` is in scope for this change when needed for
correctness, including the maintained AngelScript fork's builder, compiler,
bytecode, module/function runtime representation, VM and restore code. The
implementation MUST prefer the smallest coherent maintained-fork seam, keep it
Unreal-free where it belongs to the generic fork, and cover it with focused tests,
but it MUST NOT duplicate compilation or accept incomplete VM state merely to
avoid changing AngelScript internals. Existing project `.as` files are not edited
to simulate a cache hit, and no language-syntax change is currently required.
“Maintained-fork seam” includes permission to introduce or revise internal AS
interfaces, state representation, compiler/bytecode integration, serialization
and complete VM restoration behavior; existing lower-level interfaces are not a
fixed architectural boundary for this change. Once implementation evidence shows
that such a lower-level change is needed, no separate scope exception or renewed
authorization is required: record the rationale, compatibility impact, focused
RED/GREEN coverage and verification evidence progressively in this OpenSpec, then
make the smallest coherent change anywhere under `Plugins/Angelscript`.

The currently selected maintained-fork extension is one kind-tagged cache hook
and one complete VM adapter:

Add an internal, host-supplied function artifact hook to every builder compile family: the normal/generated `CompileFunctions()` loop, the separate factory loop, and the public single-function `CompileFunction()` path including lambdas it generates. `sFunctionDescription` alone cannot describe factories and all synthetic/generated callables, so the fork owns an Unreal-free, kind-tagged `asSBuildArtifactInvocation` descriptor. Its kind covers regular function, factory, default constructor, default destructor, `__InitDefaults`, public single-function and lambda compilation; the payload carries canonical owner/module/namespace, source/token/node identity, declaration and the generated traits/context needed to reproduce the invocation.

```cpp
enum class asEBuildArtifactLookupResult
{
	Miss,
	Restored,
	RejectedCorrupt,
	NotCacheable,
};
```

On `Restored`, the builder skips only that invocation's `asCCompiler` work after a VM-private adapter has validated and rebuilt the complete `asCScriptFunction` runtime state. This includes instruction-level operand relocation, `scriptData`, stack/local object metadata, try/catch and cleanup state, line/section/debug metadata, and every function/type/global/property/import/name/string reference. Raw bytecode attachment is forbidden. The common archive sees only versioned execution/initializer/debug codec bytes; it still serializes every declaration/type/global/dependency/link field explicitly. On `Miss` the authoritative compiler runs normally; the host captures the compiled artifact only after success. `NotCacheable` explicitly bypasses both lookup persistence and capture for public snippets/debug expressions/lambdas that lack stable module coordinates. A rejected record is diagnosed and treated as a miss before active module publication.

The same fixture can force every invocation down the authoritative compile branch.
Tests compare that result with selective restored mode at the semantic-record,
private VM-state and observable execution levels. Cached attachment never becomes
the oracle for its own correctness.

The hook and VM adapter are installed per builder/engine compilation transaction. They have no process-global state and no Unreal dependency in AngelScript's generic interfaces. All enumerated invocation kinds pass through the same contract. `CompileGlobalVariables()` remains governed by ModuleState and is not routed through this hook in V1; stable global/module initializer units are encoded only inside the atomic ModuleState payload.

Alternative rejected: perform a second compilation pipeline outside `asCBuilder`. It would duplicate declaration/layout/global semantics and drift from the authoritative fork.

### Immutable generations provide atomic recovery and multi-process safety

Generation publication performs:

1. inside the engine mutation gate, after final compile result, module swap and ClassGenerator/reinstancing have succeeded but before temporary compiled objects/descriptors are released or moved, `FreezeSuccessfulCompileArtifacts()` deep-copies one immutable transaction DTO: run identity/type/result, profile/context/source-index record, Current versus Pending disposition, stable module keys, module interfaces, type schemas, module state, canonical function execution/debug payloads, ordered actual dependency/environment fingerprints, and no AS/UE pointer or mutable descriptor; workers may never reread mutable module descriptors;
2. build keyed ModuleSnapshot roots and the exact reachable record set, then prepare hashes/compression/pack indexes on bounded workers;
3. acquire a `FSystemWideCriticalSection` derived from the normalized store path;
4. reread `Current` and rebase content-address references if another writer published;
5. write same-volume temporary pack files, flush/close, and validate them;
6. write/validate `Generations/<GenerationId>.asmanifest.tmp`;
7. rename immutable packs and manifest to final names;
8. atomically replace `Previous` and then `Current` pointers;
9. release the writer lock.

The default base root is exactly
`<ProjectSavedDir>/Angelscript/CacheV2`; `-as-cache-root` replaces that complete
base before the lower-case full-hash compatibility/context namespace is
appended. Final pack/manifest names are their full hash. Each pointer is an
exact 80-byte `UEASCV2C` schema-1 file carrying kind, nonzero GenerationId and
BLAKE3 checksum. Pointer schema is a CompatibilityKey input.

All temporary files have a frozen same-directory `.tmp.<pid>-<128-bit-nonce>`
name. Immutable installation is full-write/flush/close/reopen-validate,
no-replace rename, directory sync and final reopen validation. Pointer commits
use an explicit platform old-or-new atomic install/replace seam; a generic
delete-then-move implementation is unsupported. Store-path/lock/open/write/
flush/rename/cancel/commit outcomes use `EAngelscriptCacheStoreError 0..21`
and may nest an archive validation result, but never manufacture archive error
numbers.

Readers open one immutable generation and pin its manifest handle and every
distinct referenced pack handle under the namespace lock, then retain those
handles for the read session. They never follow a moving Current pointer or
reopen a selected pack by path mid-restore. The session counts distinct packs
against `MaxGenerationPacks` before any pack handle is opened. A failed write,
cancellation, process crash, or shutdown timeout removes only the writer's
known temporary files and leaves committed pointers intact.

The service retains Current and Previous manifests plus every pack they reference. `PendingColdStart` is retained separately for an Editor PIE structural compile that is valid for a fresh engine but not active in the current PIE session. A `PartiallyHandled` PIE result freezes two semantically distinct DTOs when applicable: one describing the actually active Current modules, and one source-correct cold-start candidate; they are never conflated. `CompileEnd` is diagnostic-only and is never used by a worker to recapture mutable objects. Explicit compaction publishes a new generation containing only currently reachable records; compaction never runs on startup.

Rebase rereads Current/Previous/Pending while holding the canonical-namespace
system-wide lock. Same-source/same-semantic work becomes `AlreadyCurrent`;
same-source/different-semantic work is `RebaseSemanticConflict`; a changed
source requires caller revalidation. Current replacement success is the commit
point, so cancellation or directory-sync failure afterward cannot roll it
back. Candidate order is Current, Previous, then cold-eligible
PendingColdStart. Each must independently match current source/profile and use
its pinned files. A corrupt or ineligible candidate never authorizes
different-source stale execution; otherwise source compiles.

Physical retention treats every presently valid Current, Previous and Pending
pointer as a root even when a slot is not currently selection-eligible.
Compaction is explicit, never startup work: Phase A rebuilds the reachable
union and atomically switches rewritten slot pointers without deleting old
immutable files; Phase B reacquires the lock, remarks current physical roots,
and sweeps only unmarked strict-name finals, deferring deletion when a pinned
reader prevents it. A cache read/write failure does not invalidate already
active modules. A source compilation failure remains authoritative and does
not authorize stale cache fallback.

### Parallelism is limited to pure preparation and each engine has one mutation gate

Bounded tasks may perform:

- source discovery and raw hashing;
- manifest/pack reading, checksum, bounds and canonical-order validation;
- decompression and pure record validation;
- source/module hit planning and FunctionInputDigest preparation;
- post-compile canonicalization, compression, pack construction, and diagnostics aggregation.

The following remain serialized on the owning engine/game-thread safe point:

- declaration/type/layout creation;
- stable-reference attachment into current engine objects;
- global storage/initializer processing;
- module swap and dependency publication;
- ClassGenerator/reflection/reinstancing;
- Current/Pending generation selection and active-route handoff.

`FAngelscriptEngine` owns an explicit reentrancy-defined compile/cache transaction gate covering startup restore/attach, hook install/uninstall, declarations/layout/globals, module swap/ClassGenerator handoff, stable route rebuild, runtime reload, Current/Pending selection, StaticJIT route refresh and shutdown/cancellation. The gate records the initializing owner thread during any-thread startup and transitions to game-thread safe-point ownership for runtime operations; nested calls are allowed only through an explicit owner token and lock order is engine gate before store-writer lock. The existing compilation lock used for diagnostics is not treated as a correctness mutex. Only the already established parse-only parallel region and pure immutable preparation may run concurrently; cache workers cannot call AS engine APIs or read mutable descriptors.

Forced-serial and normal bounded-parallel modes must emit byte-identical manifests and pack bytes. Worker completion order never selects output order. Multiple engines may share immutable file bytes but own separate gates, stable-key-to-FunctionId maps, modules, cancellation, counters, and reload state.

### Editor, PIE, packaged runtime, and shutdown use one Runtime service

`FAngelscriptCacheService` is owned by each `FAngelscriptEngine`. `AngelscriptEditor` supplies existing file-watcher/reinstancing triggers but does not own another cache implementation.

Editor policy:

- initial compile and every successfully activated hot reload schedule asynchronous generation preparation;
- body-only reload may publish Current immediately after the existing successful soft swap;
- full structural reload outside PIE publishes only after ClassGenerator/reinstancing succeeds;
- structural compilation during PIE keeps Current aligned with the active engine and may publish only `PendingColdStart`;
- after PIE ends and full reload succeeds, PendingColdStart may be promoted/replaced by a normal Current generation;
- failed compile/ClassGenerator leaves active modules and Current unchanged.

Shutdown policy:

- `FAngelscriptEngine::Shutdown()` calls Cache service shutdown before releasing AS engine state;
- flush waits at most `ShutdownFlushTimeoutSeconds`, default 5.0 seconds;
- shutdown does not discover, preprocess, or compile unprocessed source;
- timeout cancels known preparation, removes known temp files, and preserves the previous committed generation.

Fresh-start source failure:

- cache may only be selected after raw source snapshot equality;
- if current loose source differs and fails compilation, no older different-source generation is activated;
- packaged executable exits with failure/nonzero initialization status;
- Editor reports an explicit script-initialization failure state and does not activate stale scripts.

### Cache bytes are untrusted until fully validated

Before allocation or engine mutation, validate:

- envelope, per-record payload and VM codec versions, compatibility/context/
  profile/source coordinates;
- integer arithmetic, tags/enums/booleans, counts, offsets, raw/stored sizes,
  codec and exact decompression output;
- record/pack/manifest BLAKE3 identities;
- strict UTF-8 without embedded NUL, typed logical paths, exact stored bytes,
  and `FTextChar::GetCodepoint` plus one `FTextChar::ToLower` mapping per
  Unicode scalar value for collision checks without identity folding;
- set order, semantic ordinals, duplicate/conflicting full keys;
- stable-key/ExpectedAbi zero rules, typed dependency existence and keyed
  record-kind/entity/module ownership;
- full-coordinate relocation subset, exact enum/global/initializer coverage,
  sole DebugSidecar ownership, profile-specific debug-absent and debug-source
  invariants;
- per-module graph self-consistency before current source/profile/ABI/content
  eligibility, followed separately by Task 2B-3 manifest reachability; and
- configurable per-field/per-record plus read-session cumulative stored,
  decompressed and resident-memory budgets. Retained decoded state plus all
  simultaneously live semantic/index/query scratch must stay within the
  resident limit. Every scratch `Reserve`, `SetNum*`, index or queue allocation
  is preceded by checked reservation and a move-only RAII guard releases only
  temporary scratch on every exit; failed reservation changes no counter and
  allocates nothing. Persistent consumed counters remain monotonic.

Validation results distinguish malformed format, arithmetic/budget,
codec/integrity, canonical semantic, graph/ownership, and normal eligibility
mismatches. Compatibility/context/profile/source/current-ABI mismatch is a
typed cache miss, not corrupt-file evidence. A malformed manifest/index/pack
rejects its generation; a bad required record rejects the complete
ModuleSnapshot and schedules its safe compile closure. Never deserialize native
pointers, vtables, UObjects, function addresses, FName indexes, or
process-local IDs. Cache files are a performance artifact, never more
authoritative than matching loose source.

For V1 one exhaustive `Classify(Error)` is the only ValidationClass authority;
the result also carries RecordKind, validation stage and ByteOffset while
retaining Task 2A/2B-1 error numbers `0..43` and appending only the frozen
2B-2 values `44..64`. Entering a SourceIndex or ModuleInterface codec establishes
the record kind immediately: decoder semantic failures report the enclosing
field's captured payload offset, serializer semantic failures report offset
zero, and a record-boundary wrapper fills only genuinely nested zero-kind
results. One caller-owned read budget is passed through every envelope/token/
child decode, graph-index/resident allocation, eligibility query and opaque-
codec summary with the same read limits; no child resets it. Its persistent
consumed counters remain monotonic while live scratch reservations are released
by RAII and never refund persistent consumption. The old three-argument result
constructor keeps its third parameter as ByteOffset and new staged failures use
a named factory. Derived-hash or immutable graph inconsistency is malformed/
graph data, while comparison of an internally valid record with current
source, profile, ABI, content or symbol existence is an ineligible miss.

### Testability is a guarded observation surface, not a second cache path

Cache V2 deliberately exposes narrow test seams because allocation chronology,
candidate rollback, graph ordering, crash recovery and concurrent publication
cannot be proved from final output alone. These seams SHALL observe or interrupt
the same production encoder, decoder, store and lifecycle paths; they SHALL NOT
provide a test-only serializer/decoder, alternate ownership model or relaxed
validation route.

Runtime-local wire traces, allocation events, validation checkpoints, controller
measurements and deterministic fault injection compile only under
`WITH_ANGELSCRIPT_UNITTESTS` or remain in Private/Test code. Event capture uses
caller-owned fixed-capacity views with an explicit overflow bit and performs no
allocation while observing an allocation-sensitive operation. Hooks are either
explicit synchronous per-call views or, only where a scope is unavoidable,
thread-affine and non-nestable; they are inactive by default, do not use process-
global mutable state, do not survive into a decoded handle or asynchronous
publication object, and disappear from non-test builds.

Injected failures use a private test outcome/checkpoint contract rather than
adding values to the frozen public validation or store error enums. Platform
faults are exercised through the same narrow file, lock, clock, cancellation,
compression and executor capability interfaces used by production. Resolver,
opaque-payload and scheduler spies may count and order calls, but cannot supply
authority unavailable to the corresponding production interface.

The test matrix favors exhaustive wire enums/flags/field identities plus
deterministic equivalence classes for allocator occurrences: empty, one,
allocator-slack and many cardinalities; first, middle, last and nested
representatives; exact-limit and one-byte-short runs; and one complete chronology
per fixture. It SHALL NOT re-decode a complete fixture once per equivalent event
when a representative case proves the same boundary, because that creates
quadratic test time without increasing semantic coverage. Large concerns are
split across wire, physical decode, local semantics, budget/ownership, graph,
store and lifecycle test translation units while sharing immutable fixture
builders and an independent raw-wire scanner.

The preferred special-support boundary is a narrow test adapter over production
interfaces, not a broadly exported mock API. Pure codecs expose synchronous
caller-owned capture views. Candidate/factory code exposes private checkpoints and
fixed chronology only while the real transaction executes. Store and lifecycle code
receive the same platform-file, lock, clock, cancellation and executor capabilities
used in production; test implementations can fail or delay an operation and record
ordering, but cannot skip validation or install a pointer directly. Resolver and
compiler spies return only data that their production interfaces are already
authorized to provide. A test façade may be a friend in Runtime Private or live in
the Test module, is guarded by `WITH_ANGELSCRIPT_UNITTESTS`, and owns no persistent
Runtime state.

Engine-backed tests compose these boundaries around a real test engine. Runtime
defines one `FAngelscriptCacheServiceDependencies` aggregate containing the
store/platform, current-symbol/layout, compiler/attachment, Native-provider,
clock/cancellation and executor capabilities; production constructs its defaults,
while `FAngelscriptEngineDependencies` may carry an explicit aggregate/factory for
one engine. The Test module's `FAngelscriptCacheTestEngineFixture` supplies
in-memory/spying implementations and owns or resolves the real engine plus its
scope. It delegates acquisition to the existing shared module-clean Full-engine
pool, fresh `CreateFullTestEngine`, or production-like resolver. It neither
subclasses the `USTRUCT` `FAngelscriptEngine` nor restores the removed clone-engine
model. Cache/controller state remains per engine, so two fixtures mechanically
prove isolation instead of sharing an ambient service.

Every such seam has its own integrity matrix: observer absent versus present must
produce identical bytes/result/Budget/publication; zero, undersized and exact capture
capacity must be safe and report overflow explicitly; two callers and relevant
threads must not cross-route events; failed checkpoints must unwind candidate/live
state; and non-test/Shipping compilation must contain neither the adapter symbol nor
observer storage. This lets unit tests cover rollback, crash windows and concurrency
aggressively without changing the architecture being tested.

## Risks / Trade-offs

- **Canonical input omits a semantic dependency** -> domain/version every encoder, persist actual dependency keys/fingerprints, add mutation-matrix and warm-vs-cold parity tests.
- **Function reuse hook attaches incomplete VM state** -> use the maintained-fork VM adapter after declarations exist; relocate every instruction/reference and rebuild script/stack/local/debug metadata; retain module-atomic transaction and rollback.
- **Type/global segmentation is too aggressive** -> keep ModuleState atomic, widen typed dependency closure, and prefer safe misses over speculative hits.
- **Parallel hashing/packing becomes nondeterministic** -> canonical full-key sorting and serial/parallel byte equality tests.
- **Loose Shipping source exposes implementation and permits modification** -> this is an explicit product decision; source remains authoritative and invalid edits fail closed.
- **First Shipping launch has visible compile cost** -> exact warm fast path, parallel source hashing, function reuse, structured timing, and benchmark evidence.
- **Immutable packs grow over time** -> retain only Current/Previous/Pending references and provide explicit or background-idle compaction, never startup compaction.
- **Concurrent processes publish competing generations** -> system-wide store lock, Current reread/rebase, immutable content addressing, atomic pointer replace.
- **Editor PIE structure compile diverges from active classes** -> write only PendingColdStart until a cold/full ClassGenerator transaction validates and promotes it.
- **Old package/tool assumptions break immediately** -> remove old generator/staging/tests/docs in the same implementation series; no dual format is supported.

## Migration Plan

1. Preserve the accepted stable identity, wire, archive and safety authorities while completing one representative clean-compiled module as a full in-memory record/factory/graph transaction.
2. Implement deterministic Pack/Manifest and the narrow immutable Store early enough to publish and reopen one real cold generation; pure data-plane work does not wait for every unrelated negative TypeSchema matrix, but activation still requires complete selected-record validation.
3. Separate direct source/action inputs from bounded persisted preprocess-derived dependency candidates and prove an unchanged second launch restores with zero preprocess, parse and function-compiler calls.
4. Route changed source through the existing authoritative frontend, force a full clean compile, compare semantic RecordIds and incrementally publish only new content. This becomes the fallback and clean-vs-cached oracle.
5. Add the kind-tagged maintained-fork builder hook, actual-dependency capture, `FunctionInputDigest` selection and private VM adapter; prove real per-invocation hits and equality with the forced-clean result.
6. Integrate Editor/PIE/runtime lifecycle, asynchronous publish, shutdown flush, public settings/diagnostics and StaticJIT route isolation.
7. After V2 parity, switch packaging to loose NonUFS source and remove the old precompile pre-step and every production `PrecompiledScript.Cache`/`DataGuid` path.
8. Run focused/unit/integration tests, then real PIE, then real Development and Shipping package/multi-launch matrices; capture 4/16/64 MiB Pack and cold/warm/edit benchmarks and update Chinese documentation before English documentation.

During development, rollback means reverting the source revision and deleting/rebuilding Cache V2 under Saved. There is no runtime downgrade, old-cache reader, or migration tool.
