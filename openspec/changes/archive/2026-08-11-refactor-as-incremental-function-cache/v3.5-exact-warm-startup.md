# V3.5 exact warm-start packet

Date: 2026-08-10 (Asia/Shanghai)

## Outcome and boundary

V3.5 is complete only when a physical cold generation produced by Engine A is
selected by an independently initialized Engine B after authoritative current
source discovery, restored as a normal `FAngelscriptEngine` module, and executes
without invoking the preprocessor, parser, module code compiler or function
compiler for the selected module. The warm read must not prepare or publish a
second generation and must leave the physical Store unchanged.

This is the production exact-startup coordinator seam that V6 will invoke from
the full Editor/PIE/runtime lifecycle. V3.5 does not enable Cache V2 globally for
arbitrary project modules while the admitted restore shape is still one enum and
one self-contained primitive global function. A supported-shape miss remains a
normal request for the authoritative compile path.

## New Engine state contract

The old Engine is never cloned and no live pointer crosses the generation
boundary. Engine B is assembled from two sources of authority:

```text
Engine B normal initialization
  native/manual/generated binds
  engine properties and namespaces
  BindState / BindDatabase / TypeDatabase
  current native addresses, type ids and context/JIT services
                 |
                 v
current source discovery ---- exact comparison ---- pinned Cache V2 generation
  current absolute paths       profile                 semantic records
  current raw bytes/hashes      direct digest           VM execution/debug data
  current provider/mounts       dependency candidate    stable artifact keys
                 \                 |                  /
                  `------ exact-start transaction ----'
                                  |
                                  v
                      reconstructed script projection
                        live asCModule/functions/types
                        current numeric FunctionIds
                        FAngelscriptModuleDesc indexes
                        current source/watch coordinates
                        stable function route table
```

The normal-initialization side is process-local and is never serialized. Cache
V2 persists pointer-free script facts. The coordinator rebuilds the plugin-owned
middle layer (`FAngelscriptModuleDesc`, active module/type indexes and stable
routes) from those facts and the current discovery projection. A VM-only module
is not a successful warm start.

## Authoritative current-source projection

`DiscoverProductionSources` already reads the exact current bytes used for the
direct digest. It must also retain a bounded transient projection for this
startup attempt:

```text
SourceFileKey / ModuleKey
VirtualPath / RelativeFilename
current AbsoluteFilename
current RawSourceBytes (bounded by DirectSourceLimits)
```

This projection is not a new persisted record. It is cleared on discovery
failure and moves with the successful discovery result. Before activation the
coordinator must prove a one-to-one match between every selected persisted
`SourceIndex.Files` entry and the transient entry by `SourceFileKey`,
`ModuleKey`, virtual/logical coordinates and raw content hash. Duplicate,
missing, extra-in-module or mismatched entries are a safe miss before Engine
mutation.

The restored `FCodeSection` receives current `VirtualPath`, relative and
absolute filenames from this projection. Raw `.as` bytes are not preprocessed
code, so they must not be stored in `FCodeSection::Code` and must not manufacture
the legacy preprocessed `CodeHash`. Consumers requiring processed code must use
semantic cache records or explicitly enter the authoritative compile/reload
path. This closes IC-294 for exact startup without persisting host paths.

## Producer SourceIndex authority

The cold producer must persist the same SourceIndex candidate built from
production discovery plus captured preprocess-derived inputs and edges. The
clean-capture adapter may no longer manufacture a parallel one-file discovery
policy from `Module->Code[0]` when an authoritative candidate is supplied.

For the first dependency-free vertical:

1. discover the exact disk source;
2. build the persisted candidate from `DirectPlan` with empty captured inputs
   and edges;
3. normally preprocess and compile the exact same source;
4. clean-capture semantic/VM records while adopting and validating that
   SourceIndex;
5. publish the cold generation.

The legacy convenience overload remains only for established V3.4 regression
fixtures until their callers migrate. It must delegate to one capture
implementation; it is not a second production identity algorithm.

## Exact-start coordinator

The coordinator receives Engine B, a pinned validated generation, current
production discovery and limits. It returns a typed result with a disposition
(`Restored`, `Miss`, `Rejected`), reason/stage, selected module count, restored
type/function counts and compile-avoidance counters.

It performs no filesystem publication and follows this order:

1. find and decode the generation SourceIndex;
2. compare generation Profile and source snapshot authority;
3. build current dependency observations without preprocessing;
4. validate the persisted dependency candidate against current direct inputs;
5. require `Exact` and the rebuilt exact SourceIndex to equal the generation
   SourceSnapshot;
6. require an eligible, complete and currently supported module selection;
7. validate the transient current-source projection;
8. restore/activate through the V3.4 module transaction;
9. expose the restored current-engine route and diagnostic counters.

A normal source/profile/dependency/unsupported-shape mismatch is `Miss` and
leaves Engine B untouched. Malformed or internally inconsistent cache data is
`Rejected`. A late restore failure uses V3.4 rollback and is also `Rejected`.
No miss may silently fall through to compilation inside this coordinator; its
caller owns the authoritative fallback.

## Instrumentation

The test registers the existing `FAngelscriptCompilationEvents` observer only
around Engine B discovery and exact restore. Warm acceptance requires zero:

- `PreprocessProcessChunks` events;
- `PreprocessPostProcessCode` events;
- `CompileModuleParse` events;
- `CompileModuleCompileCode` events.

Because the high-level event currently reports the code-compile stage rather
than every maintained-fork compiler invocation, the exact coordinator also owns
explicit diagnostic counters initialized to zero for preprocess, parse,
module-code-compile and function-compiler calls. They describe work performed by
this startup attempt and will become the shared production diagnostics used by
V5/V6. The V3.5 exact branch must contain no compiler call site.

The test snapshots the Store's `Current`, generation manifest and referenced
Pack final files before warm startup and compares their path/size/content hash
afterward. Merely observing the same GenerationId is insufficient because an
unnecessary same-semantic publication could still touch control-plane files.

## First RED/GREEN tests

Create `AngelscriptCacheExactWarmStartupTests.cpp` rather than enlarging the
TypeSchema or V3.4 test files.

1. `UnchangedSecondLaunchRestoresWithZeroFrontendWorkAndNoPublication`
   - write one deterministic disk `.as` fixture;
   - Engine A discovers, normally preprocesses/compiles, captures with the
     authoritative SourceIndex, publishes Current, and is destroyed;
   - snapshot all physical Store files;
   - Engine B independently performs normal environment-only initialization;
   - rediscover the same disk source and open the pinned generation;
   - run exact startup while observing compilation events;
   - require `Answer() == 42`, a live normal module descriptor, the current
     absolute source path and a current-engine stable route;
   - require all frontend/compiler counters and observed events to be zero;
   - require no publication attempt and byte-identical Store files.

2. `ChangedRawSourceIsSafeMissBeforeEngineMutation`
   - modify only the fixture function body after publishing;
   - rediscover with Engine B and run exact startup;
   - require a direct-input miss before restore, no active module/type/route and
     zero frontend/compiler work inside the coordinator;
   - require the Store unchanged so the caller can perform the later clean
     compile/publication transaction.

3. `MismatchedTransientProjectionIsSafeMissBeforeActivation`
   - retain an exact direct plan but tamper a copied transient current source
     coordinate/key/path association;
   - require a typed projection miss before activation and no Engine mutation.

4. `RelocatedAbsoluteRootStillRestoresFromSameGeneration`
   - copy identical raw source to a different absolute test root while retaining
     the same logical Game mount and relative path;
   - require the same direct/candidate identity and successful restore;
   - require the restored descriptor to contain the new current absolute path,
     proving host paths are neither persisted nor identity inputs.

## Verification gate

- focused V3.5 class GREEN with logs for direct digest, SourceSnapshot,
  GenerationId, disposition/reason, selected module, frontend counters,
  FunctionId, execution result and Store before/after digest;
- established production-source discovery, dependency candidate, clean-capture,
  cold-generation and fresh-engine restore prefixes GREEN;
- complete `Angelscript.TestModule.Cache` prefix GREEN;
- official wrapper build GREEN;
- strict OpenSpec validation and parent/plugin `git diff --check` clean apart
  from documented line-ending warnings.

V3.5 closes only after the physical Engine A -> generation -> destroyed Engine A
-> independently initialized Engine B transaction proves exact source checking,
complete plugin-level reconstruction, zero frontend/compiler work and zero
publication. V4 then owns changed-module authoritative compilation and semantic
RecordId comparison.
