# V4.4 Deterministic Dependent-Recompile Wave

Date: 2026-08-10

## Outcome

V4.4 adds one conservative deterministic planner that consumes a complete
locally validated candidate Generation after an authoritative forced-clean
compile wave and returns the next set of modules that must be forced-clean
compiled. Existing HotReload/preprocessor/compiler behavior remains the only
source and compile authority. Cache V2 neither parses `.as` text again nor builds
a parallel include, declaration or inheritance analyzer.

The caller repeats:

```text
changed source discovery
    -> existing HotReload closure + forced-clean compile current wave
    -> overlay new semantic records into complete candidate Generation
    -> V4.4 compare persisted expectations to current semantic authorities
    -> next forced-clean module wave
    -> repeat until next wave is empty
    -> V4.3 publish the fixed-point complete Generation
```

This is propagation by verified clean results, not speculative transitive
over-invalidation. If compiling B after A changes B's public state, the next
iteration observes B's new authority and selects C. If B remains semantically
unchanged, C is not compiled merely because it was transitively reachable in a
source graph.

## Inputs and trust boundary

The production entry receives:

- one complete `FAngelscriptValidatedGeneration` candidate;
- the normal Cache read limits;
- an optional `IAngelscriptCacheCurrentSymbolResolver` for targets outside the
  candidate, especially current engine/environment symbols; and
- an atomic output DTO.

The planner validates the materialized Manifest, rebuilds the semantic view from
decoded records, and rejects impossible public-value mutation through the same
self-diff ownership checks used by V4.2. It accepts no caller-authored dependent
list, no text-diff classification and no stale precomputed authority catalog.

A malformed candidate, duplicate semantic authority or impossible root/record
shape is a typed planner error with an empty output. A valid dependency whose
current value cannot be proven is not a planner error: its owning module is a
deterministic safe miss with a typed reason.

## Current semantic authority catalogue

Authority is selected by both dependency kind and stable target. Looking up only
`ReferenceKind + StableKey` is insufficient: a type/property/global/initializer
has different current ABI/content authorities for layout, value and execution
edges.

| Dependency kind / target | Current ABI authority | Current content/value authority |
|---|---|---|
| Import / ScriptImport | resolved current target declaration route | absent |
| Declaration, Signature / script declaration | declaration `SignatureHash` | absent |
| Inheritance / ScriptType | type declaration `SignatureHash` | absent |
| ValueLayout / ScriptType | type declaration `SignatureHash` | `TypeSchema.Layout.TypeLayoutHash` |
| PropertyLayout / ScriptProperty | property declaration `SignatureHash` | property layout fingerprint |
| GlobalStorage / ScriptGlobal | global declaration `SignatureHash` | global storage layout fingerprint |
| HardValue / ScriptGlobal | global declaration `SignatureHash` | matching `HardValueHash` |
| HardValue / ScriptType enum authority | type declaration `SignatureHash` | matching enum-authority `HardValueHash` |
| Initializer / ScriptFunction | initializer declaration `SignatureHash` | `InitializerExecutionHash` |
| FunctionContent / ScriptFunction | function declaration `SignatureHash` | FunctionBody execution hash |
| ordinary ScriptFunction Declaration/Signature dependency | function declaration `SignatureHash` | absent |
| CompileOption / external target | injected current resolver ABI | injected current content/value |
| EnvironmentAbi / EnvironmentSymbol | injected current resolver ABI | absent |
| CanonicalName or StringLiteral | immutable owner-local canonical bytes | no external lookup |

For a `ScriptImport`, the stale import row is not accepted as proof of itself.
The planner follows its target reference into the current provider catalogue; a
removed or changed target makes the import consumer miss.

Targets absent from the candidate may be resolved by the injected current
resolver. Missing resolver, missing target, missing required content, ambiguous
authority, ABI mismatch and content mismatch all select the owner conservatively.
Unrelated environment symbols are never queried.

## Dependency owners

The planner evaluates every persisted dependency owner:

- `ModuleInterface.Dependencies` and every import target route;
- every `TypeSchema.Dependencies` array;
- `ModuleState.Dependencies`;
- every initialization action's dependencies; and
- every `FunctionBody.ActualDependencies` array.

Local canonical-name/string-literal relocations remain owner-internal and do not
create module propagation. Required relationships omitted from these arrays are
a producer/completeness defect, not permission for V4.4 to infer them from text.
V4.5 must prove the class/property/global/initializer producers emit sufficient
typed dependencies against clean-compile oracles.

## Output and deterministic ordering

The result contains sorted modules and sorted reasons per module. Each reason
records:

- owning record kind and stable semantic owner key;
- dependency ordinal (and initialization-action ordinal where applicable);
- dependency kind, target reference kind and full stable key;
- expected/current ABI and optional expected/current content; and
- one of `TargetUnresolved`, `AbiMismatch`, `ContentUnavailable` or
  `ContentMismatch`.

Module order is full `ModuleKey`; reason order is owner record kind, owner key,
owner/action/dependency ordinals, dependency kind, target kind/key and reason.
Input record, Pack and physical completion order cannot affect the result.
Duplicate identical reasons may be retained when distinct owners genuinely carry
the same edge; the module itself appears once.

## Minimal closure and fixed point

A normal call Declaration/Signature dependency compares only the callee
declaration ABI. A body-only edit therefore does not recompile callers. The
current V1 enum had no honest name for a compiler optimization that embeds an
ordinary callee body: `HardValue`, `Initializer` and `CompileOption` are distinct
authorities and must not be overloaded. V4.4 therefore adds the append-only
`FunctionContent=12` semantic dependency kind, which requires nonzero
`ExpectedContentOrValue` and a ScriptFunction target. The same body edit then
selects only the content-dependent caller. Existing enum values and physical
field widths remain unchanged; old unpublished caches are intentionally not a
compatibility target during plugin development.

The planner returns only the next wave. It does not recursively mark every
reverse-reachable module from an already stale projection. The orchestration
layer overlays each forced-clean result and invokes the planner again until no
reason remains. Cycles converge through the same process or fail closed under a
future bounded-iteration lifecycle guard; V4.4 itself is pure and has no Engine
mutation.

## First TDD packet

Add `AngelscriptCacheDependencyPropagationTests.cpp` as an independent test TU.
The production boundary is expected RED before its header exists. GREEN must
cover:

1. provider body change plus consumer ABI-only function edge: no next wave;
2. the same change plus explicit old execution-content expectation: consumer is
   selected with `ContentMismatch`;
3. removed/renamed provider function and stale consumer edge/import route:
   consumer is selected with `TargetUnresolved`;
4. type layout and property layout mismatches select only structural consumers;
5. global storage, hard value and initializer content mismatches select their
   consumers with typed reasons;
6. unrelated modules remain hits;
7. unresolved external target without a resolver is a safe miss; exact resolver
   match is a hit and unrelated symbols are never queried;
8. shuffled decoded-record/Manifest physical order produces byte-for-byte equal
   logical output ordering;
9. forged generation/duplicate semantic authority is a typed atomic failure; and
10. a synthetic A->B->C sequence proves B is the first wave, C is selected only
    after B's clean result changes, and the final overlay has an empty wave.

After focused GREEN, run the official Development Editor build, the focused
class, the complete Cache prefix, affected HotReload dependency/classification
prefixes, strict OpenSpec validation and both parent/plugin `git diff --check`.

## Non-claims

- V4.4 does not compile or mutate modules, publish Store roots, run class
  reinstancing or activate a partial candidate.
- V4.4 does not prove producer completeness for all class/property/global/
  initializer forms; V4.5 owns clean-oracle mutation evidence.
- V4.4 does not add per-function pre-compiler hits; V5 owns that hook.
- V4.4 does not restore all `FAngelscriptEngine` intermediate state. The separate
  `fresh-engine-reconstruction-boundary.md` assigns that work across V5-V7.
