## Context

The plugin now has several execution tiers and persistence paths that all consume the same AngelScript source:

- VM interpretation on the shared test engine (`ASTEST_CREATE_ENGINE` / `FAngelscriptTestEngine::GetSharedEngine`)
- Isolated full engines (`ASTEST_CREATE_ENGINE_FULL` / `FAngelscriptTestEngine::Create`)
- Cache V2 persist/restore
- StaticJIT backends `bytecode` and `typed-ast`
- Runtime JIT backends selected by BackendId and compile policy
- Optional performance sampling (`AngelscriptPerformanceTestUtils.h`)

Authoring today still looks like this: a CQTest `TEST_METHOD` owns an inline `ASTEST_AS(R"AS(... )AS")` string, builds one `FScopedAngelscriptModule`, and asserts one path. `AngelscriptTypedASTJITScriptFunctionCorpusTests.cpp` is the current extreme — it inlines fixture functions, then *also* writes them to a fake `Script/` root to create a generation engine. That is the pain the user is hitting: every new JIT, cache, or engine-property combination requires rewriting the same AS.

UE already has the expansion primitive we need. `FAutomationTestBase::GenerateTestNames` calls `GetTests(BeautifiedNames, ParameterNames)` and registers one leaf per parameter. `FAngelscriptScriptTestAutomation::FBridge` is already a COMPLEX (`bInComplexTask = true`) bridge that expands reflected `UAngelscriptTestSuite` methods this way. Epic's Python automation test scans `test_*.py` files and uses the parameter as the script path. CQTest's `TTestRunner::GetTests` only lists `TEST_METHOD` names; it is not a catalog expander.

Existing layers that remain:

| Layer | Owner | Role after this change |
|---|---|---|
| CQTest + inline AS | `AngelscriptTest/<Theme>/` | Bindings contract, HotReload, Debugger, Dump, C++-only observation |
| Native SDK | `AngelscriptTest/AngelScriptSDK/` | No `FAngelscriptEngine` |
| Reflected script suites | `UAngelscriptTestSuite` + `FAngelscriptScriptTestAutomation` | Host `Script/Tests/**` functional tests |
| This harness | new `DataDriven/` + `Fixtures/` | Same AS fixture × named engine profiles |

This record is plan-only. Implementation happens later on the same change. UE COMPLEX / CQTest background: `research/ue-data-driven-reference.md` (distilled from `数据驱动参考.txt`).

## Goals / Non-Goals

**Goals:**

- Separate AngelScript fixture source and virtual mounts from C++ test methods.
- Expose that corpus as a Shared lookup API keyed by `/Angelscript/Memory/TestCorpus/<relative>.as`, so CQTest and World/functional tests can fetch the same source without becoming DataDriven leaves.
- Let one fixture run under an explicit list of named engine profiles (VM, cache roundtrip, StaticJIT, Runtime JIT, performance collect) without copying source.
- Make shared versus isolated engine a case-level setting, not a file-level habit.
- Expand `(case, profile)` pairs into independently filterable Automation leaves under `Angelscript.TestModule.DataDriven.*`.
- Reuse `FAngelscriptTestEngine`, `CompileMemorySource` / disk compile helpers, `ExpectGlobalInt` family, and virtual-path rules already specified.
- Ship a small golden catalog that proves the loop; keep CQTest as the default for tests that are not matrix-shaped.
- Record that Coverage scenario tests (`AngelscriptTest/Coverage/`) may be generated by homogeneous slice only, with `coverage-matrix.md` remaining the index.
- Keep the test AngelScript corpus (authored + generated) as one library and derive StaticJIT C++ from it for both kinds of AS.
- Treat corpus `typed-ast-generate` leaves as StaticJIT generation tests on that same AS, so growing the fixture library also grows StaticJIT generate coverage.
- Prepare the same corpus for Runtime JIT via isolated `runtime-jit` (skip-or-run), so later backends do not copy AS into a new test pile.
- Run generated AngelScript through Cache V2 with two isolated engines (producer persist, consumer restore) and shared cache-root / project-dir config.

**Non-Goals:**

- Replace CQTest, Native SDK tests, World/PIE templates, or `UAngelscriptTestSuite`.
- Reimplement CQTest `TEST_METHOD` / `ASSERT_THAT` / Asserter types on the data-driven base, or migrate the existing CQTest corpus onto that base.
- Auto-cartesian every fixture against every profile (combinatorial explosion).
- Author or execute the host `Script/` teaching corpus from `test-as-script-corpus-and-functional-coverage`.
- Add `/Angelscript/Test/` as a new virtual-path root in v1 (use `/Angelscript/Memory/TestCorpus/...` and isolated-engine disk roots).
- Put full `FAngelscriptEngineConfig` blobs in JSON.
- Fail CI on performance budgets in v1 (collect artifacts only).
- Drive World/Actor/Debugger scenarios from this harness in v1. HotReload pairs are a **sibling** change (`test-as-hotreload-script-corpus`), not an engine profile on this COMPLEX.
- Migrate the existing 400+ CQTest files in Wave A (tasks 1–11).
- Rewrite AngelScriptSDK product generators into thousands of checked-in `.as` files.
- Generate Coverage as one wholesale emitter of all 1022 `TEST_METHOD`s.
- Generate Coverage unique API/lifecycle/environment scenarios (TArray.Sort, FString.Find, Widget, Input, Physics, Net) from type tables.
- Replace Pattern D `VerifyByPath` oracles with script getters that merely read the same UPROPERTY.
- Hand-author `.jit.cpp` files that copy fixture or product AngelScript.
- Auto-cartesian every corpus module against every StaticJIT backend.
- Change production StaticJIT rules (one module one `.jit.cpp`, no `"dual"`, editor save does not generate C++).
- Replace existing StaticJIT CQTest for packager layout, Provider ABI, coordinator matching, or diagnostics. Corpus generate leaves cover **generation against this AS**, not those contracts.
- Require Angelsea, LLVM, or any Runtime JIT plugin in default CI. Corpus `runtime-jit` leaves skip when no factory is registered.
- Treat StaticJIT generate leaves as Runtime JIT coverage, or feed `.jit.cpp` into Runtime JIT.
- Replace Runtime JIT factory/snapshot/session CQTest.

## Approaches considered

### A. COMPLEX catalog driver (recommended)

Plugin-owned `.as` fixtures + `cases.json` catalogs. One COMPLEX `FAutomationTestBase` subclass discovers catalogs at `GetTests` time and expands leaves. Runner applies the named profile, mounts fixtures, runs observations, reports through the Automation leaf.

- Pros: Matches UE Python tests and our existing script-suite bridge; leaves are independently selectable; fixtures are files; engine lifecycle is data.
- Cons: New authoring format; CQTest matchers are not the leaf API (the driver uses `FAutomationTestBase` assertions / existing `Expect*` helpers).

### B. Keep CQTest and generate `TEST_METHOD`s

Macro or codegen that stamps one CQTest method per `(fixture, profile)`.

- Pros: Stays inside current UnitTest.md shape.
- Cons: Still a C++ recompile to add a fixture or profile; CQTest `GetTests` cannot scan files; does not solve "AS library separate from unit tests".

### C. Fold the matrix into `UAngelscriptTestSuite`

Put fixtures under `Script/Tests` and let reflected suites be the only runner.

- Pros: One script-side authoring model.
- Cons: Suites run on the production-like compiled module graph; they cannot construct isolated generation engines, Cache V2 roundtrips, or coordinator `VMOnly`/`RuntimeOnly` modes. That is C++ engine-config work.

v1 implements **A**. CQTest and `UAngelscriptTestSuite` stay for their current jobs.

## Decisions

### 1. Three objects: fixture, catalog case, engine profile

- **Fixture**: one or more `.as` files plus a virtual mount. No engine config, no assertions.
- **Case**: JSON object that names fixtures/mounts, engine lifecycle, the profile list, observations, and optional `cacheRoot` for Cache V2 leaves.
- **Profile**: a C++-registered named preset that mutates `FAngelscriptEngineConfig` / coordinator / cache / JIT settings. JSON stores the profile id string. It MAY also store `cacheRoot` as a path overlay; it SHALL NOT embed a full `FAngelscriptEngineConfig`.

A case SHALL list profiles explicitly. The harness SHALL NOT invent a full cartesian product from a global profile registry.

Example catalog fragment:

```json
{
  "cases": [
    {
      "id": "syntax.optional-empty",
      "fixtures": ["Syntax/OptionalEmpty.as"],
      "mount": {
        "kind": "memory",
        "virtualRoot": "/Angelscript/Memory/TestCorpus/Syntax"
      },
      "engine": "shared",
      "profiles": ["vm"],
      "observations": [
        { "kind": "compile", "expect": "success" },
        { "kind": "executeInt", "decl": "int EchoEmpty()", "value": 0 }
      ]
    },
    {
      "id": "syntax.optional-empty.cache",
      "fixtures": ["Syntax/OptionalEmpty.as"],
      "mount": {
        "kind": "disk",
        "virtualRoot": "/Angelscript/Game/OptionalEmpty.as"
      },
      "engine": "isolated",
      "profiles": ["cache-roundtrip"],
      "cacheRoot": "OptionalEmptyCustom",
      "observations": [
        { "kind": "compile", "expect": "success" },
        { "kind": "executeInt", "decl": "int EchoEmpty()", "value": 0 }
      ]
    }
  ]
}
```

Shared `vm` can reuse one fixture file from the cache case. The second case exists because cache restore needs an isolated engine and a disk-backed source identity. Optional `cacheRoot` names a custom Cache V2 folder (see Decision 13); omit it to use the per-leaf default under `Saved/Automation/DataDriven/`.

### 2. Fixture tree lives in the test module, not host `Script/`

Physical root:

`Plugins/Angelscript/Source/AngelscriptTest/Fixtures/`

Layout:

```
Fixtures/
  README.md
  Syntax/OptionalEmpty.as
  Syntax/cases.json
  Language/...
```

Host `Script/` remains the product/teaching/script-suite tree. Test fixtures must not be compiled by the editor's normal script discovery. Isolated disk-mount cases copy or point engine `GetProjectDir` at a temp or fixture-owned script root, the same trick `AngelscriptTypedASTJITScriptFunctionCorpusTests` already uses, but the *source of truth* is `Fixtures/` rather than an inline string.

Memory-mount cases call `CompileMemorySource(Engine, VirtualPath, Script)` with `/Angelscript/Memory/TestCorpus/<relative>.as`.

### 3. Custom COMPLEX `FAutomationTestBase` plus a per-leaf session

UE data-driven leaves are COMPLEX `GetTests` / `RunTest`, not CQTest `TEST_METHOD`s. UE background: `research/ue-data-driven-reference.md`. In-repo precedent: `research/fbridge-precedent.md` (`FAngelscriptScriptTestAutomation::FBridge`).

`FBridge` is the existing COMPLEX adapter that turns `UAngelscriptTestSuite` methods into `Angelscript.ScriptTests.*` leaves. “Same as FBridge” means copy that **expansion mechanism** (handwritten `FAutomationTestBase`, snapshot `GetTests`, command as key, jump-to-`.as`). It does **not** mean reuse `FBridge`, share its prefix, or run script-suite methods from this harness.

Handwrite a **second** subclass (`bInComplexTask = true`) under `AngelscriptTest/DataDriven/`. Do **not** use `IMPLEMENT_COMPLEX_AUTOMATION_TEST`. Do **not** rewrite CQTest `GetTests` to scan JSON.

Two C++ objects, because COMPLEX is one long-lived registered instance and member state would leak across leaves. Steal CQTest's factory-per-leaf, not its macros:

```text
FAngelscriptDataDrivenAutomation  : FAutomationTestBase   // registered, long-lived
        holds catalog snapshot only
        GetTests()  → beautified names + key commands
        RunTest(key) → construct session, run, destroy
        GetTestSourceFileName(CompleteName) → primary .as

FAngelscriptDataDrivenLeafSession                             // one per leaf, short-lived
        ctor  = BEFORE_EACH (resolve case, acquire/create engine, ResetModules)
        body  = mounts + observations (Expect* on the Automation Test&)
        dtor  = AFTER_EACH (ResetModules or Destroy isolated engines)
```

The registered object SHALL NOT store `FAngelscriptEngine*`, compiled modules, or temp `Script/` roots. Payload routing is Decision 14: `Parameters` is only the key; fat input lives in the snapshot (or a Saved sidecar keyed by that same id); fat output leaves through `ExecutionInfo` and Saved artifacts.

Steal from CQTest: per-leaf isolation, setup/teardown, `ExecutionInfo` assertions, jump-to-source, Info-skip. Do not steal: `TEST_CLASS` / `TEST_METHOD`, `ASSERT_THAT`, custom Asserter, `FWaitUntil` latent chains, replacing 400+ CQTest files. Framework translation units SHALL NOT include CQTest headers. The leaf session is the authoring surface: wrap Shared helpers (`FAngelscriptTestWorld`, `FAngelscriptTestFixture`, later `AngelscriptBlueprintTestUtils`). Catalog `kind` values call those tools. Unique World stories MAY call `Session.World()` from C++ before a JSON kind exists. See `research/complex-framework.md`.

New types under `AngelscriptTest/DataDriven/`:

| File | Responsibility |
|---|---|
| `AngelscriptDataDrivenCase.h/.cpp` | Catalog structs, JSON parse/validate |
| `Shared/AngelscriptTestScriptCorpus.h/.cpp` | Queryable test-script database: virtual-path lookup, enumerate, memory compile helper |
| `AngelscriptTestEngineProfile.h/.cpp` | Named profile registry → config + post-create hooks |
| `AngelscriptDataDrivenHarness.h/.cpp` | `FAngelscriptDataDrivenLeafSession` + `RunCase` |
| `AngelscriptDataDrivenAutomation.cpp` | COMPLEX `FAutomationTestBase` bridge: snapshot, `GetTests` / `RunTest` / source-file mapping |

Automation identity:

- Beautified name: `Angelscript.TestModule.DataDriven.<CatalogTheme>.<CaseId>.<ProfileId>`
- Parameter/command: stable opaque id `theme/caseId@profileId` (not a raw filesystem path with spaces)
- `GetTestSourceFileName(CompleteName)` returns the primary `.as` fixture path for authored cases. Generated product leaves have no file; the driver MUST dump numbered generated source on failure.

Registration is gated by `WITH_ANGELSCRIPT_UNITTESTS`.

Discovery of catalogs uses `IFileManager` under the Fixtures directory, not Unreal asset scanning. Invalid catalogs fail discovery of *that file* with a diagnostic leaf or a harness self-test; they do not silently skip. Parse once into an immutable snapshot so `GetTests` stays well under the engine hitch warning.

### 4. Engine lifecycle is a case field, profiles may force isolated

`engine`: `shared` | `isolated`

- `shared` → `FAngelscriptTestEngine::GetSharedEngine()` then `ResetModules` before the case (same semantics as `ASTEST_CREATE_ENGINE`).
- `isolated` → `FAngelscriptTestEngine::Create(ProfileConfig, Dependencies)` and destroy at end of the leaf.

Profiles that persist cache, install StaticJIT generation, or select a Runtime JIT backend MUST require `isolated`. The validator rejects `engine: shared` with `cache-roundtrip`, `typed-ast-generate`, or `runtime-jit-*`.

Shared engine remains the default for cheap VM compile/execute leaves so the suite does not recreate bind databases per Syntax case.

### 5. v1 named profiles

Registered in C++, not JSON:

| Id | Engine | What it does |
|---|---|---|
| `vm` | shared or isolated | Compile + execute through VM (`VMOnly` / no JIT attach) |
| `cache-roundtrip` | isolated only | **Two** isolated Full engines: producer compiles disk AS and persists Cache V2; destroy; consumer restores from the same resolved `cacheRoot` / default `CacheV2RootOverride` + `GetProjectDir` and executes. Authored fixtures and generated products both use this hook after materializing to temp `Script/`. |
| `typed-ast-generate` | isolated only | Generation-only StaticJIT `typed-ast` path; skip leaf if `AS_CAN_GENERATE_JIT` is false |
| `runtime-jit` | isolated only | Coordinator `RuntimeOnly` + configured BackendId; skip leaf if no factory |

v1 does not add `bytecode-generate` or MIR/LLVM-specific ids until those plugins are the subject of a focused change. Additional profile ids are additive registrations.

### 6. v1 observation kinds

| `kind` | Oracle |
|---|---|
| `compile` | success or expected diagnostic substring |
| `executeInt` / `executeBool` | existing `ExpectGlobalInt` / `ExpectGlobalBool` |
| `executeException` | `ExecuteFunctionExpectingScriptException` |
| `perfCollect` | write median samples through `AngelscriptPerformanceTestUtils`; do not fail the leaf on budget |

JIT fallback-reason and native-entry proofs stay out of generic observations in v1; `typed-ast-generate` uses a profile-specific post-check in the profile hook (generated function present / fallback recorded), implemented as harness code rather than an open-ended JSON DSL.

### 7. Keep CQTest for non-matrix tests

New UnitTest.md rule (docs task, not a silent style drift):

- Keep CQTest as **incubator** only. The house of record is the COMPLEX **session + tools** (`research/complex-framework.md`). Catalog `GetTests` is one enumerator. World/Blueprint wrap existing Shared helpers on the session; they are not leftover CQTest and not engine profiles. After a feature is locked: move source to `Fixtures/`, add catalog cases for compile/execute, use `Session.World()` / `Session.Blueprint()` for those oracles once those facades ship. Routing: `docs-as-test-direction-map/research/framework-lanes.md`. This harness **is** the catalog enumerator on that framework. Do not migrate the existing 400+ CQTest files in Wave A. Do not `#include` CQTest from the framework.

### 8. Dual-repo and suite wiring

Implementation lives in the Angelscript submodule. Parent OpenSpec stays here. After submodule commit, update the parent gitlink.

Add suite prefix `Angelscript.TestModule.DataDriven` to `Tools/Shared/TestSuiteDefinitions.ps1` as `DataDriven`. Verification uses `Tools\RunTests.ps1` / `Tools\RunBuild.ps1` only.

### 9. Authored fixtures vs generated products — neither style is universal

Two existing styles look similar (both produce a lot of AS) but they are not interchangeable:

| | Coverage unroll (`Coverage/AngelscriptCoverage*.cpp`) | SDK generate (`AppendGeneratedAsLine` + `FNativeTypeCase`) |
|---|---|---|
| Axes | Named scenarios in `coverage-matrix.md`, one `TEST_METHOD` per capability | Homogeneous products: type × operator × category × partition |
| Source | Giant `ASTEST_AS` with `LocalInt8()`, `LocalInt16()`, … or unique Actor/UPROPERTY scripts | C++ tables emit AS at runtime |
| Oracle | Human-written expected values next to each function | Formula / type-width / compile-fail contract |
| Engine | `FAngelscriptEngine` + UE binds | Raw `asIScriptEngine` |
| Failure UX | You can read the AS in the `.cpp` | `PrintGeneratedAsSource` dumps numbered AS into the Automation log |
| Typical good fit | `TArray.Sort` on an Actor, mixin, UFUNCTION meta, Widget | `int8..uint64` times bitwise/shift ops times lvalue/const/temporary/field |

**Rule:** if the next cell is produced by `for type in Types: for op in Ops:` and the expected result is a formula, generate. If the case has a unique story, UE object lifecycle, or a one-off diagnostic, author it.

How this harness uses both:

1. **Authored scenario fixtures** — checked-in `.as` under `Fixtures/`. This is Coverage unroll *extracted out of C++*. `OptionalEmpty.as` and a later `TArraySort.as` belong here. Do not invent a generator for them.
2. **Generated products** — C++ case tables (reuse `FNativeTypeCase` / `AppendGeneratedAsLine` where the product is language-core) emit a memory-mount source at `GetTests`/`RunTest` time. The leaf id is a stable product id such as `LANG-OP-INTEGRAL-BITWISE/int8/mutable_lvalue`. JSON catalogs MAY declare a generator id instead of a fixture path. v1 does **not** check in thousands of generated `.as` files.
3. **False unroll to fix later** — Coverage `IntExpression` copying `LocalInt8` … `LocalUInt64` by hand is a type product trapped in unroll form. When that file is migrated, it becomes a generator feeding this harness, not 8 extra fixture files.
4. **SDK generators stay on Native SDK** for raw-engine white-box evidence (`Compile`, `Bytecode`, `Metadata`). Only when the *same* product must also run Cache/JIT/`FAngelscriptEngine` does it grow a harness leaf. Do not duplicate SDK suites into Fixtures.

Failure mapping: authored leaves point `GetTestSourceFileName` at the `.as` file. Generated leaves keep the product id in the beautified name and MUST print the generated source on failure (same contract as `PrintGeneratedAsSource`).

### 10. Coverage can be generated by slice, not as a suite rewrite

`AngelscriptTest/Coverage/` already thinks in Übershader axes (see file headers on `AngelscriptCoverageIntPropertyTests.cpp` / `IntExpression` / `IntFunction`): walk `int8…uint64` against one usage axis. The implementation is still hand-pasted `ASTEST_AS`. That is generate-eligible. The same directory also holds unique UE stories. Those are not.

This is **not** the Runtime CodeCoverage extension.

Classification of the 18 `coverage-matrix.md` domains, template ids, and retirement rules live in `research/coverage-generation.md`. Summary:

| Eligible now (Wave B+) | Later (needs new observations or more tables) | Never in this change |
|---|---|---|
| Int/Float/Bool **Expression** operators and conversions (`expression-product`, Pattern B, existing `executeInt`) | Int/Float/Bool **Property** family (`uclass-property-family`, Pattern D `VerifyByPath`) | Matrices 10–18 environment systems |
| Int/Float/Bool **Function** value/in/out/inout (`function-mode-product`) | UFUNCTION all-widths (`ufunction-width-product`, Pattern C) | Unique methods: FString.Find/Split, TArray.Sort, FVector.Dot |
| Container **element/key type** matrices | Math-struct shared Function **shape** | Actor/World lifecycle stories |
| Homogeneous 🚫 compile-fail families | Object-ref / specifier permutations | One-off diagnostics |

**Wave A (tasks 1–11)** ships the harness + Syntax golden + `integral-bitwise` on `FAngelscriptEngine`. It does not touch Coverage CQTest.

**Wave B (task 12)** adds `coverage-int-expression-arithmetic` (bitwise/shift MAY share the table). Dual-run `Angelscript.TestModule.Coverage.IntExpression` until parity; do not delete `ArithmeticOperators` in the same step that first adds the generator.

**Pattern D wait:** `IntFamilyDeclarationDefaults` is a real generator (one UCLASS, eight `UPROPERTY`s from a table), but the oracle is C++ `VerifyByPath<FInt8Property, int8>(…, "Int8Value", 100)`. Harness v1 observations cannot express that. Do not “simplify” it to `executeInt` of a script getter — that drops the property-taxonomy proof Coverage exists to provide. Add spawn + reflective observations in a later slice, then generate Property files.

Identity: every Coverage product leaf records the matrix scenario name (`ArithmeticOperators`) and the CQTest method it dual-runs. Update `coverage-matrix.md` when a method is retired; do not grow a second matrix.

### 11. Two libraries: test AS corpus and derived StaticJIT C++

The user-facing split is:

```text
Layer 1  Test AngelScript corpus (source of truth)
         authored Fixtures/**/*.as
         + generated products (tables → AS, not checked in)

Layer 2  Derived StaticJIT C++
         one <StableModuleKey>.<TargetProfile>.jit.cpp per AS module
         produced by typed-ast-generate (Wave A) / later bytecode-generate
```

Both handwritten AS and generated AS are Layer 1. Both can request corresponding StaticJIT. Layer 2 is never a handwritten shadow of Layer 1. Details: `research/static-jit-from-test-corpus.md`.

This pairing **is** StaticJIT testing, not a leftover. A corpus case that lists `vm` plus `typed-ast-generate` proves the same AngelScript on the interpreter and on the StaticJIT generator. Adding a fixture or a product cell, then listing the generate profile, is how generate coverage grows. Authors do not add a second AS copy under `StaticJIT/`.

What those leaves prove in Wave A:

| Proven | Not proven by generate leaves alone |
|---|---|
| Isolated `StaticJITGeneration` can compile this module | Loaded `AngelscriptTestJIT` Provider native execute |
| Typed-ast emit **or** a recorded per-function fallback reason | Packager/Provider ABI, coordinator match, diagnostics CQTest |
| Same AS as the `vm` executeInt oracle | Runtime JIT (`runtime-jit` is a different profile) |

Provider-load execute remains a later mechanical publish into `AngelscriptTestJIT`. Until then, generate completion / fallback is the StaticJIT oracle. Existing `Angelscript.TestModule.StaticJIT.*` contract tests stay.

How this lands on existing profiles:

- `syntax.optional-empty` + `typed-ast-generate` is the **authored** pairing golden (task 7). Disk mount, isolated `StaticJITGeneration` engine, skip if `AS_CAN_GENERATE_JIT` is false. Do not require `AngelscriptTestJIT` Provider load to pass.
- One `integral-bitwise` cell + `typed-ast-generate` is the **generated-AS** pairing golden (task 10.5). Materialize the product text to a temp `Script/` root. Do not cartesian every type × generate in Wave A.
- Later Coverage expression products are the same Layer 1 input; they do not need a third JIT authoring style.
- Session `.jit.cpp` under `Saved/Automation/DataDriven/` is not committed. Optional later mechanical publish into `AngelscriptTestJIT` still starts from this corpus.
- Production editor save still does not generate C++. `"dual"` stays forbidden. Packager still emits one translation unit per AS module.

ScriptCorpus extraction (task 9) is the cleanup of the current anti-pattern: inline AS **plus** a fake `Script/` write. After extraction, OptionalEmpty.as is the only AS.

### 12. Same corpus prepares Runtime JIT

Runtime JIT is a **third execution profile** on Layer 1, not Layer 2 and not a third AS pile. Details: `research/runtime-jit-from-test-corpus.md`.

```text
Layer 1  Test AngelScript corpus
         ├─ vm                 executeInt on VM
         ├─ cache-roundtrip    two isolated engines: persist then restore
         ├─ typed-ast-generate StaticJIT generation (Layer 2 .jit.cpp)
         └─ runtime-jit        coordinator RuntimeOnly execute (skip if no factory)
```

Wave A **prepares the slot**:

- Register `runtime-jit` (isolated, `RuntimeOnly`, configured BackendId, skip-if-no-factory).
- Catalog case `syntax.optional-empty` + `runtime-jit` with the same `EchoEmpty` oracles as `vm`.
- Enumeration always has the leaf. No factory → Info skip. Factory present → executeInt must match VM.
- Memory mount is allowed (disk `Script/` is a StaticJIT generate requirement, not a Runtime JIT one).
- Do not cartesian products or Coverage widths against Runtime JIT in Wave A.
- Angelsea/LLVM stay optional plugins. Default CI must stay green without them.
- Do not set `StaticJITGeneration` on this path. Do not pass `.jit.cpp` to Runtime JIT.

Later, when a factory is in a developer or CI machine, the same catalog line is the Runtime JIT test. Adding `runtime-jit` to a generated-product or Coverage case is how that coverage grows. Factory ABI / snapshot / session tests stay existing Runtime JIT CQTest.

Open until apply: BackendId from `DefaultAngelscriptCompileOptions.ini` versus a harness default that skips when absent. Either way JSON only stores the profile id.

### 13. Generated AS uses the same two-phase Cache V2 engines

Yes: Cache V2 on this harness is **two `FAngelscriptTestEngine::Create` calls**, not one engine that persist-and-restore in place. Details: `research/cache-roundtrip-two-phase.md`. Pattern already in `AngelscriptCacheFreshEngineRestoreTests` / `AngelscriptCacheExactWarmStartupTests`.

- **Producer:** isolated Full, `CacheV2RootOverride` set, `bDisableCacheV2Persistence = false`, `GetProjectDir` = temp root with `Script/`, compile disk AS (authored copy or **materialized generated product**), persist, destroy. No live module pointers survive.
- **Consumer:** new isolated Full, **same** cache root and project dir, restore, `executeInt` only here, `bDisableCacheV2Persistence = true` so it does not publish again. Must not pass by compiling source as the oracle.
- JSON does not carry full engine configs. Optional case field `cacheRoot` is the only catalog overlay for the cache directory; producer and consumer still share the resolved path. Compatibility/context keys remain harness constants.
- Default `CacheV2RootOverride` is `{ProjectSavedDir}/Automation/DataDriven/<leaf>/CacheV2`. A relative `cacheRoot` resolves under `{ProjectSavedDir}/Automation/DataDriven/CacheRoots/<cacheRoot>/`. An absolute path is accepted only if it normalizes inside `{ProjectSavedDir}/Automation/`. Reject `..`, empty, Fixtures, host `Script/`, and the project's production cache tree.
- `cacheRoot` is valid only on cases that list `cache-roundtrip`. Other profiles SHALL fail catalog validation if they set it.
- Wave A: OptionalEmpty authored cache (task 6) plus one `integral-bitwise` `int8` `mutable_lvalue` cache leaf (task 10.6). One OptionalEmpty case (or a sibling) SHALL demonstrate a custom `cacheRoot`. No type cartesian.
- Does not replace `Angelscript.TestModule.Cache.*`.

### 14. Complex payloads use snapshot + artifacts, never `Parameters`

GMP XConsole (`research/gmp-xconsole-parameters.md`) still receives `TArray<FString>` argv and can decode a quoted JSON token or `@filepath`. COMPLEX Automation does not: `CompleteTestName = TestName + " " + Parameters`, and this harness (like `FBridge`) takes **everything after the last space** as the command. JSON, Windows paths, and packed expected values in `Parameters` will split wrong. Do not import `SerializedInvoke`, console meta, or the command pipeline.

Three channels, each one job:

| Direction | Channel | What it carries | Wave A |
|---|---|---|---|
| **In** (enumerate → `RunTest`) | `Parameters` | Lookup key only: `theme/caseId@profileId` | Required |
| **In** | Catalog snapshot | Case JSON already parsed: fixtures, `engine`, `profiles[]`, `cacheRoot`, observations (`kind`/`decl`/`value`/later `args`) | Required. This **is** the fat input bus. |
| **In** | Saved sidecar | Generated AS or a huge expected blob that should not sit in the enumerate snapshot | Later. Path lives **inside** the snapshot, never in `Parameters`. |
| **Out** (`RunTest` → Session / CI) | `ExecutionInfo` | Pass/fail, Info-skip, error strings. `RunTest` still returns `bool`. | Required |
| **Out** | Log dump | `[AS-SOURCE-BEGIN]` … generated source on failure | Required for generated leaves |
| **Out** | Saved artifact | `perfCollect` JSON under `Saved/Automation/AngelscriptPerformance/`; later optional `actual.json` for struct diffs | `perfCollect` in v1; struct sidecar later |

**Inbound (how a leaf gets complex input).** Authors put the payload on the **case / observation object**, not on the Automation command. `cases.json` is already JSON; a later `executeJson` / `args` / map oracle is a new field on that object. C++ deserializes it when the session runs (same idea as XConsole’s typed decode, without putting the JSON on argv). Generated product source is stored on the snapshot leaf (`GeneratedSource` or equivalent), not serialized into `OutTestCommands`.

**Outbound (how complex results leave the leaf).** UE has no typed return from `RunTest`. Do not invent a second command-line encoding for actuals. Failures go through `AddError` / existing `Expect*` on the Automation test. Humans need the generated AS in the log. Machines that need a blob collect a **file** under `Saved/Automation/DataDriven/<sanitized-key>/` (perf already has a sibling tree). The file name is derived from the same key; CI does not parse `Parameters` to recover JSON.

**Later sidecar (only if the snapshot is too fat).** During `GetTests` or first `RunTest`, write `Saved/Automation/DataDriven/<leaf>/payload.json` (or `source.as`). The in-memory snapshot stores a relative path under `Saved/Automation/`. `RunTest(key)` loads it. Do **not** put `@Saved/.../payload.json` into `Parameters` (spaces). Wave A keeps generated source in the snapshot; the sidecar is an escape hatch, not a task.

**Forbidden.** JSON in `OutTestCommands`. Comma-packed expected structs in the key. GMP `@file` tokens as the Automation command. Returning structured JSON through `AddInfo` as the only oracle (Info is for skip reasons, the driver card, and breadcrumbs; oracles stay `Expect*` / files).

### 15. Each leaf prints a compact driver card, not a packed `Parameters` blob

Session Frontend already shows two identity fields per leaf: the beautified name and `Parameters`. That is enough to *select* a row. It is not enough to *read* the row when a log or failure is all you have. Coverage already does `AddInfo(CaseLabel)` at the start of a case; this harness does the same job with a stable marker.

Three layers, each one job:

| Layer | When | What | Must not contain |
|---|---|---|---|
| **Enumerate identity** | `GetTests` | Beautified name encodes theme / case or product cell / profile. `Parameters` is the key. | Observation JSON, generated AS, `FAngelscriptEngineConfig` |
| **Driver card** | every `RunTest` (pass, fail, skip) | One `AddInfo` line tagged `[AS-DD-DRIVER]` | Generated source, engine-config blobs, `perfCollect` JSON |
| **Failure dump** | fail only | Error text repeats the card + case/profile/`decl`; generated leaves add `[AS-SOURCE-BEGIN]` | Using Info as the pass oracle |

Wave A card fields (space-separated `k=v`, relative paths, no spaces in values):

```text
[AS-DD-DRIVER] key=Syntax/syntax.optional-empty@vm profile=vm engine=shared fixtures=Syntax/OptionalEmpty.as obs=executeInt:EchoEmpty=0
```

Generated product example:

```text
[AS-DD-DRIVER] key=Products/integral-bitwise.int8.mutable_lvalue@vm profile=vm engine=isolated product=integral-bitwise type=int8 category=mutable_lvalue obs=executeInt:OpAnd=...
```

If `cacheRoot` is set, append `cacheRoot=OptionalEmptyCustom`. Skip leaves still emit the card, then the existing skip Info (missing factory / `AS_CAN_GENERATE_JIT`).

`RunCase` / session start owns `AddInfo`. Failures `AddError` with the same card prefix so the first error is self-contained (Session Frontend often surfaces errors without requiring you to open Info). Do not write a per-leaf `params.json` on pass in Wave A (Coverage-scale products would flood `Saved/`). Do not put this card into `OutTestCommands`.

Precedent: Coverage `AddInfo(CaseLabel)`; Native SDK `PrintGeneratedAsSource` only on generated failure. `FBridge::ExecuteForTesting` is the pattern for asserting `ExecutionInfo` entries in harness tests.

### 16. The fixture tree is a queryable test-script corpus, not harness-private files

Earlier drafts only let the COMPLEX harness read `Fixtures/` via a catalog relative path. That is not enough. C++ unit tests and World/functional CQTest also need to **fetch the same AngelScript by canonical virtual path** without inlining `ASTEST_AS` and without becoming DataDriven leaves.

This is a **test-module script database**, not a production Runtime API and not the host `Script/` teaching corpus (`test-as-script-corpus-and-functional-coverage` still owns `/Angelscript/Game/...`).

Canonical key:

```text
physical:  Plugins/Angelscript/Source/AngelscriptTest/Fixtures/<relative>.as
virtual:   /Angelscript/Memory/TestCorpus/<relative>.as
example:   /Angelscript/Memory/TestCorpus/Syntax/OptionalEmpty.as
```

Do **not** name this type `FAngelscriptTestFixture` — that RAII engine helper already exists in `Shared/AngelscriptTestFixture.h`. The corpus lives in Shared so Bindings / World / Debugger / Coverage CQTest can include it without depending on `DataDriven/`:

`Shared/AngelscriptTestScriptCorpus.h`

```text
FAngelscriptTestScriptRecord
    VirtualPath, RelativePath, AbsolutePath, Source, bGenerated

FAngelscriptTestScriptCorpus
    GetRoot()
    MakeMemoryVirtualPath(RelativePath)          // TestCorpus + relative
    TryGetByVirtualPath(VirtualPath, Out, Error) // primary lookup
    TryGetByRelativePath(RelativePath, Out, Error)
    TryEnumerate(VirtualPrefix, OutPaths, Error)
    TryCompileMemory(Engine, VirtualPath, Error) // Get + existing CompileMemorySource
```

Rules:

- Lookup is the organization API. A COMPLEX session MAY `TryGetByVirtualPath` then spawn/tick with `Session.World()` (wrapping `FAngelscriptTestWorld`). Incubating CQTest MAY still fetch the same record. They do **not** have to add a `cases.json` row merely to load source. World Tick is not an engine profile.
- One-off `ASTEST_AS` remains allowed for snippets that will never be reused.
- `TryGetByVirtualPath` SHALL reject `/Angelscript/Game/...`, host `Script/` paths, `..`, and paths outside `GetRoot()`. This database does not proxy the teaching corpus.
- Authored files are always lookupable from disk. Generated products use the same virtual-path namespace (`/Angelscript/Memory/TestCorpus/Products/...`) via a process-local overlay (`RegisterGenerated`); they are not checked in. Wave A ships authored lookup; the overlay is the product-generator hook.
- The COMPLEX harness is one consumer: catalogs still list relative paths, and `BuildMemoryDescriptors` calls `TryGetByRelativePath`. Catalogs do not own the files.
- The harness still does **not** drive World/Debugger observations in v1. Functional tests that need World keep CQTest; they just stop owning the `.as` text. HotReload before/after pairs are `test-as-hotreload-script-corpus` (separate COMPLEX under `Angelscript.TestModule.HotReload.Corpus`).

## Risks / Trade-offs

- [Bridge state leak] COMPLEX is one instance; a leftover engine pointer contaminates the next leaf → Per-leaf `FAngelscriptDataDrivenLeafSession`; registered Automation object holds snapshot only.
- [Discovery cost] Scanning JSON during Automation worker enumerate could hitch → Keep catalogs small in v1; parse once into an immutable snapshot; do not walk the whole `AngelscriptTest` tree.
- [Shared-engine contamination] A buggy case leaves modules or engine properties behind → Always `ResetModules` after shared leaves; profiles that touch engine properties require isolated.
- [Profile skip vs fail] Missing Runtime JIT plugin must not fail CI → Skip with an Info event naming the missing BackendId, same pattern as AutoRTFM tests that skip when the runtime is disabled.
- [Two AS test worlds] Authors may put functional tests in Fixtures instead of `UAngelscriptTestSuite` → Docs state: Fixtures are engine-matrix inputs; `Script/Tests` are product-facing script suites with World helpers.
- [JSON drift] Catalog `decl` strings diverge from fixture functions → Golden harness tests compile and execute the shipped `OptionalEmpty.as`; a later validator can grep decls.
- [Generated-source opacity] A product leaf fails with no readable AS → Require `PrintGeneratedAsSource` (or harness equivalent) on every generated compile/execute failure.
- [Wrong authoring] Authors generate unique Widget/Actor scenarios or unroll 18×6 operator cells by hand → Docs + spec: formula products generate; unique scenarios are files. Do not rewrite all 1022 Coverage methods; Wave B is IntExpression only.
- [False Pattern D] A property generator “passes” by reading the UPROPERTY from script → Forbid; keep `VerifyByPath` until harness spawn observations exist.
- [Handwritten JIT corpus] A second tree of `.jit.cpp` copies fixture functions and rots → Spec: Layer 2 is derived only; generate profile is the proof; do not accept manual transcriptions.
- [JIT cartesian] Every product cell also generates typed-ast and bytecode → Explicit profile lists; Wave A generate goldens are OptionalEmpty plus one bitwise cell.
- [Runtime JIT CI] Default CI has no Angelsea/LLVM → `runtime-jit` Info-skips; OptionalEmpty leaf still enumerates so the slot exists.
- [Fat Parameters] JSON / `@file` / packed expected values in COMPLEX `Parameters` split on spaces and cannot round-trip → Decision 14: key in `Parameters`, payload in snapshot or Saved sidecar, results via `ExecutionInfo` and artifacts.
- [Invisible row] A failing leaf only says `EchoEmpty != 0` with no catalog identity → Decision 15: `[AS-DD-DRIVER]` Info on every run; failures repeat the card in `AddError`.
- [Private fixtures] Only the COMPLEX harness can read `.as` files, so World/CQTest keep inlining source → Decision 16: Shared `FAngelscriptTestScriptCorpus` lookup by `/Angelscript/Memory/TestCorpus/...`; catalogs are one consumer.
