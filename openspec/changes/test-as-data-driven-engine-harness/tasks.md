# Data-Driven Engine Harness Implementation Plan

> Plan-only record. Do not implement in the recording session. At apply time use `superpowers:subagent-driven-development` or `superpowers:executing-plans`. Dual-repo: implement in `Plugins/Angelscript`, then update the parent gitlink.

**Goal:** Ship a COMPLEX **framework** (per-leaf session + tools) whose first enumerator is a JSON catalog: plugin-owned AngelScript corpus under named engine profiles, StaticJIT generate, Runtime JIT skip-or-run, then (Wave B) Coverage IntExpression products. World/Blueprint session facades wrap existing Shared helpers after Wave A (`research/complex-framework.md`). Do not reimplement CQTest macros; do not `#include` CQTest from the framework.

**Architecture:** Fixture library + JSON catalogs + C++ profile registry + handwritten COMPLEX `FAutomationTestBase` bridge with a per-leaf session. Authored and generated AS are Layer 1; StaticJIT `.jit.cpp` is derived Layer 2. `typed-ast-generate` leaves are StaticJIT generate coverage; `runtime-jit` is the Runtime JIT slot (isolated, skip if no factory). Packager/Provider/factory CQTest stays. Coverage generation is slice-based. Do not reimplement CQTest macros.

**Tech stack:** UE 5.7 COMPLEX `FAutomationTestBase` (not `IMPLEMENT_COMPLEX_AUTOMATION_TEST`, not CQTest `TEST_METHOD` expansion), existing `FAngelscriptTestEngine`, `CompileMemorySource`, `ExpectGlobalInt`, Cache V2, StaticJIT typed-ast generation engines (skip if unavailable), Coverage Pattern B invokers for Wave B.

**Spec:** `openspec/changes/test-as-data-driven-engine-harness/specs/` (including `as-coverage-product-generation`, `as-test-static-jit-from-fixture-corpus`, and `as-test-runtime-jit-from-fixture-corpus`).

## Global Constraints

- Gate every new Automation registration with `WITH_ANGELSCRIPT_UNITTESTS`.
- New test files start with `Angelscript` and live under `AngelscriptTest/DataDriven/`, `AngelscriptTest/Shared/` (corpus tests), or `Fixtures/`.
- Authored fixtures are a Shared corpus (`FAngelscriptTestScriptCorpus`) keyed by `/Angelscript/Memory/TestCorpus/<relative>.as`. Incubating CQTest and COMPLEX session tools MAY load by virtual path without a catalog leaf. Do not name this type `FAngelscriptTestFixture`. Do not serve host `Script/` or `/Angelscript/Game/` from this API.
- Verify only through `Tools\RunBuild.ps1`, `Tools\RunTests.ps1`, and `Tools\RunTestSuite.ps1`.
- Do not migrate Bindings, Debugger, Native SDK, or host `Script/` corpus in this change. HotReload pairs are sibling `test-as-hotreload-script-corpus` (after this corpus API).
- Do not add `/Angelscript/Test/` as a new virtual-path root in v1.
- JSON catalogs reference profile ids; they do not serialize `FAngelscriptEngineConfig`. Optional `cacheRoot` is a path overlay only: default `{ProjectSavedDir}/Automation/DataDriven/<leaf>/CacheV2`, relative names resolve under `Saved/Automation/DataDriven/CacheRoots/`, absolute paths must stay inside `Saved/Automation/`. Reject `..` and non-cache profiles.
- COMPLEX `Parameters` is a lookup key (`theme/caseId@profileId`). Fat input (observations, `cacheRoot`, generated source, later `args` / JSON oracles) lives in the catalog snapshot or a Saved sidecar referenced by that snapshot. Fat output leaves through `ExecutionInfo` and Saved artifacts. Do not put JSON, `@file`, or packed expected values in `OutTestCommands`. Each `RunTest` SHALL `AddInfo` a compact `[AS-DD-DRIVER]` line (key, profile, engine, fixtures or product cell, observation summary). Failures repeat that card in `AddError`. Do not write a per-pass params sidecar in Wave A. The registered `FAutomationTestBase` holds a catalog snapshot only. Each `RunTest` constructs `FAngelscriptDataDrivenLeafSession` and must not keep `FAngelscriptEngine*` on the Automation object. Do not reimplement CQTest `TEST_METHOD` / `ASSERT_THAT`. Do not use `IMPLEMENT_COMPLEX_AUTOMATION_TEST`.
- `cache-roundtrip` creates two isolated engines (producer persist, consumer restore) with shared `CacheV2RootOverride` and `GetProjectDir`. Generated products materialize to temp `Script/` first, same as typed-ast generate. Do not cartesian every product cell onto cache.
- Performance observations collect artifacts only; they do not fail budgets in v1.
- Unique scenarios are authored `.as` files; homogeneous type×operator products are generated. Do not check in one file per generated cell in v1.
- Do not rewrite AngelScriptSDK generators into Fixtures.
- Do not generate unique Coverage API/lifecycle/environment scenarios (TArray.Sort, FString methods, Widget/Input/Physics/Net). Homogeneous Coverage type-family slices wait until Wave B (section 12).
- Pattern D Coverage property tests MUST keep `VerifyByPath`; do not replace them with script getters.
- StaticJIT C++ is derived from the test AS corpus. Do not hand-write `.jit.cpp` that copies fixtures or products. Generate-profile leaves **are** StaticJIT generation tests of that AS; they do not replace packager/Provider/coordinator CQTest. Wave A generate goldens are OptionalEmpty plus one `integral-bitwise` cell.
- Runtime JIT uses the same corpus. Wave A registers `runtime-jit` (isolated, skip-if-no-factory) and the OptionalEmpty golden. Do not require Angelsea in CI. Do not cartesian products against Runtime JIT. Do not treat `typed-ast-generate` as Runtime JIT coverage.
