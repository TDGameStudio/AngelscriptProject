## Why

CQTest `TEST_METHOD` plus inline `ASTEST_AS` source is the wrong grain for the current product: one AngelScript fixture now needs to prove compile, Cache V2 restore, StaticJIT (`bytecode` and `typed-ast`), Runtime JIT backends, engine-property/syntax flags, and optional performance under either the shared test engine or a fresh isolated engine. Copying the same `.as` body into every C++ method does not scale, and CQTest has no first-class data-driven leaf expansion.

## What Changes

- Add a plugin-owned **script fixture library** whose `.as` files live under `AngelscriptTest/Fixtures/` and are queried through Shared `FAngelscriptTestScriptCorpus` by canonical virtual path `/Angelscript/Memory/TestCorpus/<relative>.as`. The COMPLEX harness is one consumer. CQTest and World/functional tests MAY fetch the same source without a catalog leaf. One-off `ASTEST_AS` remains allowed. This is not the host `Script/` teaching corpus.
- Add **case catalogs** that bind fixtures to named engine profiles, engine lifecycle (`shared` vs `isolated`), observation kinds (compile, execute, cache, JIT, performance), and expected results.
- Add a **COMPLEX Automation driver** in `AngelscriptTest`: a second handwritten `FAutomationTestBase` subclass (`bInComplexTask = true`) that discovers catalogs and expands each `(case, profile)` into an independently selectable leaf. Copy the expansion mechanism of `FAngelscriptScriptTestAutomation::FBridge` (snapshot `GetTests`, command as key, jump-to-source). Do not reuse `FBridge`, do not use prefix `Angelscript.ScriptTests`, and do not run `UAngelscriptTestSuite` methods. `Parameters` is a lookup key only. Fat input lives in the catalog snapshot (later a Saved sidecar keyed by the same id, never JSON or `@file` in `OutTestCommands`). Fat output leaves through `ExecutionInfo` and Saved artifacts (`perfCollect` JSON, generated-AS log dumps). Each `RunTest` emits a compact `[AS-DD-DRIVER]` Info card (key, profile, engine, fixtures or product cell, observation summary); failures repeat that card in the error. Each `RunTest` constructs a short-lived leaf session (CQTest-style isolation) and must not keep `FAngelscriptEngine*` on the registered instance. Do not reimplement CQTest macros, and do not migrate existing CQTest files onto this base.
- Keep CQTest as an **incubator** only. Native SDK and `UAngelscriptTestSuite` / `FBridge` stay. World/Blueprint lasting tests graduate onto session tools wrapping `FAngelscriptTestWorld` / `AngelscriptBlueprintTestUtils` (`research/complex-framework.md`). HotReload reusable pairs remain `test-as-hotreload-script-corpus` (enumerator on the same framework when it lands). Do not `#include` CQTest from the framework.
- Split fixture authoring: unique scenarios are checked-in `.as` files (Coverage-style unroll). Homogeneous type×operator products stay table-driven generators (SDK `FNativeTypeCase` / `AppendGeneratedAsLine` style) and feed the harness as memory mounts with stable product ids. Neither style is universal.
- Record that **Coverage can be code-generated only by slice**, not as one generator for all 1022 `TEST_METHOD`s: type/width/mode cartesian rows (int family, function value/in/out/inout, container key/value types, UPROPERTY width templates) become products; unique API and World scenarios stay authored. `coverage-matrix.md` remains the scenario index. Existing Coverage CQTest stays until a generated slice proves prefix parity.
- Treat the test AngelScript corpus (authored `Fixtures/` plus generated products) as one library, and StaticJIT C++ as a **derived** second library: both handwritten and generated AS can request corresponding StaticJIT generation. Do not hand-maintain a parallel `.jit.cpp` corpus.
- Let generated products use the same **two-phase Cache V2** path as authored fixtures: producer isolated engine compiles (after materializing AS to a temp `Script/`), persist, destroy; consumer isolated engine restores with the same cache root and source identity, then execute. JSON still does not embed `FAngelscriptEngineConfig`. Cases MAY set `cacheRoot` to a custom Cache V2 folder (relative under `Saved/Automation/DataDriven/CacheRoots/`, or an absolute path inside `Saved/Automation/`); omit it for the per-leaf default. Producer and consumer always share the resolved path.
- Make that pairing a **first-class StaticJIT test**: the same corpus leaf that proves VM compile/execute also proves StaticJIT generation when the case lists `typed-ast-generate`. This grows generate coverage without a second AS pile. It does not replace packager, Provider ABI, coordinator, or diagnostics CQTest.
- **Prepare the same corpus for Runtime JIT**: register isolated `runtime-jit` now (skip if no factory so default CI stays green). OptionalEmpty is the Wave A golden with the same `executeInt` oracles as `vm`. Later backends list `runtime-jit` on corpus cases; they do not copy AS into a new Runtime JIT folder. StaticJIT `.jit.cpp` is not a Runtime JIT input. Factory ABI CQTest stays.
- Deliver this change first as a plan-only OpenSpec record. No harness, fixture, or documentation implementation is part of the recording session.

## Capabilities

### New Capabilities

- `as-data-driven-test-harness`: Case catalog schema, named engine profiles, shared-versus-isolated lifecycle, two-phase Cache V2 producer/consumer engines, COMPLEX Automation discovery/execution with a per-leaf session on a custom `FAutomationTestBase`, authored and generated source kinds, observation kinds, and gating/`WITH_ANGELSCRIPT_UNITTESTS` rules.
- `as-test-script-fixture-library`: Plugin-owned AngelScript fixture tree, Shared virtual-path corpus API (`TryGetByVirtualPath` / enumerate / memory compile), authored-versus-generated source kinds, catalog-to-fixture binding, and the rule that C++ tests do not own reusable fixture source.
- `as-coverage-product-generation`: Which Coverage matrix slices may become generators, which must stay authored, how generated leaves keep `coverage-matrix.md` identities, and the dual-run retirement rule for existing Coverage CQTest.
- `as-test-static-jit-from-fixture-corpus`: Authored fixtures and generated AS products are the StaticJIT input corpus; derived `.jit.cpp` is generated code; generate-profile leaves are StaticJIT generation tests on that same corpus; session artifacts are not the source of truth. Packager/Provider/coordinator CQTest stays.
- `as-test-runtime-jit-from-fixture-corpus`: The same corpus prepares Runtime JIT execute leaves (`runtime-jit`, isolated, skip-if-no-factory). Wave A ships OptionalEmpty as the slot; no cartesian; no Angelsea CI requirement; StaticJIT generate is a different proof.

### Modified Capabilities

- None. The harness consumes `test-engine-lifecycle`, `as-virtual-script-paths`, `as-script-source-provider`, `runtime-engine-create-factory`, `angelscript-unit-test-gates`, `as-static-jit-backend`, `as-runtime-jit-backend`, and `as-unified-jit-coordinator` without changing their requirements. `as-script-test-suite-runner` remains the reflected `UAngelscriptTestSuite` path and is a sibling, not a replacement. Production StaticJIT still emits one `.jit.cpp` per AS module, and a normal editor `.as` save still does not generate C++. Runtime JIT factories remain optional plugins; corpus leaves skip when no factory matches.

- Future sources under `Plugins/Angelscript/Source/AngelscriptTest/DataDriven/` (harness), `Plugins/Angelscript/Source/AngelscriptTest/Shared/AngelscriptTestScriptCorpus.*` (corpus lookup), and `Plugins/Angelscript/Source/AngelscriptTest/Fixtures/` (`.as` + `cases.json`).
- Dual-repo: OpenSpec in the parent project, implementation in the `Plugins/Angelscript` submodule, then parent gitlink.
- Automation prefix `Angelscript.TestModule.DataDriven.*` plus a `DataDriven` entry in `Tools/Shared/TestSuiteDefinitions.ps1`.
- Docs: `Documents/UnitTest/UnitTest.md`, `Documents/Guides/Test.md`, `Documents/Guides/TestConventions.md`, and `Plugins/Angelscript/Source/AngelscriptTest/Shared/README_MACROS.md`.
- Related but separate: `test-as-script-corpus-and-functional-coverage` owns host `Script/` teaching corpus and `UAngelscriptTestSuite` functional tests. `test-as-hotreload-script-corpus` owns HotReload before/after pairs and `Angelscript.TestModule.HotReload.Corpus` leaves. This harness does not author those trees and does not run `UAngelscriptTestSuite` or HotReload ClassGenerator analyze.
- v1 does not migrate the existing 400+ CQTest files. One golden Syntax fixture, one `integral-bitwise` product, plus a TypedASTJIT ScriptCorpus extraction prove the harness. Coverage generation is a later wave on this same change, starting with the int-family slices, not a rewrite of all 18 Coverage domains.
