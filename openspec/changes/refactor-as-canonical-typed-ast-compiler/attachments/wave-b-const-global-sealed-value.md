# Wave B closure — sealed integer constant-global value

Worktree: `D:\as-cta`.
Change: `refactor-as-canonical-typed-ast-compiler`.
Date: 2026-08-23.

## Problem

The Sema path already evaluates a supported integer global initializer. For
example, `const int G = 40 + 1` became `default=41` in the sealed AST and
`const int G = 0x29` executed as `41`. However, `asCBytecodeCodeGen::Generate`
then reparsed the presentation string `decl->defaultArg` using `strtoll`.

That left two sources of truth:

```text
Sema:       typed expression -> evaluated integer
CodeGen:    declaration text -> strtoll -> integer
```

It is unsafe architecture even when both happen to agree. CodeGen should
consume the sealed result, not reimplement a text parser or depend on the
format chosen for a diagnostic/dump field.

## Implemented rule

`asCDecl` now carries:

```cpp
bool    hasConstantValue;
asQWORD constantValue;
```

`asCSema::ActOnGlobalVarInit` sets the raw integer value after successful
`EvalIntegerConst`. `asCASTContext::SetDeclConstantValue` is a normal
pre-seal-only construction API. The deterministic AST dump writes
`constant=<bits>` whenever the fact exists.

The existing integer-global CodeGen route now follows this rule:

```text
decl has initializer text
    and type is an integer
    and sealed hasConstantValue == true
        -> write the required 1/2/4/8 byte representation of constantValue
    otherwise
        -> fail closed with asNOT_SUPPORTED
```

There is no `strtoll` in `as_bytecode_codegen.cpp` after this change. Sema
also formats the retained display/default string as a 64-bit signed value so
the human-readable field no longer truncates a valid 64-bit evaluated result.

## Scope boundary

This is deliberately only the existing **integer** constant-global route. It
does not claim that floating-point, string, handle, value-object, list-pattern,
or arbitrary runtime global initializers can be generated by CANONICAL CodeGen.
Those require their own sealed constant/lifetime and storage protocols. Missing
or incompatible facts fail closed instead of falling back to text parsing or
the legacy compiler.

