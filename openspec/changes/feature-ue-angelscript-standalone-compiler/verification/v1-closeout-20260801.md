# Standalone V1 external-consumer closeout — 2026-08-01

> **Architecture correction (2026-08-01):** Shared `AngelscriptLanguageCore`, Runtime `Language/`, and UE frontend-migration statements in this record are preserved as historical evidence and are no longer the active design. UE keeps its original authoritative preprocessor/descriptor path; Standalone owns `Standalone/Source/Compiler/Frontend` privately, and the hosts exchange only the complete offline JSON bundle.


Status: passed and archive-ready. This record supersedes earlier release-count,
archive-hash, and external-consumer pending statements. The change has not been
archived or committed by this work session.

## Outcome and boundary

Standalone V1 now has a verified final-engine producer-to-consumer path:

1. an ordinary content-only external Unreal project, with no C++ host module,
   loads the installed `Angelscript` plugin;
2. `AngelscriptOfflineExport` publishes a complete Project bundle to both its
   project-local default destination and an explicit destination;
3. repeated exports are byte-identical;
4. the CLI extracted from the final Release ZIP consumes that explicit bundle
   under `ue-validation` / `project` and reports the same bundle identity.

The implementation did not add a public standalone plugin option, a UBT-visible
standalone macro, a second binding implementation, or a Standalone branch to
existing `Bind_*.cpp`, ClassGenerator, or mature Runtime/Editor control flow.
The CMake-only policy remains private to `AngelscriptMaintainedFork`; the final
package remains a CLI product, not a public C++ SDK.

## Red/green and failure remediation

The closeout kept failing cases as focused regressions before changing product
code:

- the configure-time target-interface assertion first rejected public
  maintained-fork policy definitions and the propagated `Standalone/Compat`
  include directory; the full policy set and Compat directory are now private;
- an allocator-lifetime regression reproduced a zero-byte allocation released
  after the stack `FCountingAllocator` was destroyed; outstanding allocation
  ownership is now tracked independently from byte totals and survives until
  the last delayed free;
- Release package publication exposed a transient Windows rename sharing
  violation; destination publication now uses a bounded retry without weakening
  atomic replacement;
- Release/ASan soak exposed two independent use-after-free paths: the Runner's
  `array<string>` argument handle and maintained-fork shutdown ordering. The
  context now owns the argument reference, and the existing standalone cleanup
  block removes non-funcdef types before their dependent teardown;
- PowerShell 5.1 argument forwarding could not reliably preserve multiple
  dash-prefixed commandlet arguments; `RunCommandlet.ps1` now accepts a JSON
  `-ExtraArgsFile`, while its original default-project behavior remains covered;
- the external script baseline initially compared LanguageCore's internal short
  module ID with the UE offline-contract module ID. The replacement plan now
  derives the exporter-compatible SHA-256 identity from
  `module-id-v1\n<logical-module-name>\n/Angelscript/Game/<logical-path>` while
  retaining the LanguageCore ID for its internal role. Same-name records with a
  different contract ID still fail closed;
- a proposed Editor-module commandlet-loading guard was tested and rejected.
  The external fixture was corrected to represent a normal content-only
  consuming project, and the temporary Editor change was fully reverted.

`ValidateBundleKind`, which always returned success, and its obsolete direct
test were removed. Unrelated StateSnapshot loop edits were restored. Only the
two required `asFunctionCaller{}` registration corrections remain; eight unused
wrappers that do not compile with `AS_REFERENCE_DEBUGGING=0` remain deleted.
