# Current Fork Limitations and Non-Representable Coverage

This record is authoritative for a planned core-language or raw-SDK case that
is constrained by the current fork. It is not a reason to silently remove
coverage. Every row retains the intended behavior, concrete evidence, current
classification, and the condition that would permit a future test or catalog
change. This includes restrictions that are exercised as enabled negative
tests, not only cases that are Disabled or deferred.

## Recording Rules

Each row must state all of the following before a product is reduced, split, or
classified as fork-specific behavior:

1. The original language or public-SDK behavior and owning planned product.
2. The exact missing API, grammar restriction, or current-fork behavior.
3. A source location, compiler diagnostic, or minimal raw-SDK reproduction.
4. Why a substitute fixture would test a different behavior.
5. Its disposition: enabled `RejectByFork`, compiled `Future238Disabled`,
   `ApiDeferred`, or an approved non-representable product reduction.
6. The future prerequisite and the source owner that must be revisited.
