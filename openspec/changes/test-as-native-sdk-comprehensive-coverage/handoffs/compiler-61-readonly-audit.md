# Compiler 61 个 Unowned 方法只读审计

## 审计范围与判定规则

- 输入清单：`audits/method-product-reconciliation.csv` 中 `File=Compiler/*` 且 `State=Unowned` 的 61 个方法。
- 逐项证据：对应 `Plugins/Angelscript/Source/AngelscriptTest/AngelScriptSDK/Compiler` 方法体，而不是方法名称。
- 产品证据：`catalogs/coverage-products.psd1` 中现有 11 个 Compiler 产品，以及 `coverage/native-domains.md` 的 Compiler 主题边界。
- `ExistingProductDisposition` 表示该方法不应成为独立 owner：它应记录为兼容/辅助/重复/跨主题 disposition，并明确指向一个更强产品。表中标注“建议”的 ProductId 表示应先建立该产品，再把辅助方法 disposition 到它。
- `NewIndependentProduct` 表示方法体包含现有产品没有声明或没有实际证明的证据层。相同建议 ProductId 的多个方法不是要求重复登记同一产品；应重构为一个数据驱动 owner，或选择其中一个方法扩展为完整 owner，其余方法再记录 disposition。
- 本报告不把“源码能编译”自动当成 Compiler 独立产品。只有编译阶段、builder 内部状态、bytecode/opcode、诊断位置/策略、发布原子性或生命周期等 Compiler 特有证据无法被更强 owner 覆盖时，才建议新产品。

## 现有产品不可被过度解释的边界

- `COMPILER-BUILDER-SHAPE-FAILURE` 只拥有四种 source shape 与三种 failure family；它不能因为“某方法也失败”就自动覆盖 mutable global、script interface、duplicate declaration、warning policy、CompileFunction 或 module dependency。
- `COMPILER-BYTECODE-SHAPE` 只拥有 arithmetic call、conditional branch、ordinary loop 和 class-layout publication四种 shape；它不能自动吸收 break/continue、recursion、short-circuit、default-argument call site 或 enum switch。
- `COMPILER-BYTECODE-MUTATION` 与 `COMPILER-BYTECODE-CONTAINER-OPERATIONS` 的 jump 证据是成功的 forward label resolution；它们不拥有 backward signed offset、multiple targets、missing target rejection 或跨 `AddCode` sequence resolution。
- `COMPILER-BUILDER-REBUILD-RECOVERY` 证明失败后模块恢复，但没有观察 `Module::Build()` 对 transient `builder` 的销毁，也没有观察 `Builder::Reset()` 的 parser/counter 状态，因此不能吞并 builder lifecycle。
- `COMPILER-BUILDER-FUNCTION-DECLARATION`、`SCALAR-DECLARATION`、`TEMPLATE-DECLARATION` 和 `PROPERTY-VERIFICATION` 是 application parsing API 产品，不是 staged module publication、class layout 或 CompileFunction 产品。
