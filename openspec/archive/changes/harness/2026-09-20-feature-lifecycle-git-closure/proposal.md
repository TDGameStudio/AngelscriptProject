# Explained lifecycle decisions and Git closure

## Why

Create and Replan currently write formal OpenSpec records without an automatic scoped Git checkpoint. Queue closure commits plugin changes while primary records can remain dirty. Archive enforces terminal integrity but does not consume the user's informed archive-and-commit decision. Active Grill continuation is already required, yet a side question in this conversation ended with an explanation-only response while earlier choices remained open. Workflow feedback is written into a separate ignored observation ledger, contrary to the selected topic-draft workflow.

## What Changes

- Prepare and validate the complete first planning candidate before Create; bind the Gate to its design, tasks, verification and exact formal-record Git selection.
- Commit accepted Create/Replan planning records without introducing routine implementation checkpoints. Replan does not checkpoint the replaced implementation.
- Explain completed, abandoned and superseded closure; execute one approved archive/Git plan with recoverable stages and complete the queue item only after the required stages succeed.
- Bind Git execution to a previewed candidate and support explicitly selected, attributable patches in shared files while protecting outside staged content and normal hooks.
- Keep Grill active across side questions and corrections, then inspect relevant counterexamples when listed choices are exhausted.
- Run an explanation-driven improvement loop for ordinary module explanations as well as Create, Replan and closure. Distinguish explanation method, specification clarity, missing capability knowledge and retrieval gaps; retain sourced findings in topic drafts and improve only the selected scope.
- Admit verified factual explanatory knowledge within existing maintenance authority, index it in its owning capability and use it in later explanations. Publish this Change's lifecycle-checkpoint knowledge after its implementation is proven.

## Impact

Owning capabilities: harness/core and harness/git. Owning implementation: Harness dispatch, creation/handoff/replan, feedback/draft records, execution/queue state, GitOperations and their isolated fixtures. Owning guidance: Harness, Brainstorming, Grill, explaining-work, lifecycle Skills, git-operations, change-queue and AGENTS.md.

No AngelScript product implementation, real backlog cleanup, automatic push/integration/workspace removal, historical archive rewrite, feedback-ledger migration, new draft mode, independent harness-update Skill or runtime conversation daemon is included.
