# Heading-node task cards with diff Files and a structured authoring contract

## Why

The seven active `tasks.md` plans are either unexecutable or unreadable. Five still use the retired inline format and expose no Ready work. The two in the current root-checkbox format duplicate a `## Task X.Y` heading above every checkbox, indent every card four spaces, write Cases as sentence chains, name no interface signatures, and repeat 40–60 lines of Harness policy as a preamble; across 24 tasks there are three numbered implementation steps. The authoring contract checks only `Files` and `Verification`, so every other section degrades into prose, and one plan defers all of its symbols into a "finish the design" task. The user asked for tasks that read as headings with an unindented body, carry one stage-level outcome with its interfaces and cases, and leave the RED/GREEN cycle to the TDD Skill.

## What Changes

**Parser and release.** `Tools/openspec` learns the heading-node format: a task is `## [ ] X.Y Title` / `## [x] X.Y Title`, its body is every block until the next level-1 or level-2 heading, unindented, the first paragraph is the brief. `**Files**` becomes a ```` ```diff ```` fence (`+` create, space modify, `-` delete, `/`-terminated directory prefixes, ` # ` comments, flat paths allowed, literal `none`); `files[]` keeps plain paths and a new `file_roles[]` carries roles. `**Verification**` is unchanged. Root-checkbox list nodes join the inline format under `unsupported-task-format` with a message naming the heading form; there is no dual parser. Version `0.10.0`, packaged through `Publish-OpenSpecPackage.ps1` after the user authorizes the submodule commit, annotated tag, and parent EXE swap.

**Authoring contract.** `openspec/references/tasks.md` is rewritten around the heading node: a fixed plan header (`## Goal`, `## Architecture`, `## Global constraints`, optional `## File map`, `## Requirement coverage` with a self-review line), mandatory card labels for behavior tasks (brief, `**Outcome**`, `**Interfaces**` with signatures when any symbol is produced or consumed, `**Cases**` as named cases with a role tag and Given / When / Then clauses, `**Files**`, `**Verification**`), optional `**Notes**`, `**Evidence**` after execution, a lighter skeleton for document tasks, no step-level TDD, a forbidden-phrase list, and a three-item self-review recorded in `attachments/data/planning-validation.md`. `Context and interfaces` and `Implementation` retire as labels. The repeated execution preamble moves to a new `harness/references/execution-conventions.md`; `task-dag.md`, `config.yaml` rules.tasks, `openspec/SKILL.md`, `openspec-continue-change` and `openspec-apply-change` (Skill-side preflight) and the Skill tests follow. The quota prohibition remains: labels are information, not size.

**Migration.** The seven active `openspec/changes/angelscript/*/tasks.md` and this Change's own `tasks.md` are converted to the heading-node syntax only: IDs, graph, `done` state and content preserved; redundant headings dropped; plan-specific preamble moved into `## Global constraints`; `## Goal` / `## Architecture` / `## Requirement coverage` added from the proposal and any existing acceptance table. Cards still lacking Interfaces or Cases are not enriched here; apply preflight blocks them until their owning Change updates them.

**Draft carryover is self-contained.** Drafts are local and git-ignored, so a Change must not link into `openspec/drafts/`. `openspec-create-change` now also copies the draft `glossary.md` and every finding cited by the design, a talk or a knowledge into `attachments/drafts/`, and citations point at the copies (`openspec/references/attachments.md`, `openspec-create-change/SKILL.md`). This Change's own attachments were repaired the same way.

**Specification.** `harness/core` MODIFIED: "Harness-recognized Task Graph", "Ready-to-execute Task authoring", "Deterministic OpenSpec package", "Exploration markers and durable carryover", "Naming confirmation before implementation".
