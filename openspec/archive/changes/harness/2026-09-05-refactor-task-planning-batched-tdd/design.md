## Decisions

Task granularity belongs to the OpenSpec task-authoring reference; execution batching belongs to Harness verification; test design and real RED/GREEN belong to TDD. Entry Skills and the workflow/template route to those owners and perform the relevant checks without copying entire policies. Task Cards retain flexible Markdown, the existing single DAG, Files and verify surface.

A feature group is a bounded independently testable outcome, not a fixed test count, time box, file count or process launch. Multiple related scenarios share its RED and GREEN phases. A batch may satisfy several Ready tasks only with the same verified source/binary identity and explicit task-to-case evidence. A smaller task remains useful even when its tests share an expensive process with another task.

Tests precede new behavior. Missing C++ interfaces may receive only the minimal compilable skeleton needed to execute a test. Build errors, crashes, undiscovered cases and aggregate counts do not prove the intended behavior failed. Existing code and explicitly authorized historical exceptions are preserved, not deleted or relabeled as observed RED. New work follows the latest user-directed grouped policy.

The active AS task 4.1 retains its original integrated Builder outcome but becomes an acceptance gate over new pending feature nodes. Existing completed nodes stay checked. New access, conversion, host lookup and call-context outcomes carry fixtures and failure oracles. No language contract or implementation is changed here; the two old AST removals and final product verification retain their existing owners.

## Evidence and reference

The local Superpowers snapshot is v6.3.0, commit b36e0829c6d0140e93cfef2ca599b1b07d4a7797, under the user's uninstalled-superpowers-backup/repository. Its writing-plans and implementer prompts distinguish an independently testable task from small execution steps and focused iteration from full-suite checks. We adopt those distinctions, not its automatic review, worktree, commit or model-selection policies.

Before/after independent agents answer the same bounded fixture request. This is a read-only consumer exercise, not a formal Review or a substitute for deterministic protocol checks. The scenario and evaluation rubric are retained with compact outputs and limits. Existing owner tests continue to prove link/structure contracts; new prose rules are not tested merely by matching their wording.

## Boundaries

No new Task schema, batch database, CLI code, Harness API, UE parameters, plugin source or user configuration. Root AGENTS stays thin. The AS coverage inventory is corrected to distinguish the 481-case verified snapshot from later unverified source. The separately indexed stale UE project-context issue is not silently repaired or closed by this change.

The owner OpenSpecSkill test keeps its full repository-content scan by default. Explicit SurfacePaths bound English, capability knowledge-index and active attachment-index inputs to validated workspace-relative files/directories, while every package/protocol/authoring/link assertion and hermetic fixture stays enabled. Selecting a child includes its whole owning index. Missing, outside-workspace, empty or reparse-traversing selections fail rather than silently reducing coverage. This is a test-input boundary, not a portable CLI or Harness API change; unrelated baseline language and knowledge-index violations remain visible in the full invocation.
