# Scope lock and delegate exclusion

## Context

The new frontend can emit Resolved class descriptors. The user wants generated types verified, including asType holding a UClass pointer. One Change versus a Resolved-only first Change was still open.

## Evidence

AskQuestion `lock-scope` = `approve-design`. Follow-up: delegates are not verified now because they may be redesigned. Draft log R2–R3. Provenance: local draft topic `angelscript/class-generation-handoff`.

## Options

Phased Resolved-only Change; one Change for UCLASS materialization; one Change for class / struct / enum / delegate; one Change for class / struct / enum with delegates excluded.

## Settled Decision

Lock scope `classgen-handoff`. One Change `angelscript/feature-classgen-type-materialization` generates, attaches, and verifies UCLASS / USTRUCT / UENUM. Reuse `asCEngineCompileRegistration` and existing ClassGenerator. Do not verify or redesign delegate / event materialization.

## Consequences

Tasks must prove SuperClass projection, stop DefinitionsBuilt overwrite, register Taken definitions, run ClassGen, and assert asType UserData for class / struct / enum only.

## Flip Condition

If Engine registration or ClassGen cannot be proven in NativeEngine Compile tests inside one Change, split materialization without bringing delegates back in.

## Visual

```
Change acceptance
├─ UCLASS / USTRUCT / UENUM   // asType.GetUserData() + reverse pointer
└─ delegate / event           // project only, no UserData assert
```
