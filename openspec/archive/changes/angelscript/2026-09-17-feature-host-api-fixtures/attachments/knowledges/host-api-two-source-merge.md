# Host-API container cases come from two piles

Disposition: candidate.

## Reusable Insight

Bindings leftover axis files (`Behavior_01`, `Queries_01`, `Observe_*`) are the positive API skeleton. `Pending/Containers` is the Fail, thicken, and pointer-type pile. A complete container FileTag needs both. Neither pile may be copied as privileged `root` stars.

## Evidence

Bindings TArray has 8 files and 40 Observe names and almost no UFUNCTION. Pending/Containers TArray has 81 files including Reject, Negative, Exception, Advance, and UClass, plus `@Kind` / `@Covers`. SoftObjectPath exists only on the Bindings side. TWeakObjectPtr / TSubclassOf / TObjectPtr exist only on the Pending side.

## Boundaries

Does not admit GAS `Pending/Optional`, TestFramework Usage suites, or treat CodeGen admission as compile/run. Does not keep TSet files that declare they are not TSet API inside a TSet pocket.

## Application

Use when rewriting any TArray/TMap/TSet/TOptional/pointer FileTag and when teaching that Bindings leftovers are not the same contract as Pending/Containers.
