# Talk: FileTag is a theme pocket

## Context

Hand-authored Language files treated FileTag, privileged `root`, and a forced parent star as one idea. The user rejected keeping `root` as a reserved representative.

## Evidence

Casting records a star: one `root` and every other version `@parent root`. There is no real Family. Mashup roots place several independent claims in one body.

## Options

A. One FileTag is one concern; restore the old representative-root contract.
B. FileTag is a theme pocket; several VersionTags are cases; Parent is optional.
C. Two container kinds (Scene + Family).

## Settled Decision

B, from the Q3 free answer (exploration R3) and R20 approval: drop privileged `root`; FileTag is the theme range; one VersionTag is one case; negatives leave the file.

## Consequences and Flip Condition

Parser and Builder must allow several parentless versions. Flip if the user restores a forced star or a reserved representative name.

## Visual

```
FileTag = theme pocket
├─ case A    // no Parent
├─ case B
└─ case C
   └─ child  // Parent only for a real edit
```
