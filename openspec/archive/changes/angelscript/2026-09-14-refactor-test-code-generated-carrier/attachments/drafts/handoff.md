# Generated C++ Test Source Carrier Handoff

Source identity: faithful English export of the approved `angelscript/test-framework-completion/designs/generated-cpp-carrier` handoff. Approved by the user on 2026-09-14 after the directory, mapping, CLI, verification, and modularity rounds; the user explicitly authorized creation and immediate implementation.

## Problem

The current `.as` carrier is generated by `AngelscriptTest.Build.cs` as Windows RCDATA and unpacked by a runtime resource provider. This couples fixture-set changes to UBT rule execution, numeric resource IDs, RC linking, and a runtime index. The replacement must be reviewable and deterministic while preserving the implemented parser, database, activation, and handwritten cross-module registration path.

## Success criteria

- `.as` remains the single authored truth and `CodeGenTool/**` is excluded from discovery.
- `codegen.py generate` deterministically synchronizes one mirrored `.generated.cpp` per `.as`.
- `codegen.py check` is read-only and fails for missing, changed, or stale projections.
- The Python implementation remains modular and `generate` and `check` share `build_sync_plan()`.
- Generated C++ preserves raw bytes, registers through `FAngelscriptTestCodeRegistration`, and parses at activation through `FAngelscriptTestSourceParser::Parse`.
- Handwritten `FAngelscriptTestCodeRegistration` and `AS_TEST_SOURCE` remain supported.
- The Windows RCDATA generator, index, RC input, and runtime resource provider are removed; ordinary UBT does not invoke Python.
- Output is reproducible and safe under no-op, stale cleanup, and Unity Build behavior.
- Python tests, drift check, focused C++ Automation, and a Harness Unreal build prove the migration.

## Scope and exclusions

In scope: modular Python code generation and tests, checked-in per-source C++, existing registration/parser integration, RCDATA deletion, affected C++ coverage, durable specification, and author guidance.

Excluded: diagnostics assertions, reload execution, LSP/DAP consumers, `TestSource-old` recipes/history/catalog, AngelScript compilation in Python, version-diff interpretation, automatic Git hooks, and Python execution from ordinary UBT.

The planning-only `angelscript/refactor-testing-unified-framework` Change is neither deleted nor archived here. This Change owns only the selected generated carrier and explicitly excludes the older generator's recipe/history/catalog scope.

## Constraints

- Preserve unrelated dirty work and remain in the selected workspace.
- New C++ tests stay under `AngelscriptTest/NewVersion/` and use `Angelscript.UnitTest.<Area>.<Scenario>` identities.
- Use `WITH_ANGELSCRIPT_TESTS`; do not restore the legacy test gate.
- C++ remains the sole authority for metadata, annotations, version trees, and origin maps.
- Generated symbols use stable normalized-FileTag digest suffixes and are Unity-safe.
- The writer completes discovery, validation, and rendering before mutation, atomically replaces changed outputs, then performs bounded signed stale cleanup.

## Decision and rationale

Use one checked-in generated C++ projection per authored fixture. This separates explicit author synchronization from ordinary compilation and reuses the existing runtime seams without duplicating the container grammar in Python. A common plan makes `check` and `generate` agree; a dedicated generated root creates a provable stale-cleanup boundary.

Rejected alternatives are one aggregate translation unit, premature fixed hash shards, and permanent RCDATA coexistence. Reconsider shards only after measured build evidence demonstrates unacceptable per-file translation-unit cost. Do not restore RCDATA unless a later cross-platform or runtime constraint specifically requires a non-C++ carrier while retaining the same authored-truth and drift-check rules.

## Architecture

```text
authored .as
└─ thin CLI -> shared sync plan -> discovery + pure renderer
   └─ mirrored checked-in .generated.cpp
      └─ existing static registration
         └─ one-shot activation -> existing parser -> database/query center

handwritten provider
└─ existing registration + AS_TEST_SOURCE -> same activation/database
```

## Failure boundaries

- Reject normalized or case-folded path collisions before writes.
- Exclude non-`.as` files and all of `CodeGenTool/**`.
- Keep empty and arbitrary-byte sources length-explicit.
- Never mutate in `check`.
- Never rewrite equal output in `generate`.
- Delete only signed `.generated.cpp` files under the exact generated root; preserve and report other extras.
- Never use Python `hash()`, absolute paths, timestamps, or locale-dependent output.
- Preserve authored `.as` source identity and parser line/byte locations.
