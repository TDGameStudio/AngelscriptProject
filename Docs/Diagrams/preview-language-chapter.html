AngelScript 语言基础 · 目录

本章要解决什么

建立变量、函数、类、枚举、控制流、句柄与引用的语言心智模型，并标出普通 AngelScript 与 Unreal 方言的分界。本章聚焦“与引擎无关的语言核心”：语法、语义，以及当前 fork 在语言层做的扩展（如 foreach、fallthrough、struct、access 等关键字）。掌握核心之后，再进入 学习反射、Blueprint 与绑定层的专有行为。

本章所有示例形状都对照仓库 Script/Examples/Core/ 与 Script/Game/ 下的可运行示例；需要更深的实现细节时，用页内链接进入对应的语法参考与内部文档。

如果你还没跑通第一个脚本，先完成 ，再回到本章逐层深入。语言核心与 Unreal 反射是两件事：本章只讲语言本身。

基本类型与变量

学完能做什么

你将能在 .as 文件中声明局部变量、成员变量和常量，读懂常见基础类型，并判断一个值是普通 AngelScript 值、Unreal 结构体值，还是由 Unreal GC 管理的对象引用。

前置条件：已经能打开项目的 Script/ 目录；如果还没有运行过脚本，请先阅读 。

最小示例

下面的函数只使用脚本局部变量，可以放进任意 .as 文件。保存后，它会随脚本模块一起编译。

void DescribeValues()
{
    bool bEnabled = true;
    int Count = 3;
    float Distance = 125.0;
    FString Label = "Checkpoint";
    FName StableName = n"Checkpoint";

    auto DoubledCount = Count * 2;
    const FVector Offset = FVector(0.0, Distance, 0.0);

    Print(f"{Label}: enabled={bEnabled}, count={DoubledCount}, offset={Offset}");
}

这里有三类需要分开理解的值：

  • bool、int、float 等是普通标量。整数还可以按需要使用 int8、uint8、int64 等明确宽度的类型。
  • FString、FName、FVector 等来自 Unreal 绑定。它们不是 AngelScript 标准库凭空提供的类型；可用成员和运算取决于当前插件绑定。
  • AActor、UObject、UActorComponent 等变量表示 Unreal 对象引用。脚本中不写 C++ 的 * 和 ->；用 . 访问，空引用用 nullptr 判断。

auto 让编译器从右侧表达式推断静态类型，但不会把语言变成动态类型。推断完成后，变量仍只接受兼容值。const 表示这个名字在当前作用域中不能被重新赋值；它不会自动让其引用到的整个 Unreal 对象成为不可变对象。

标量类型一览

普通标量是与引擎无关的语言核心类型。整数类型带明确宽度和符号，按需要选择即可：

类型说明
bool布尔值 true / false
int8 int16 int / int32 int64有符号整数（int 等价于 int32）
uint8 uint16 uint / uint32 uint64无符号整数（uint 等价于 uint32）
float32 位浮点，字面量可写 1.0f
float64 / double64 位浮点

没有特殊理由时用 int（32 位有符号）即可。需要与 Unreal 的字节数据、位掩码或紧凑存储对齐时，才用 uint8、int64 等明确宽度的类型。混用不同宽度/符号的整数运算时留意隐式转换与溢出。

字符串与名字：FString / FName / FText

这三者都来自 Unreal 绑定，用途不同，不要混用：

  • **FString**：可变的通用字符串，适合拼接、临时构造、调试文本。
  • **FName**：不区分大小写、经过内部化的稳定名字，适合做查表键、标签、组件名等。字面量写作 n"Name"。
  • **FText**：面向**最终用户显示**的、可本地化的文本。凡是要展示给玩家的界面文字应使用 FText。
FString Label = "Checkpoint";       // 通用文本
FName StableName = n"Checkpoint";   // 稳定名字，用于查表/标签

字面量形式

  • **数值字面量**：3、255、1.0、1.0f；十六进制 0x14、二进制 0b1010 等。
  • **普通字符串**："..."，得到 FString。
  • **名字字面量**：n"..."，直接得到 FName（见上）。
  • **格式化字符串**：f"..."，花括号中的表达式会被求值后插入，还支持格式说明符与对齐：
Print(f"Called from actor {GetName()} at location {Location}");
Print(f"Three decimals: {Value :.3f}");   // 保留三位小数
Print(f"Hex: {20 :#x}");                    // 0x14
Print(f"{DeltaSeconds =}");                 // 打印 "DeltaSeconds = 0.01"

上面的格式说明符形状对照仓库 Script/Examples/Core/Example_FormatString.as；完整规则见 。

auto 与 const 的边界

  • auto 只是**类型推断**：编译器根据右侧表达式确定一个静态类型，之后变量仍然是强类型，不接受不兼容的值。它不会让语言变成动态类型。
  • const 约束的是**当前这个名字不能被重新赋值**；它不会把所指向的整个 Unreal 对象变成不可变对象。
auto DoubledCount = Count * 2;              // 推断为 int
const FVector Offset = FVector(0, 125, 0);  // Offset 不能再被重新赋值

成员变量与 Unreal 可见性

类体里的普通成员默认只供脚本使用。只有在需要编辑器、Blueprint、复制或其他反射能力时才添加 UPROPERTY()：

class AValueExample : AActor
{
    int InternalCounter = 0;

    UPROPERTY(Category = "Example")
    float Speed = 300.0;

    UFUNCTION(BlueprintOverride)
    void BeginPlay()
    {
        InternalCounter += 1;
        Print(f"{GetName()}: speed={Speed}, starts={InternalCounter}");
    }
}

这条边界很重要：普通 AngelScript 变量语义属于本页；UPROPERTY 的默认可编辑性、Blueprint 暴露和复制规则属于 Unreal 方言。继续阅读 。

常见错误与验证

  • 不要把 FString 和 FName 当成同一种用途。用户文本通常用 FString；稳定名字和查表键常用 FName。
  • 不要把 auto 当成“任意类型”。编译错误应在保存脚本后出现在当前编译诊断中。
  • 对对象引用先判断 nullptr；需要跨帧保存对象时，还要理解对象生命周期和 GC。
  • 本页适用于当前仓库的 UE 5.7 插件 fork，示例形状已对照 Script/Game/Example_Actor.as 与 Core 示例；具体绑定成员仍以当前源码和代码补全为准。

验证方法：保存包含 DescribeValues() 的文件，确认没有编译错误；从一个 BeginPlay() 调用它，运行 PIE 并在输出日志中找到打印结果。

函数与控制流

学完能做什么

你将能声明全局函数和类方法，使用参数、返回值、if、for、while、switch、break 与 continue，并知道普通脚本函数和 Unreal UFUNCTION() 的边界。

前置条件：熟悉 。

一个可直接运行的函数

int SumPositiveValues(const TArray<int>& Values)
{
    int Total = 0;
    for (int Value : Values)
    {
        if (Value <= 0)
            continue;

        Total += Value;
    }
    return Total;
}

void PrintDifficulty(int Level)
{
    switch (Level)
    {
    case 0:
        Print("Easy");
        break;
    case 1:
        Print("Normal");
        break;
    default:
        Print("Custom");
        break;
    }
}

函数签名在调用点之前必须可见于编译模块。参数和返回值具有静态类型；return 的值必须与声明兼容。只有一条语句的条件分支可以省略花括号，但教程和团队代码更推荐保留花括号，减少后续修改造成的歧义。

范围 for 适合遍历容器中的值；需要索引或原地修改时使用计数循环。不要在范围循环中随意改变容器长度，除非具体容器页面明确说明该操作安全。

控制流：条件与循环

条件用 if / else if / else。循环有四种常用形式：

// 1) 计数 for：需要索引、或要原地按下标修改时用它
for (int Index = 0, Count = Values.Num(); Index < Count; ++Index)
    Sum += Values[Index];

// 2) 范围 for：只需要逐个取值时最简洁
for (int Value : Values)
    Sum += Value;

// 3) while：先判断后执行
while (Remaining > 0)
    Remaining -= Step;

// 4) do-while：至少执行一次再判断
do
{
    Attempts += 1;
}
while (Attempts < MaxAttempts);

break 跳出当前循环，continue 跳到下一次迭代。计数 for 的两种形式都对照仓库 Script/Examples/Core/Example_Array.as。

switch 与 fallthrough

switch 的每个 case 分支默认**不会**自动贯穿到下一个 case——你需要显式 break（或 return）。当前 fork 提供了一个专门的 fallthrough 关键字，用来**明确表达**“有意贯穿到下一个 case”，从而避免 C++ 中“忘了写 break”造成的隐蔽 bug：

void PrintDifficulty(int Level)
{
    switch (Level)
    {
    case 0:
        Print("Easy");
        break;
    case 1:
    case 2:
        Print("Normal");   // 1 和 2 共用同一分支
        break;
    default:
        Print("Custom");
        break;
    }
}

case 标签使用限定的枚举名（如 EExampleEnum::A）时同样适用，见 与 Script/Examples/Core/Example_Enum.as。

方法、全局函数与 Blueprint

普通全局函数和类方法只参与脚本调用。需要让 Unreal 反射和 Blueprint 看见时，添加 UFUNCTION()：

UFUNCTION(Category = "Examples")
int ClampScore(int Score, int Minimum, int Maximum)
{
    return Math::Clamp(Score, Minimum, Maximum);
}

class AScoreActor : AActor
{
    UFUNCTION(BlueprintEvent)
    void ScoreChanged(int NewScore)
    {
        Print(f"Score changed: {NewScore}");
    }

    UFUNCTION(BlueprintOverride)
    void BeginPlay()
    {
        ScoreChanged(ClampScore(125, 0, 100));
    }
}

当前 fork 中，全局 UFUNCTION() 可成为 Blueprint 节点；类内 BlueprintEvent 允许 Blueprint 子类提供覆盖；覆盖 Unreal 父类事件时使用 BlueprintOverride。完整 specifier 和 RPC 规则请进入 。

需要生成 Blueprint 输出 pin 时可使用 &out。普通结构体可修改引用使用 &；对象引用与结构体引用不是同一概念：

void SplitLocation(const FVector& Location, float&out X, float&out Y)
{
    X = Location.X;
    Y = Location.Y;
}

参数传递方式

参数默认按值传递。对结构体等值类型，用引用修饰可以避免拷贝或返回多个结果：

写法含义典型用途
const T&只读引用，不拷贝传入较大的结构体/数组只读
T&out仅作为输出写入返回多个结果；在 Blueprint 中生成输出 pin
T& / T&inout可读可写引用就地修改调用方传入的值
// 只读引用传入 + 两个输出参数
void SplitLocation(const FVector& Location, float&out X, float&out Y)
{
    X = Location.X;
    Y = Location.Y;
}

// &out 在 Blueprint 中会显示为节点右侧的输出 pin
UFUNCTION(Category = "Examples")
void ExampleFunctionWithOutputParameter(FVector&out OutPosition)
{
    OutPosition = FVector(1.0, 1.0, 0.0);
}

上面 &out 的形状对照 Script/Examples/Core/Example_Functions.as。注意**对象引用**（如 AActor）本身就是引用语义，与这里的结构体 & 不是一回事；两者的区别见 。

命名参数与常用库函数

调用时可以用 名字 = 值 的形式按参数名传参，提升可读性、也方便跳过带默认值的参数：

Print("You selected A!", Duration = 30);
float Clamped = Math::Clamp(X = 2.0, Min = 0.0, Max = 0.5);

常用数学函数位于 Math:: 命名空间，例如 Math::Abs、Math::Min、Math::Max、Math::Clamp、Math::Sin、Math::RandRange 等（见 Script/Examples/Core/Example_Math.as）。

失败边界与验证

  • switch 的 case 默认不贯穿，需要显式 break；确需贯穿时使用 fallthrough 关键字明确表达。
  • 空对象引用不是控制流异常；在访问前显式判断 nullptr。
  • 热重载时，改变普通脚本函数体通常比改变反射签名影响更小；结构变化要按热重载文档验证。
  • 本页示例已对照 Script/Examples/Core/Example_Functions.as、Example_Array.as 和 Example_Enum.as；适用于当前 UE 5.7 fork。

验证方法：将示例放入 Script/ 下的 .as 文件，从一个 Actor 的 BeginPlay() 调用它们，保存后确认编译成功并检查输出日志。若修改 UFUNCTION 签名，还要打开 Blueprint 子类确认节点和覆盖仍有效。

★ 函数参数与返回值

学完能做什么

你将能精确控制函数如何接收和返回数据：按值还是按引用、只读还是可写、如何输出多个结果、如何用默认值和命名参数写出清晰的调用。

前置条件：先读 建立最小函数语法。

参数传递方式一览

参数默认**按值**传递（得到一份拷贝）。对结构体等值类型，用引用修饰可以避免拷贝或返回结果：

写法含义典型用途
T（默认）按值传入拷贝小标量、不想影响调用方
const T&只读引用，不拷贝传入较大结构体 / 数组只读
T&out仅作为输出写入返回多个结果；蓝图右侧输出 pin
T& / T&inout可读可写引用就地修改调用方传入的值

AActor、UObject 这类**对象引用本身就是引用语义**，与 FVector& 这种“值类型上的引用参数”不是一回事。区别见 。

只读引用与输出参数

// const T& 只读传入 + 两个 &out 输出
void SplitLocation(const FVector& Location, float&out X, float&out Y)
{
    X = Location.X;
    Y = Location.Y;
}

// &out 在蓝图中显示为节点右侧的输出 pin
UFUNCTION(Category = "Examples")
void ExampleFunctionWithOutputParameter(FVector&out OutPosition)
{
    OutPosition = FVector(1.0, 1.0, 0.0);
}

用 &out 是脚本里“返回多个值”的常用方式：一个 return 值 + 若干 &out 参数。以上形状对照 Script/Examples/Core/Example_Functions.as。

默认参数值

参数可以带默认值；带默认值的参数必须放在参数列表**末尾**。调用时省略即用默认值：

void SpawnPickups(int Count, float Spacing = 100.0, bool bAlignToGround = true)
{
    // Spacing / bAlignToGround 可省略
}

SpawnPickups(3);                 // Spacing=100.0, bAlignToGround=true
SpawnPickups(3, 50.0);           // bAlignToGround=true
SpawnPickups(3, 50.0, false);    // 全部显式

命名参数

调用时可以用 名字 = 值 按参数名传参，提升可读性、也方便只覆盖后面的某个默认参数：

Print("You selected A!", Duration = 30);
float Clamped = Math::Clamp(X = 2.0, Min = 0.0, Max = 0.5);

以上对照 Script/Examples/Core/Example_Enum.as 与 Example_Math.as。命名参数与默认值配合，能避免为了传最后一个参数而把中间的默认值也写全。

返回值

返回值有静态类型，return 的值必须与声明兼容。需要“返回多个结果”时，组合一个返回值与若干 &out，或返回一个 struct：

struct FSplitResult { float X; float Y; }

FSplitResult SplitXY(const FVector& V)
{
    FSplitResult R;
    R.X = V.X;
    R.Y = V.Y;
    return R;
}

常见错误与验证

  • 默认参数只能在**尾部**；把带默认值的参数放在必填参数前会编译错误。
  • &out 参数在函数内应被赋值；调用方拿到的是写回的值。
  • 不要用值传递一个大 struct 却期望修改会影响调用方——那需要 T&。
  • 验证：把示例放入 Script/ 下的 .as，从 BeginPlay() 调用，保存后确认编译成功；若改了 UFUNCTION 的 &out，打开蓝图子类确认输出 pin 正确。

★ UFUNCTION 与蓝图暴露

学完能做什么

你将能用 UFUNCTION() 及其规格（specifier）把脚本函数按需暴露给 Unreal 反射与蓝图：作为可调用节点、纯节点、可覆盖事件，或覆盖 C++ 生命周期事件，并知道哪些函数应保持脚本私有。

前置条件：熟悉 与 。

最基本：暴露与不暴露

不加 UFUNCTION() 的函数只能被脚本调用；Unreal 不感知它们，因此它们的热重载也更快。加上 UFUNCTION() 才进入反射：**全局** UFUNCTION() 直接成为蓝图节点，**类内** UFUNCTION() 成为该类实例上的可调用方法。

// 全局 UFUNCTION → 直接是蓝图节点
// 函数正上方的注释会成为该节点的 tooltip；Category 决定它在蓝图菜单中的分组
UFUNCTION(Category = "Example Functions")
void ExecuteExampleFunction(AActor InputActor)
{
    Print("Called for actor: " + InputActor.GetName());
}

常用规格一览

规格作用
（无）蓝图可见的普通（非纯）节点
BlueprintPure纯节点（无执行引脚），**必须有返回值**
BlueprintCallable蓝图可调用（与 BlueprintEvent 组合时表示既可覆盖又可调用）
BlueprintEvent蓝图可**覆盖**；默认不可调用，除非同时加 BlueprintCallable
BlueprintOverride覆盖 C++ 父类事件（BeginPlay、Tick、ConstructionScript 等）
NotBlueprintCallable仅脚本可调；用于委托/定时器回调这类需要 UFUNCTION 但不想被手动调用的函数
CallInEditor在 Details 面板加一个按钮，可在编辑器里执行（不进入最终发行版）
Category = "..."决定节点在蓝图菜单里的分组标题

规格可以用逗号链式组合：

UFUNCTION(BlueprintPure, BlueprintEvent, Category = "Hi Mum")
int ReallySpecifiedFunction()
{
    return 1337;
}

以上形状对照 Script/Examples/Core/Example_FunctionSpecifiers.as。

覆盖 C++ 事件 vs 声明可覆盖事件

  • 覆盖引擎已有事件（BeginPlay、Tick 等）用 BlueprintOverride：
UFUNCTION(BlueprintOverride)
void Tick(float DeltaTime) { /* 每帧逻辑 */ }
  • 声明一个**让蓝图子类覆盖**的新事件用 BlueprintEvent：脚本里的实现作为默认，蓝图覆盖后调用蓝图版本。脚本里的 BlueprintImplementableEvent / BlueprintNativeEvent 在这里没有区别。
UFUNCTION(BlueprintEvent)
void NewOverridableMethod() { Log("Blueprint did not override this event."); }

以上对照 Script/Examples/Core/Example_Functions.as 与 Script/Game/Example_Actor.as。

UFUNCTION 还支持网络 RPC 等更复杂的规格与规则，属于反射/网络层，超出本页范围。完整 specifier 列表与 RPC 规则见 。

常见错误与验证

  • BlueprintPure 必须有返回值（纯节点没有执行引脚）。
  • BlueprintEvent 默认只可覆盖、不可调用；要在蓝图里调用它，需同时加 BlueprintCallable。
  • 委托/定时器回调函数需要是 UFUNCTION() 才能被绑定；不想被手动调用时加 NotBlueprintCallable。
  • 改动 UFUNCTION 签名属于结构性变化，热重载后要检查蓝图子类节点与覆盖是否仍有效。
  • 验证：保存后在蓝图中确认节点出现在正确 Category、tooltip 来自注释、纯/非纯与覆盖行为符合预期。

★ 委托、事件与 Mixin

学完能做什么

你将能用 delegate 声明单播回调、用 event 声明多播事件派发（可被蓝图绑定），并用 mixin 给已有类型“外挂”方法。

前置条件：熟悉 与 （绑定的目标函数必须是 UFUNCTION()）。

delegate：单播回调

用 delegate 关键字声明一个函数签名类型，等价于 C++ 的 DECLARE_DYNAMIC_DELEGATE()。它可以作为函数参数传递：

delegate void FExampleDelegate(UObject Object, float Value);

UFUNCTION()
void ExecuteExampleDelegate(FExampleDelegate InDelegate)
{
    if (!InDelegate.IsBound())        // 执行前可先判断是否已绑定
    {
        Log("Input delegate was not bound.");
        return;
    }
    InDelegate.Execute(nullptr, 5.4);        // 未绑定时会报错
    InDelegate.ExecuteIfBound(nullptr, 1.0); // 未绑定时什么也不做
}

绑定用 .BindUFunction(this, n"FunctionName")——注意 n"" 是 FName 字面量，编译期解析，比动态构造更快：

FExampleDelegate Local;
Local.BindUFunction(this, n"ExampleFunction");   // 目标必须是 UFUNCTION()

event：多播事件

用 event 关键字声明多播事件，等价于 C++ 的 DECLARE_DYNAMIC_MULTICAST_DELEGATE()。事件**不能作为 UFUNCTION 参数**，但可以作为脚本类的 UPROPERTY()，从而让蓝图 / 关卡脚本绑定：

event void FExampleEvent(UObject Object, float Value);

class AExampleEventActor : AActor
{
    // 声明为 UPROPERTY() 后，蓝图可对它绑定
    UPROPERTY(Category = "Example Events")
    FExampleEvent ExampleEvent;

    UFUNCTION(BlueprintOverride)
    void BeginPlay()
    {
        // Broadcast 调用所有绑定者；即使无人绑定也不报错，无需先 IsBound
        ExampleEvent.Broadcast(nullptr, 100.0);
    }

    UFUNCTION()
    void ExampleFunction(UObject InObject, float InValue)
    {
        Log("ExampleFunction: " + InValue);
    }

    UFUNCTION()
    void BindExampleDelegates()
    {
        // 多播用 .AddUFunction 追加绑定；目标同样必须是 UFUNCTION()
        ExampleEvent.AddUFunction(this, n"ExampleFunction");
        ExampleEvent.Broadcast(nullptr, 12.5);   // 脚本绑定者 + 蓝图绑定节点都会被调用
    }
}

以上对照 Script/Examples/Core/Example_Delegates.as。

mixin：给现有类型加方法

用 mixin 关键字声明的全局函数只能**当作方法调用**，其第一个参数就是被调用的对象类型。使用前该模块仍需被 import。它与 C++ 函数库的 ScriptMixin 元标记行为类似：

mixin void ExampleMixinActorMethod(AActor Self, FVector Location)
{
    Print("Mixin invoked on: " + Self.GetClass().GetName());
}

void Example_MixinMethod()
{
    AActor ActorReference;
    ActorReference.ExampleMixinActorMethod(FVector(0.0, 0.0, 100.0));  // 当作方法调用
}

以上对照 Script/Examples/Core/Example_MixinMethods.as。

常见错误与验证

  • 绑定的目标函数必须标记 UFUNCTION()，否则无法绑定。
  • Execute 在未绑定时报错，不确定是否绑定时用 ExecuteIfBound 或先 IsBound；Broadcast 永不报错。
  • 事件不能作为 UFUNCTION 参数传递；需要作为 UPROPERTY() 暴露给蓝图。
  • mixin 所在模块必须被 import 才能使用其方法。
  • 验证：保存后在蓝图里对 UPROPERTY 事件绑定并触发，确认脚本与蓝图绑定者都被调用。

类、继承与接口

学完能做什么

你将能用 class 和 struct 组织脚本类型，用继承和 Super:: 复用父类逻辑，用基类可覆盖方法实现“接口式”多态派发，并理解脚本 struct 与访问修饰符的边界。

前置条件：熟悉 与 。

先选对类型：class 还是 struct

  • **class** 表示带身份的对象类型。继承 AActor、UObject 或组件类型后，它会进入 Unreal 的生成类型和对象生命周期，可作为 Blueprint 父类。
  • **struct** 更适合按值传递的数据聚合（位置、配置、结果等）。
struct FExampleStruct
{
    // struct 里带 UPROPERTY() 的字段会反射到生成类型上
    UPROPERTY()
    float ExampleNumber = 4.0;

    UPROPERTY()
    FString ExampleString = "Example String";

    // 没有 UPROPERTY() 的字段仍在 struct 中，但 Blueprint 看不到
    float ExampleHiddenNumber = 3.0;
}

1）**任何字段改动都需要完整 reload**——无论该字段是否为 UPROPERTY()，这是脚本 struct 的技术限制。2）脚本 struct 的 Blueprint Make/Break 节点**默认关闭**。以上对照仓库 Script/Examples/Core/Example_Struct.as。

继承与 Super::

派生类用 : 指定基类；需要调用父类的脚本实现时用 Super::Method()。下面高亮行是子类覆盖父类可覆盖方法、并用 Super:: 回调父实现的关键位置：

Undefined widget 'angelscript-code'

“接口式”多态：BlueprintEvent + BlueprintOverride

需要“调用方只依赖行为契约、由不同派生类各自实现”时，当前插件版本中**最稳定**的做法是：在基类用 UFUNCTION(BlueprintEvent) 声明可覆盖方法，派生类用 UFUNCTION(BlueprintOverride) 覆盖，调用方只持有基类引用：

class AExampleDamageableBase : AActor
{
    UFUNCTION(BlueprintEvent)
    float ApplyDamage(float Amount) { /* 默认实现 */ return 0.0; }

    UFUNCTION(BlueprintEvent)
    bool IsAlive() { return true; }
}

class AExampleDamageableActor : AExampleDamageableBase
{
    UFUNCTION(BlueprintOverride)
    float ApplyDamage(float Amount) { /* 自定义实现 */ return 0.0; }
}

// 任何 AExampleDamageableBase（含子类）都能传进来，运行时派发到实际实现
UFUNCTION(Category = "Example Dispatch")
void ApplyDamageToTarget(AExampleDamageableBase Target, float Damage)
{
    if (Target == nullptr)
        return;
    Target.ApplyDamage(Damage);
    if (!Target.IsAlive())
        Print(f"{Target.GetName()} is dead!");
}

上面的形状对照仓库 Script/Examples/Extended/Example_InterfaceDispatch.as。

AngelScript 语言本身有 interface 关键字（脚本级接口）。但要在 Unreal / Blueprint 之间稳定地做跨类派发，本仓库示例采用的是上面的基类 BlueprintEvent 模式，而不是把 C++ UINTERFACE 的习惯原样搬过来——真正的 Unreal 接口、脚本接口与绑定接口存在额外的反射与生成约束。在未对具体用例核对源码/测试前，优先使用已验证的 BlueprintEvent 模式。

访问修饰符（进阶）

除了 public / protected / private，当前 fork 还支持用 access 声明更细粒度的访问契约：可以在 private/protected 基础上，额外授权特定的类（甚至用 * 授权全部），并加 readonly、editdefaults、inherited 等修饰：

class UAccessSpecifierExample
{
    // 在 private 基础上，额外允许这两个类访问
    access InternalWithCapability = private, UAccessSpecifierComponent, APlayerController;

    access:InternalWithCapability
    float AccessibleFloatValue = 1.0;
}

以上对照 Script/Examples/Core/Example_AccessSpecifiers.as；完整修饰符语义见 。

规则与边界

  • 派生类使用 : 指定基类；脚本方法的覆盖与 Unreal BlueprintOverride 不是完全相同的层次——覆盖 C++/Blueprint 事件时需要 BlueprintOverride。
  • 需要调用脚本父实现时使用 Super::Method()。
  • struct 可以有普通脚本方法；要进入 Blueprint 的字段需要 UPROPERTY() 反射元数据。
  • 类型的**反射生成、热重载和 Blueprint 子类迁移**属于当前 fork 的 ClassGenerator 行为，不是普通 AngelScript 语法本身。

学完能做什么

前置条件：熟悉 与 。

选择容器

容器语义典型用途
TArray<T>保留插入顺序、可按下标索引列表、队列、逐个遍历
TSet<T>不重复集合去重、成员判断
TMap<K,V>按键查找值查表、计数、关联

它们来自 Unreal 绑定，不是普通 AngelScript 内建容器；可用方法与成本以当前绑定为准。

TArray：有序列表

TArray<int> Values;
Values.Add(2);
Values.Add(8);
Values.Add(255);

// 范围 for 逐个取值
for (int Value : Values)
    Log("Array contained " + Value);

// 或按下标遍历
for (int Index = 0, Count = Values.Num(); Index < Count; ++Index)
    Log("Array[" + Index + "] = " + Values[Index]);

int Found = Values.FindIndex(255);   // 线性查找，返回下标
if (Values.Contains(8)) { /* 线性查找是否存在 */ }

Values.RemoveAt(Found);   // 按下标移除
Values.Remove(8);         // 按值移除（线性查找）
Values.Empty();           // 清空

常用方法：Add、Num、Contains、FindIndex、RemoveAt、Remove、Empty、[] 索引。对照 Script/Examples/Core/Example_Array.as。

TMap：键值查找

TMap 因为脚本里没有裸指针，取值方式与 C++ 略有不同：

TMap<FString, int> Counts;
Counts.Add("Four", 4);
Counts.Add("ChangeThis", 5);

// Find(Key, Out)：返回是否找到，找到则把值拷进 Out
int FoundValue = -1;
if (Counts.Find("Four", FoundValue))
    check(FoundValue == 4);

// [] 返回引用，可读可写；键不存在会抛异常，先用 Contains 判断
if (Counts.Contains("ChangeThis"))
{
    int& Value = Counts["ChangeThis"];   // 取引用
    Counts["ChangeThis"] = 12;           // 通过 [] 直接写
}

// FindOrAdd：不存在则以默认值插入，并返回引用
Counts.FindOrAdd("Newb") = 9;

// 范围 for 得到迭代器元素，用 GetKey/GetValue/SetValue
for (auto Element : Counts)
    Log(Element.GetKey() + " => " + Element.GetValue());

要点：Find(Key, Out) 用输出参数返回值；[] 返回**引用**（键不存在会抛异常，先 Contains）；FindOrAdd 返回可写引用；迭代元素用 GetKey() / GetValue() / SetValue()。对照 Script/Examples/Core/Example_Map.as。

TSet：去重集合

TSet<FName> Unique;
Unique.Add(n"Key");
Unique.Add(n"Key");        // 重复添加不会增加元素
if (Unique.Contains(n"Key")) { /* ... */ }

句柄、引用与类型转换

学完能做什么

你将能分清脚本里三种“引用”概念——Unreal 对象引用、结构体引用参数、输出参数——正确使用 nullptr 判断与 Cast<T>() 类型转换，并知道对象生命周期与 GC 会影响一个引用是否仍然可用。

前置条件：熟悉 与 。

三个不要混淆的概念

脚本里没有照搬 C++ 裸指针的 * / -> 写法。要区分三件事：

  • **Unreal 对象引用**（如 AActor、UObject）：由对象系统和 GC 管理的引用。用 . 访问成员，用 == nullptr / != nullptr 判断空。
  • **结构体引用参数 T&**：函数参数上的可读写引用，用来就地修改调用方传入的结构体值。
  • **输出参数 T&out**：只作为输出写入的参数（在 Blueprint 中显示为输出 pin）。
void InspectActor(AActor Actor)          // 对象引用
{
    if (Actor == nullptr)
        return;

    ACharacter Character = Cast<ACharacter>(Actor);
    if (Character != nullptr)
        Print(f"Character: {Character.GetName()}");
}

void MoveAlongX(FVector& Location, float Amount)   // 结构体引用：就地修改
{
    Location.X += Amount;
}

void MakeLocation(FVector&out Result)              // 输出参数：只写
{
    Result = FVector(100.0, 0.0, 0.0);
}

对象引用（AActor 等）本身就是引用语义，传递的是“对同一个对象的引用”；而 FVector& 这类是**值类型上的引用参数**，用于避免拷贝或就地修改。两者写法相近，含义不同，别混为一谈。参数传递方式的完整表格见 。
